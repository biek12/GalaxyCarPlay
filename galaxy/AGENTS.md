# galaxy 自有代码规范

生效：2026-11-11。适用于本目录全部现有和新增自有模块；根 AGENTS 的车型、签名、数据及设备授权边界继续适用。第三方代码保留原有声明，不机械改写上游核心。

## Android 工程结构（本次用户纠正，优先于旧任务书）

- 完整标准见 [Android工程规范](../docs/refactor/Android工程规范.md)，批次和文件职责见 [重构总图](../docs/refactor/重构总图-20261111.md)。两份文档均是编码与审计依据，不能只阅读本摘要。
- 用户随后补充：先复用 `common`/`galaxy/common` 已有UI组件，`ui`只补必要跨应用封装、资源适配及缺口；已迁出的组件继续使用同一实现，不重写一套。复用来源、现有委托和本批缺口必须逐项列明；不能让ui反向依赖含CarPlay业务的common造成循环。详见 [组件复用映射](../docs/refactor/Common组件复用映射-20261111.md)。
- 普通页面、列表项、设置行、弹窗及静态组件骨架使用 `res/layout` XML，启用 View Binding；Kotlin 只绑定状态、事件和确需动态的内容。禁止把原有 `addView` 工厂换个文件继续拼整页。Canvas/Surface 渲染、确需自适应测量的控件单独列例外与依据，其静态外壳仍使用资源。
- 用户可见固定文案、格式化句子、数量文案分别使用 `string`、占位符、`plurals`；布局尺寸、文字角色、颜色、主题、图形和状态背景分别归 `values/dimens`、styles、colors、themes、drawable/color selector，夜间差异使用资源限定符。已有语言不得丢失。`mipmap` 用于实际启动图标，不为目录数量造素材。
- 先 import 再引用类型；真实类型导航优先 `Intent(context, VehicleAccountActivity::class.java)`，不改成反射字符串。外部 action、组件名、协议键和单位化参数按职责归属集中定义，禁止建立全局万能 Constants 或抽取无语义常量。
- Activity 负责生命周期和装配，呈现状态转换、用户操作、持久化、I/O 与后台生命周期各有归属；沿已有实现迁移，不重建第二套服务、配置源或公共控件。布局迁移保持已审定 Flyme 样式和业务行为。

## 先复用，再编码

1. 先查本项目文档、源码及已跑通参考，记录固定版本、文件/方法、调用顺序、输入输出、线程、资源与退出语义。区分实车事实、离线结果、推断及未知。
2. 同一能力已有实现时先复用或迁移，不重建另一份工具、状态源、接口或 UI 控件。抽公共能力必须写明实际调用点和合适归属。
3. 遇到未探索的协议、厂商接口、ABI、显示消费者或权限链，提交“问题、既有依据、缺口、拟委派 Agent、只读范围、预期证据”的探索申请，用户批准后由其他 Agent 探索；不自行试探、不猜参数、不擅自增加备用路线。已知源码的阅读、引用核查与审计不属于新接入试验。

## 职责与依赖

- `service`：统一基础身份、资源协调、车辆订阅、媒体入口及实际执行/回执；不能靠任意客户端 active 推导用户要切换显示模式。
- `mobile` 与 `common` 产品适配：CarPlay 会话和已核验车型接入；向服务提供地图/媒体数据，不自行夺取仪表显示所有权。上游宿主核心保持可升级。
- `cluster`：用户方案、主题/布局、预览及显示工作意图；界面不直接执行 Root/QNX/采集。草稿、应用意图、运行回执分别建模。
- `ui`：实际公共 View/文字/列表/按钮/弹窗/选择/开关、主题与交互，不依赖车辆、Binder、权限、Root、网络或 Wi-Fi 设置 SDK。
- `contracts`、`client`、`lyrics` 等按现有职责提供边界契约、连接和共用能力；不把业务状态塞进全局工具类。既有 AutoRecord 等模块不得被本轮顺带改行为。
- 一个类一个主要职责，一个方法一个清楚动作，一个职责块只处理一个阶段。禁止把多个动作压在一行、万能 Manager/Utils、无必要的接口层或仅包装一次调用的多层转发。
- 公共抽取以稳定语义和实际复用为依据；单模块专用方法留模块内。兼容入口只委托公共实现，不各维护一套逻辑。

## 注释、命名与 import

- 所有自有类/接口/object、方法/函数（含私有）有对应 KDoc/Javadoc 或语言原生文档注释；说明职责、有效输入、结果及必要的副作用。属性访问器和有独立职责的回调同样说明契约，可紧邻所属属性/回调描述。
- 生命周期、异步阶段、资源提交/释放、错误处理及业务分区前补块注释，说明为什么、线程、所有者、前置条件和取消后行为。不能用逐行翻译代码的注释凑数。
- 注释随代码同步；“已运行/已恢复”须有实际证据来源，不以请求成功代替完成。
- Kotlin/Java 类型在文件头 import 后使用短名。禁止在表达式、类型声明、注解或调用中直接写 `com.xxx.Type`、`android.xxx.Type`、`java.xxx.Type` 等完整限定类名；重名使用 Kotlin import alias 或调整局部命名。包声明、import、Manifest/XML、反射/协议所需的类名字符串不是直接类型调用。
- 类/接口用 PascalCase，函数/属性用 camelCase，常量遵从模块既有风格；动作名体现真实副作用，单位和状态含义清楚。保留既有包名、Galaxy 前缀、兼容配置键与外部契约。

## 代码格式化

- 所有自有代码及新增模块必须遵守统一、可自动执行的格式规则；现有代码按整理批次落实，不能仅整理功能而留下压缩排版。
- 统一缩进、运算符/参数空格、换行、花括号、空行、尾随空白、文件末换行及 import 排列；一行不堆多个独立语句，长参数和调用按语言规则展开。保留字符串、协议数据、脚本 here-document 的有效空白，不能机械替换改变语义。
- 优先复用仓库已有语言格式配置和工具；暂无配置时，编码 Agent 先在候选中提供适用于对应语言的工具、固定版本与配置建议，并在候选副本运行。配置须可复现，不凭个人排版喜好反复改动，不为格式化升级业务依赖或重建工具框架。
- 格式化覆盖本批交付的完整自有源文件，严格限于本批写范围，不批量改第三方、生成代码或其他任务文件。后续各批逐步覆盖全目录；不能把局部完成写成全仓已格式化。
- 交付记录工具/版本、配置、执行命令、文件范围及真实结果。对同一候选再次执行格式检查或格式化应不再产生差异；没有运行必须说明未验证。`git diff --check` 只检查空白错误，不能代替语言格式化。
- 格式变更与行为变更分别说明，审计确认未改变字符串、资源、协议及业务语义；不为格式化另堆无意义 Test。
