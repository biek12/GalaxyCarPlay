# 图片背景与媒体区域替换闭环

2026-11-11。用户要求优先完成图片背景和歌词／媒体区域的完整接入。本轮将上轮原生候选装配到 AutoCluster、AutoService、Root helper 和 QNX Hook；正常使用不需要手工复制 SO、导入认证材料、登录 Telnet 或执行试验脚本。本文范围是这两条产品链；CarPlay／本机地图生产者仍按原专项推进。

本轮没有连接车辆、安装、启动模拟器或执行 HMI。源码闭环、离线合同验证、目标候选编译与实际车机显示分别记账，不用宿主模型代验原厂 Kanzi。

## 实际接入

| 阶段 | 图片背景 | 歌词／媒体 |
| --- | --- | --- |
| AutoCluster | 选择图片，保存在本App私有目录；已应用方案与草稿分开 | 已审定紧凑头部、封面、四行歌词、当前长句滚动和短进度 |
| 客户端 | 同一份方案／图像FD提交，重连重放；迟到旧请求不会覆盖新方案 | `VisualMusicSession` 只在真实可视需求存在时查询／缓存完整歌词，原始媒体单独保留 |
| AutoService | 校验调用签名／包／元素租约和FD类型／尺寸；后台解码，完整保留图片、等比居中，空白区域黑色；只有解码成功且租约仍有效才替换当前方案 | 来源选择、稳定曲目身份、原始／可视快照、封面版本与会话校验；编码GKM1四行与GCA1封面，不改原厂原始歌词透传 |
| 跨系统发布 | 固定1920×532紧密RGBA8；后台原子发布GBF1，只有换图／换代才搬运像素；静态图片的有效期由服务租约决定 | GKM1／GCA1和GHL1租约发布到自有OTA桥目录；不把图片路径／客户端Shell传给Root |
| 首次运行／升级 | 独立控制worker经自有认证Root helper，以固定op11部署源码绑定的SO、控制器、材料校验和及健康检查程序。核对固定固件和已安装版本，复用健康会话；确有需要才启动 | 使用同一部署／生命周期；op12读取UI回执，不登录QNX |
| 原厂UI | 找到唯一`Contents2D/module_BG/BG`，创建自有Texture/Image2D，保有并替换原子节点；换图不重启HMI | 原厂可见媒体区域内挂接已审定面板；保有原组对象，失焦／无媒体／过期时放回原对象 |
| 运行回执 | 实际背景槽位所有权、帧序号、代次 | 实际媒体挂接、GKM revision；与背景共同携带UI/EGL提交计数和PID |
| 停止／恢复 | 单独关背景只撤销背景；全停时由控制器确认原厂进程恢复 | 单独关音乐只撤销媒体；服务失效／UI失去心跳由独立guard恢复，且只结束映射本应用SO的进程 |

表中首次运行／升级一行同时适用于两条链。控制器没有9秒试验期限，工作状态受持久用户选择、活跃客户端租约和服务续租控制；不是无条件常驻。旧有驻车试验入口仍保留限时约束。

## 生命周期和界面

- 背景／音乐需求独立于旧`features.projection`，遵守Root与全局自动运行关闭选择。Root未就绪先等待，不以配置已保存冒充运行成功。
- 图片解码期间返回“正在应用”；失败明确失败并保留上一份工作方案，不能把上一份方案的active回执算作新图片成功。撤销使排队中的图片提交失效。
- 只有当前服务代次、当前来源、未过期的GHR1实际回执才能成为active。进程／Root就绪、GHL1意图、文件写入和EGL活性均不能单独代验节点挂接。
- 新服务先核验当前APK对应部署版本，避免旧SO遇到新租约后刷新心跳而绕过升级。失败恢复有次数和间隔，重新应用方案可以开启新一轮；不循环抢占HMI。
- 采用此前驻车接入验证过的进程退出交接、库路径和`on -p 15 -X aps=System`环境。先启动独立guard，再交接；发现并发HMI则撤销自有实例。没有修改原厂磁盘文件、挂载、监控清单或启动项。
- 本车既有现场记录中QNX声明UTC比Android约快8小时。GHL使用两次递增续租校准源时钟，单个遗留文件不能建立校准；GHR同时携带源时间和QNX本地采样时间，短命健康检查进程不重新猜时差。过期后不能通过反复读取旧文件重新延长生命期，不修改系统时间。
- 正常换图／切换音乐使用UI线程的可还原节点事务。guard容许短暂代次切换；连续失去有效心跳才恢复。原厂进程恢复确认与节点回执分开。
- 主动关闭／Binder死亡会停止需求；服务崩溃后旧GHL1到期，guard恢复。重新启动读取已应用方案，并重新传递私有图片。陈旧回调与旧代次不复活输出。

主要实现：`ClusterRenderService`、`AutoClient.configureClusterElements`、AIDL `configureClusterImage`、`ClusterBackgroundStore`、`KanziMediaPublisher`、`ClusterHookController`、`ClusterHookReceipt`、`QnxClusterHook`／`QnxClusterRemote`、`g733_hook_runtime.sh`、`g733_music_probe.cpp`与`kanzi_background/background_runtime.h`。

离线验证包含：

1. 真实Android Bitmap解码／缩放，经图像FD生成RGBA；实际发布器生成图片、歌词与租约文件；版本化控制器接受实际挂接回执，再停止并确认恢复。此处Root／QNX控制端明确使用测试替身。
2. 原生测试直接消费上一项编码的同一批文件，挂接背景与媒体，核对四行文字和像素，再撤销并核对原对象身份与顺序。仅为离线执行重置fixture的绝对到期时间；不改像素／文本／代次。
