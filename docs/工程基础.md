# 工程基础与验证

## 目录：学习旧GalaxyPlay，剔除上游mobile壳

用户明确要求保留Galaxy产品目录，并剔除被替代的上游入口，不是取消galaxy。当前结构为：

```text
GalaxyPlay/
├─ galaxy/
│  ├─ mobile/   唯一应用模块：构建脚本、清单、资源、Application
│  └─ common/   产品配置与后续Flyme/车型/OEM适配
├─ common/      上游宿主核心；追加编译galaxy/common
└─ shared/      官方协议、传输、音视频与认证核心
```

**根mobile已删除，不保留第二份应用源码或构建壳。** [settings配置](../settings.gradle.kts)将Gradle逻辑名 `:mobile` 直接映射到 `galaxy/mobile`，所以构建命令不变。旧GalaxyPlay用setRoot绕过原mobile/src；本项目进一步把应用构建脚本也收进产品目录，不留下根mobile构建壳或闲置源文件。

- [应用构建](../galaxy/mobile/build.gradle.kts)、[唯一主清单](../galaxy/mobile/src/main/AndroidManifest.xml)、[Application](../galaxy/mobile/src/main/java/com/ecarx/carplay/GalaxyPlayApplication.kt)和[名称资源](../galaxy/mobile/src/main/res/values/product.xml)均在galaxy/mobile标准目录，不靠第二份variant清单覆盖。
- [产品配置](../galaxy/common/src/main/java/com/ecarx/carplay/product/GalaxyProduct.kt)、[首启初始化](../galaxy/common/src/main/java/com/ecarx/carplay/product/GalaxyStartupDefaults.kt)和[回归](../galaxy/common/src/test/java/com/ecarx/carplay/product/GalaxyStartupDefaultsTest.kt)只在galaxy/common维护。[common配置](../common/build.gradle.kts)追加编译，不丢上游测试。
- [shared核心](../shared/build.gradle)保留官方源码与测试；[galaxy/shared](../galaxy/shared)承载产品侧网络/音频策略层（`MediaPlatformAdaptation`、`P2pChannelPolicy`、JNI 编解码探针）。不引入automotive、samples或site。

显示名 **CarPlay**，applicationId **com.ecarx.carplay**，debug无后缀，保留上游namespace。产品版本与核心锁定分开见[版本属性](../gradle/galaxyplay-version.properties)，当前 `0.1.0-dev / versionCode 1` 不是已发布版本，不用它覆盖车辆应用。

首启只填缺失的L6 2023 Max / FlymeAuto 2.3.1标识和MANUAL偏好，不覆盖显式P2P/认证，不连接手机或绑定OEM。

## 旧GalaxyPlay适配迁移批次

按用户授权完整导入旧GalaxyPlay `galaxy/` 目录（445份登记：**401导入 + 41导入后适配修改 + 2保留本项目入口 + 1导入后删除**），逐项按L6与官方v0.2.21接口适配。旧参考`samples/`不迁入。

- 规模对照参考目录：`galaxy/common` 370份全部在位并新增17份（方控`steering/*`、`GalaxyHostAdapter`、启动默认值、诊断拆分等）；`galaxy/shared` 50份全部在位并新增5份（`MediaPlatformAdaptation`、`P2pChannelPolicy`、`GalaxyAudioPreviewFallback`、JNI `Product.mk`/`Application.mk`）；`galaxy/mobile` 25份全部在位并新增6份。
- 核心接缝（均为中性接口，不反向依赖Galaxy类型）：`CarPlayHostProduct`/`HostProductBindings`（产品装配入口）、`CarPlayBackgroundSession`从`CarPlayHostActivity`抽出、`MediaPlatformAdaptation`（音频属性/路由/焦点注入）、`AudioRenderer`增加产品注入参数（默认值保持上游行为）。
- 已落地功能：Flyme原生UI与设置页、USB有线与MANUAL/P2P无线配置、L6/L7音频模板与焦点策略、原车媒体注册与回调、方控学习（Autolink传输/手势/存储/引擎）、更新源与诊断。
- **方控运行时（2026-10-29 已完成）**：`GalaxySteeringBinding` 在 `bindMedia`/`sessionStored`/`sessionStateChanged(true)` 三处挂接，`detachMedia`/`sessionStateChanged(false)` 释放；主线程 + 代次号串行化，同一控制器重复挂接为空操作、控制器更替先释放旧监听、close后迟到回调丢弃。媒体四动作经 M05 跨源250ms窗口与 `CarPlayBackgroundSession.beforeMediaCommand` 闸门，按 `sendMediaButton` 真实返回值回报；Siri/接听/挂断走控制器对应方法。设置页只剩一个入口 `GalaxySteeringSettings`（`L7SteeringDebugPage` 降级为其内部“实物键观察”分区），旧键 `xcertplay_airplay/galaxy_steering_enabled` 可读并双写。
- **部分实现，仪表输出仍未完成**：Galaxy产品CarPlay媒体会话现独立发布封面、标题/艺人、播放进度，并在独立音乐卡绘制；歌词按用户授权从 LRCLIB 查询，网络请求只发送标题与艺人，卡片关闭即取消请求。音乐层与完整导航地图的合成/界面层已有接点，但这些 Android 画面尚未进入 L6 HAB→QNX。已静态解码 AutoDisplay v3.6.2 并固化其 Java-side `virtual_cluster` 样本参数用于离线契约回归；其 HAB Service `exported=false`、不提供 Binder，Native HAB 库及帧/提交协议不可作为本应用的跨包接口。用户目前没有可提供的授权 HAB SDK/API；因此不复制样本二进制或猜协议，也不把 sample 参数测试写成显示功能完成。L6 TBT已新增显式`DIMNaviInteractioncService` Binder适配，按静态L6 DIM契约发送导航启停与路名；仍未在目标固件/实车验证Binder授权、运行回执与QNX显示。此结构化TBT仅是配套信息，不替代111完整地图，也不证明HAB画面已输出。L6 上原车窗口键回送仍受既有 `model()==L7` 门控（是否开启属产品决策）。

## 固定基线与差异

从官方 [v0.2.21固定提交](https://github.com/shihabal3amri/DiPlay/tree/49bf3bc2b011cb5ee7c7f4da9b99b18cbd3a23a2)导入1322份文件，原始SHA256见[基线锁定](../tools/upstream/baseline-lock.json)。[补丁登记](../tools/upstream/patches.json)记录 `mobile/ → galaxy/mobile/` 路径映射，原始摘要不改，并登记4组补丁：

- P001：工程名、模块选择和唯一应用路径。
- P002：产品标识/入口、首启配置与common追加编译；含产品新增文件。
- P004：移除上游临时手机认证syslog采集，保留正常Lockdown/CarKit协商。
- P005：旧GalaxyPlay `galaxy/` 完整迁入与v0.2.21核心接缝（产品装配、音频平台适配、后台会话抽取）；[导入清单](../tools/upstream/galaxy-import.json)单独记录445份来源与事后适配。

当前共467份登记差异：**439份galaxy产品文件（galaxy/common 411 + galaxy/mobile 28）+ 28份上游核心文件**，分组为 P001 1 / P002 8 / P004 1 / P005 457；D11首批将3个L7命名的车型音频配置类纯重命名为`GalaxyVehicle*`，故`patches.json`现记录3份产品删除（旧类路径）并登记3个新路径，导入清单同步标注。未迁旧核心整包。同步先生成独立候选、映射应用路径并核补丁，再审查差异、许可与回归；不直接覆盖工作区。

```sh
python3 scripts/project_checks.py
python3 -m unittest discover -s scripts/tests -v
python3 scripts/record_patches.py            # dry-run：列出新增/修改/删除，不写盘
python3 scripts/record_patches.py --write    # 落盘重建补丁登记与差异段

```

[离线检查](../scripts/project_checks.py)验证漂移、丢失/新增/删除、补丁摘要、入口唯一性与无凭据边界；[登记工具](../scripts/record_patches.py)在产品层增删改后按基线重算差异段与摘要（内容未变的文件逐字节不变，`--write` 才落盘），并把已删除文件从补丁中移除、记入 `deletions`、在[导入清单](../tools/upstream/galaxy-import.json)标注“导入后删除”；[候选工具](../scripts/prepare_upstream.py)只读取本地正式发布标签，不联网、不切换参考HEAD，候选存在即拒绝覆盖。三者都不代替Android编译或完整许可/隐私审计。

### 单命令验证（D09）

```sh
scripts/verify.sh            # 全量：离线源码检查 + :shared/:common 单测 + :mobile lint + assembleDebug
scripts/verify.sh --quick    # 只跑离线源码检查与工具回归（秒级，不调 Gradle）
scripts/verify.sh --no-lint  # 跳过 :mobile:lintDebug
scripts/verify.sh --offline  # 强制 Robolectric 离线；缓存缺失直接失败
scripts/verify.sh --mirror   # 依赖解析走公开镜像（仅本机网络受限时）
```

[verify.sh](../scripts/verify.sh) 与 [verify/lib](../scripts/verify/lib) 只服务本机验证：不进入 APK、不进入产品源集、不改依赖声明或测试断言。缓存与工具链默认都在仓库内、已被 `.gitignore` 排除，可用环境变量覆盖：

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `GALAXY_VERIFY_CACHE` | `<repo>/.work` | Robolectric 依赖与测试沙箱 home 的根目录 |
| `GRADLE_USER_HOME` | `<缓存>/gradle-home` | Gradle 用户目录（依赖下载缓存） |
| `GALAXY_ANDROID_SDK` | `<缓存>/android-sdk` | Android SDK/NDK；目录存在时自动导出 `ANDROID_HOME`/`ANDROID_SDK_ROOT` |

离线准备：把 `android-all-instrumented-*.jar` 放进 `<缓存>/robolectric-deps`，脚本据此打开 `robolectric.offline`；同时把测试JVM的 `user.home` 重定向到 `<缓存>/android-user-home`，因为 Robolectric 的下载锁落在 `user.home`，受限环境写不了真实用户目录。缺缓存时退回公开镜像（`GALAXY_ROBOLECTRIC_REPO_URL` 可覆盖），仅在 `--offline` 下直接失败。
