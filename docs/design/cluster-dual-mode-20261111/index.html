A / B 信息架构对照

同一套 FlymeAuto 视觉语言，区别只在导航组织；不另造两套品牌风格。

常用操作步骤（按结构推演，非用户研究数据）
A · 四入口（推荐）B · 三 Tab + 独立入口
看当前状态总览（一级入口，常驻左导航）我的主题 Tab 顶部薄状态卡
改原厂音乐原厂增强 → 音乐 → 预览 → 应用顶部小控件「原厂增强」→ 同左
做完整主题主题 → 主题库 → 编辑器编辑主题 Tab（与总览同层）
日夜 / 启动设置设置（独立一级入口）顶部小控件「设置」
可见性差异

A：日常启停、原厂配置、主题制作、基础设置是四个并列一级入口，任一任务 1 步可达；总览有独立空间逐项列出元素状态与应用回执。

B：改动较少、沿用现有三 Tab，但模式与设置被压成顶部小控件；三 Tab 常占 100px，进入原厂配置时 Tab 与当前任务无关；状态卡被压缩，元素状态无独立位置。

比较的是 4 个任务入口 与 3 个主题入口加独立入口 的组织差异，不是性能差异；两者共享同一套色阶、文字角色、组件与状态语义。

建议采用 A：Codex 规划中的推荐方向。现有三个主题功能下沉到「主题」内部，功能不删。模式名建议对用户展示为「完整自定义 / 原厂增强」，技术文档继续写遮罩 / 元素替换，避免混淆两条出口。
