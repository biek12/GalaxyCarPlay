### 原厂语音助手真实接收链

以下均来自本车刚提取 APK，区别于旧 L7 广播推断：

1. `InputService/sources/com/geely/inputservice/policy/KeyCodeActionImpl.java:322` 的 `onShortClick`，在 `:372` 对 200231 调用 `sendVoiceBroadcast(0)`。
2. `InputService/sources/com/geely/inputservice/action/ActionCommonManager.java:234` 创建 `ecarx.intent.action.ECARX_KEY_RVOICEASSIST_EVENT`；`:240` 写 `ecarx.extra.ECARX_KEY_EVENT_TYPE=200231`，`:241` 写 `ecarx.extra.ECARX_KEY_ACTION_TYPE=0`；`:244` 发给当前用户。
3. 系统广播历史真实派送给 `com.baidu.iov.sal/com.baidu.iov.salapp.carcontrol.VoiceassistKeyEventBroadcastReceiver`。
4. `VRMiddleware/sources/com/baidu/iov/salapp/carcontrol/VoiceassistKeyEventBroadcastReceiver.java:24` 校验 action，`:25` 读取 keyEventCode，`:27` 校验 200231，`:30` 调用 `BridgeSDK.getInstance().get(ISpeechManager.class).toggleDialogue()`。
5. 长按是另一分支：`KeyCodeActionImpl.java:268` / `:299` 调用 `sendCarLinkBroadcast(3)`，Action 为 `action_steering_wheel_controller_event`。这次用户要求短按，不把该源码分支标为长按实车已验证。

现有 `L7SteeringWheel` 只接收第五项的广播，不能覆盖本车语音短按入口。后续按已核验链增加观察/路由，保持单一事件所有者与去重，不禁用或拦截原车助手。
