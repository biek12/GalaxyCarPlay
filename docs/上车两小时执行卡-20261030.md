```sh
cd /Users/anjon/Documents/GalaxyPlay

```

上车后沿已有授权通道连接，使用实际TLS/无线ADB端点，不猜固定5555。下列 `devices` 仅列出已经连接的目标；不把设备标识复制进报告。

```sh

field() { python3 "$BUNDLE/scripts/cluster_field_session.py" --bundle "$BUNDLE" --results "$RESULTS" --adb "$FIELD_ADB" --serial "$FIELD_SERIAL" "$@"; }
```

## 已准备的安装命令（现场显式执行）

使用已连接目标，更新自有应用，保留数据；每条都要显示Success再继续。不要卸载/清数据/更换签名。失败保留原始错误供本地判断，不反复试装。

```sh
"$FIELD_ADB" -s "$FIELD_SERIAL" install -r "$BUNDLE/app/AutoService-debug.apk"
"$FIELD_ADB" -s "$FIELD_SERIAL" install -r "$BUNDLE/app/CarPlay-debug.apk"
"$FIELD_ADB" -s "$FIELD_SERIAL" install -r "$BUNDLE/app/AutoCluster-debug.apk"
"$FIELD_ADB" -s "$FIELD_SERIAL" install -r "$BUNDLE/tests/ProjectionSmoke-test.apk"
field check
field gpu
```

显式 `authorize` 会沿既有root入口授本App权限、恢复ADB开关并启动AutoService自动运行，以App自身身份完成白名单/TLS/ADB Root/helper核验。其他check/gpu/perf/fields/snapshot命令保持原范围，不自动取得Root或登录QNX。`snapshot`只记录本机ADB UID、固定布尔状态、目录/采样/有效计数及数值时序；不证明helper/QNX身份，不导出凭据或任意状态文本。

`perf`依赖**已经存在的UID0 ADB**，否则立即报错；此时先按AutoService既有TLS/Root流程排查/重连实际端点，不能拿缺权限的空采样当通过。`fields`不要求UID0，但依赖本轮AutoService已运行。两者只读取，不切巡航/档位/驾驶模式/回收。

## 定位速查

| 现象 | 先取什么 | 下一步只查这一段 |
| --- | --- | --- |
| APK/GPU失败 | `field check`/`field gpu`输出报告；安装错误本地保留 | 混包/签名/Android EGL先解决，不把GPU问题归给QNX |
| 自身ADB授权未通 | `field authorize --host '当前Android地址'`的阶段报告 | 先核安装摘要、root入口、本App公钥和0640/SELinux、TLS开关/端点、本AppUID与helper；这一项未通优先修复，不拿电脑ADB通代验 |
| 迟迟无画面 | `field snapshot fault`，记自动准备阶段及耗时 | 普通身份AUTH/INIT/ACK → helper UID0 → QNX远端UID → 接收端校验/启动，按最后成功阶段追，不先重装全部 |
| 地图黑但主题可见 | GPU结果、手机是否确实输出111内容、连接路线与截图 | CarPlay111 → 解码/纹理 → 合成；不以TBT替代完整地图 |
| 画面卡/延迟增加 | 当前map10/20/30报告与同屏视频 | 输入/合成/新帧提交、p95/p99、CPU/PSS/线程/FD；先找热点，配置30不代表显示30 |
| 车辆字段异常/假0 | `field fields parked`、原车读数照片与字段状态/age | supported/read status/area/raw/freshness逐层对比，未知保留--；不猜ID/单位或删采集范围 |
| 退出不恢复/图传告警 | 正常STOP前后照片、限定窗口快照、fault/after报告 | 自有owner/import/窗口释放及原车共存；不能以post=0当仪表正常 |

QNX只读窗口快照使用包内 `diagnostics/snapshot-qnx.sh before|during|after`，通过已有授权通道传入自有独立可写目录再执行；仅限定窗口属性和自有/原车相关进程，不抓全量slog/进程环境。脚本输出在其目录上一级 `logs/qnx-<phase>.txt`，通过既有通道取回 `$RESULTS`。QNX程序名称可能为receiver-candidate，以部署记录为准，脚本的旧probe文件ls失败不能当接收端缺失。QNX登录正常由AutoService自动取得；需要额外Shell时复用已核验通道，认证不写入本测试包/报告。**本轮不主动重启QNX或修改原车启动项。**

## 结果落在哪里

`$RESULTS/acceptance.json`逐项填写实际结果、照片/报告相对路径；状态使用not_tested/pass/fail/blocked，并补实际测试时间。自动生成的采样成功只表示工具执行完成，不自动替现场项目判定通过。V18是档位/驾驶模式，V19是首次准备/身份/自恢复，V20是三种连接与音频/原车媒体/方控。V01–V17沿用原编号，便于与前轮比对。
