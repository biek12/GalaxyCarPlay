# Cluster 上车前验证与现场验收

目标固定：银河L6 2023 Max / FlymeAuto2.3.1，Android11/API30/aarch64，QNX7.0.X/aarch64le。当前轮次不连接车辆、不安装，不运行Lint。下列安装/现场命令是准备给实际测试时执行的步骤。

**本次电脑只有两小时电量，现场直接按[两小时执行卡](上车两小时执行卡-20261030.md)走。** 包含100分钟主流程、10分钟故障处理与10分钟退出保存，以及统一版本/GPU/性能/字段/快照命令；打包成功后 `.work/vehicle-test/cluster-current.txt` 指向本轮包。以下为完整验收要求，未覆盖内容如实留待后续。

## 一条命令完成离线准备

```sh
bash scripts/verify_cluster_preflight.sh --package
```

若自有QNX源码改变、尚无匹配的目标候选，显式指定本机已采集rootfs，仅用于导入符号核验，不复制OEM库：

```sh
bash scripts/verify_cluster_preflight.sh --qnx-rootfs /absolute/path/to/captured/rootfs --package
```

入口依次运行契约/服务/Cluster及CarPlay地图音乐接缝回归、三个APK assembleDebug、独立GPU测试APK assembleDebugAndroidTest、全部Python工具测试、HAB本机AddressSanitizer/UndefinedBehaviorSanitizer、主题研究证据校验和主机合成帧复制对照。测试结果不得缺套件、失败或跳过。结果绑定源码与测试脚本、APK证书和摘要、QNX程序摘要；任何失败不生成可交付测试包，修改源码后拒绝复用旧报告打包。Gradle可复用同输入的已有结果，不把过期XML数量当作本次通过。

报告：`.work/logs/cluster-preflight.json`；完整日志：`.work/logs/preflight-*.log`。测试包：`.work/vehicle-test/cluster-editor-<时间>/`与ZIP。包内包含三个APK、配套QNX候选、独立GPU测试APK、日夜组件/主题图、6个可导入主题包、自有源码、摘要、采样工具和本文。没有真实认证/配对/签名材料或OEM库；认证仍由已授权AutoService流程完成。

把包内 `acceptance-template.json` 复制到包外填写V01–V20的实际结果、截图和采样报告路径；不要修改已核验包内文件。统一入口init可自动完成此步。`diagnostics/`提供限定窗口/进程快照脚本与既有显式Telnet诊断工具，不自动登录。

## 先核版本，避免整次测试浪费在混包

1. `python3 /absolute/path/to/bundle/verify_bundle.py /absolute/path/to/bundle`，检查摘要。
2. IPC已升为v2，**CarPlay、AutoService、AutoCluster必须整套更新**，不能只装Cluster。原签名、保留数据；现场采用既有 `adb -s <已连接设备> install -r <APK>` 逐个完成。本轮未执行。
3. 只读核对已装APK与测试包完全一致：

```sh
python3 scripts/cluster_device_check.py --adb /absolute/path/to/adb --serial '<已连接设备>' --bundle /absolute/path/to/bundle --output .work/logs/cluster-installed-check.json
```

该脚本不连接新地址、不安装、不取得Root、不运行QNX；不保存设备标识。版本不同直接指出具体应用。不要为测试清空应用数据、换签名或修改原车启动项。

## 可先在开发Android设备执行的真实GPU冒烟

本机离线测试使用Robolectric原生Canvas，**没有Android真实EGL驱动执行证据**。独立 `tests/ProjectionSmoke-test.apk` 已准备：运行自有Canvas→SurfaceTexture/OES→EGL→ImageReader链，校验上下方向/通道、预乘透明度、完整地图适配、草稿预览独立几何、首帧原子切换、关闭预览后正式输出，以及圆角裁切/整体虚化/边缘虚化中心清晰。只画合成色块，不启动AutoService/Root/HAB，不操作车辆或QNX，可在开发Android设备/模拟器提前做。

先安装与包内AutoService匹配的测试APK，再显式执行：

```sh
python3 scripts/cluster_device_check.py --adb /absolute/path/to/adb --serial '<已连接设备>' --bundle /absolute/path/to/bundle --gpu-smoke --output .work/logs/cluster-gpu-smoke.json
```

没有兼容设备时保留“未执行”，不能用测试APK编译通过代验。现场先跑这一步可把Android合成问题与HAB/QNX问题分开，目标60秒内返回。

## 性能采样已准备

相同源内容、温度、配置下分别保留旧版本和本轮报告。脚本只读已存在UID0 ADB；不会调用adb root或改变场景。整机SurfaceFlinger单列，不归入自有App合计。

```sh
python3 scripts/measure_autoservice.py --serial '<已连接设备>' --scenario map-media --warmup 60 --duration 300 --output .work/logs/map-media-30.json
python3 scripts/measure_autoservice.py --serial '<已连接设备>' --scenario static --warmup 60 --duration 300 --output .work/logs/static-30.json
python3 scripts/measure_autoservice.py --serial '<已连接设备>' --scenario stopped --warmup 20 --duration 60 --output .work/logs/stopped.json
```

报告记录CPU（100%=一核）、PSS/RSS、线程/FD，以及限定自有dump数值：地图/主题纹理到帧、合成提交、新内容HAB提交、compose/copy/postAck/frameAge/postInterval的最近256样本p50/p95/p99。POSTED只证明QNX `screen_post_window` 成功返回；帧龄起于Android ImageReader取图，不是手机到面板延迟。物理显示帧率/端到端延迟需同屏计时/相机另行确认，不混用两端单调时钟。

本轮不预设“60fps合格”或无依据CPU数字。30上限作为主要对照，比较与旧10fps同内容表现；出现持续排队、丢帧、线程/FD增长、地图缺内容或原车告警时保存对应阶段结果供定位。保留上一套已安装APK与同轮接收端作为回退材料；不卸载/清数据，不强停原车服务，不修改窗口层级来掩盖告警。

## 二轮专项（本轮新增）

按[已确认二轮需求](Cluster二轮需求-巡航回收与音乐分区-20261030.md)检查：巡航off/stby/active与原车对应、目标速度单位/圆点角度，低中高自动档位与独立回收功率来源；raw电功率/累计能量不冒充kW。原厂续航条位置/样式、胎压页先采集再标定，模板待标定项不算通过。菜单raw key6短按四页循环、长按/取消不切，App/Root两条事件通路与迟到回调分别验收。地图边缘虚化/整体/关闭、圆角开关/半径与完整源内容；音乐背景的区域/圆角/地图及封面模糊、最新四行歌词、页码及快速连续切页。场景树保存后重载，保持所有子组件可编辑。


二轮专项对应验收模板V12–V17，不与旧轮次记录合并。现场核对APK后，可对用户已选择的状态运行以下只读采样；脚本不会改变巡航、回收档位或车辆状态：

```sh
python3 scripts/capture_cluster_fields.py --serial '<已连接设备>' --label parked --duration 30 --output .work/logs/cluster-fields-parked.json
python3 scripts/capture_cluster_fields.py --serial '<已连接设备>' --label cruise-standby --duration 30 --output .work/logs/cluster-fields-cruise-standby.json
python3 scripts/capture_cluster_fields.py --serial '<已连接设备>' --label regen-auto --duration 30 --output .work/logs/cluster-fields-regen-auto.json
```

可选标签还包括cruise-off/cruise-active/regen-low/regen-medium/regen-high。仅导出明确列出的仪表数值、枚举、新鲜度与菜单序号，不保存任意属性/媒体/认证原始输出。报告中的passed仅表示采样执行完成，`units_and_regen_direction_verified`保持false，必须结合原车对照独立核实；原始功率字段没有自动换算成kW。截图时同时保留原厂胎压及两条续航的区域尺寸/位置，再填写V14据此标定。
