# Cluster 组件细化与 GT 对标

2026-10-30。用户已认可总体方向与 Flyme 风格，要求每个组件继续细化；组件库一行三个真实样式预览，浏览不添加，只有编辑器的“添加组件”实例化。此文描述本轮自有实现，实车效果仍需指定 L6 验收。

## 参考实际做法

用户指定的 [GT 页面](https://carplay.silo42.design/examples/gt/) 是浏览器仪表演示，其编辑器把仪表分为 speed/rpm/map/gear/telltales 元素。读取页面及脚本后确认：速度表配置包含盘面、外圈、起始/扫过角、主次刻度、刻度数字位置、细针及尾部/轴心、中央速度/单位、附属续航、巡航/限速标记、条件配色和左右辅助弧；并非只有一个“圆环+数字”控件。示例画布1920×720，不能把它直接当成本车1920×532的布局。

参考脚本在本机 `.local/gt-editor.8102bd40.js` 留存用于只读研究，页面检查图为 `.local/gt-speed-properties.png`。此站的代码和素材没有复制进 APK；本轮使用自有 Android Canvas/Path/Picture 绘制。GT功能结构也不等于本车已有所有字段：巡航/限速/附属弧仅绑定 AutoService 实际已发布的只读字段，缺失显示为空/不可用，不猜属性 ID。

EVCC 的固定版本与源码调用证据继续见[3.3.3研究](EVCC3.3.3流畅度与主题补充-20261030.md)和[主题方案](多投屏主题系统方案-20261030.md)。本轮学习静态缓存、结构化元素、统一动画时钟和有界最新状态；可配置上限、内容截止时间与自有消费确认属于本项目新增实现，不能写成 EVCC 原有功能。

## 本轮组件能力

所有组件支持名称、位置/尺寸、显示/隐藏、锁定拖动、层序、复制、删除；可样式化字段支持日间/夜间单独覆盖与恢复继承。绑定/量程等语义字段不随日夜改变。共24类，每类3个自有预设，共72个；样式预览和实际主题使用同一绘制器。

## 运行结构与性能

XML在IO线程解析、校验、编译；图片缩采样/字体预热、颜色数值解析和静态表盘Picture缓存均在准备或场景变更时完成。几何拖拽复用资源/属性缓存；逐帧只使用最新数据、动态组件与统一动画状态。正式主题用硬件 Canvas 输出透明层，AutoService 的单一 EGL owner 采样原生地图 OES 纹理，分别输出仪表和编辑草稿预览，不截图地图、不传 Binder Bitmap。

配置范围1–60fps，默认输出/组件动画上限30。帧率控制采用累计余数的截止时间，静止内容不重复绘制；地图按到帧、歌词按边界、车辆按变化/过期唤醒。HAB无新画面时1秒心跳只为保持已有会话。慢消费时有界邮箱保留最新帧，不累积待显示旧帧；配置上限、纹理到帧、输出提交、QNX提交确认和面板呈现分别测量。

仍存在 ImageReader RGBA读回、pipe、RGBA→BGRA共享槽位和QNX Screen buffer复制，不能宣称端到端零拷贝。自有GLC2扩展在双方协商后，发送端等待QNX复制并成功 `screen_post_window` 返回的签名POSTED，才可覆写共享槽位；省去接收端scratch中转。该确认不等于物理面板呈现，也不是对AutoDisplay未知ACK字段的猜测。
