# 项目规划

目标：**银河 L6，2023 年 Max，FlymeAuto 2.3.1 优先**；随后扩展 L7。应用显示名 **CarPlay**，包名 **com.ecarx.carplay**。

代码基线已确认：官方 DiPlay **v0.2.21 / 49bf3bc2b011cb5ee7c7f4da9b99b18cbd3a23a2**，选择性迁入现有适配。用户已于2026-10-28明确要求开始建立项目基础：本轮落入官方核心与L6首启配置；依用户进一步澄清学习旧Galaxy目录、剔除上游根mobile，应用只在galaxy/mobile维护，实际验证见[工程基础](工程基础.md)；不等于完整App适配或实车验收。

## 1. 执行原则

- 用户已确认 DisplayAuto 路线支持 L6/L7、方控程序已跑通，直接作为开发前提；不要求用户再提交可行性证明。
- Agent 负责从已提供源码确定服务、接口、参数和迁移位置。参考项目的车型硬编码是要替换的实现细节，不是本项目的否决条件。
- 不新增无源码依据的防御性回退或能力缩减；正常工作、停止、释放与重新连接按具体协议实现。
- 逐项确认产品范围与交互选择；源码能确定的技术细节由 Agent 落实，不把每个接口变成用户选择题。
- 前一版“风险与停止线”“ECARX热备/候选降级”“请用户定位DisplayAuto版本”等表述撤销。具体接入及剩余源码工作见[源码核验](源码核验.md)，不是要求用户补证明。

## 2. 本项目接入结构

```text
CarPlay App：GalaxyPlay 原生 Flyme View 页面、设置、方控学习
  └─ Galaxy 会话编排
       ├─ 官方 DiPlay v0.2.21
       │    ├─ USB：iAP2 / NCM / USBMUX / Lockdown
       │    ├─ 无线：MANUAL 热点 / Wi-Fi Direct
       │    ├─ AirPlay 主屏与集群111视频 / 音频解码
       │    └─ 媒体HID / Siri / 电话控制
       ├─ L6 配置：2023 Max / FlymeAuto 2.3.1
       ├─ 音频：L6模板 + Galaxy焦点策略 + 标准usage路由
       ├─ 原车媒体：Galaxy MediaCenter注册、曲目/进度与控制回调
       ├─ 仪表：AutoDisplay的L6/L7专用HAB→QNX接入 + 原生集群流；DIM数据独立接入
       └─ 方控：Autolink HardKey → 学习/手势/映射 → DiPlay控制器
```

学习旧GalaxyPlay的产品目录，但剔除根mobile壳：应用构建、清单、资源与入口只在 `galaxy/mobile`，Gradle `:mobile`直接映射该目录；产品/Flyme/车型/OEM适配只在 `galaxy/common`，由根 `common`追加编译。根 `common/shared`保留上游宿主及协议核心，不在两处放同一产品代码；无真实实现不预建galaxy/shared，不引入星枢完整车控/规则/脚本/远程平台。下列新类名仍是建议职责名，不代表功能已经建成。

## 3. 按功能确定迁移内容

### 3.1 FlymeAutoUI 与车型入口

**来源**：本地 GalaxyPlay 的 `L7Components`、`L7Ui`、Header/ModalDialog/Settings 组件与 `galaxy/common` 产品资源，已有原生 View 实现。

**执行**：

1. 迁入组件、主题与对应页面，保持与核心界面解耦；产品显示名改为 CarPlay。
2. 建立 L6 profile，首启车型与音频模板指向 L6，不再继承 `L7AudioTemplates.model()` 的 L7 默认。
3. 保留旧配置键的兼容读取，产品类名是否去掉L7前缀不影响已有配置格式。
4. 中控画面尺寸、系统栏与Insets仍由宿主实际窗口计算；不把仪表输出尺寸混入中控UI布局。

### 3.2 USB 与无线

**核心**：保留 v0.2.21 的 `CarPlayController`、`IphoneUsbHost`、NCM、USBMUX/Lockdown及无线管理器，不从旧GalaxyPlay整文件覆盖。

**产品接入**：迁入 `GalaxyPreferencePolicy`、无线设置/原生热点配置及启动策略；由其构造 `CarPlayRuntimeConfig`。

- 有线设置 → `transport=WIRED` → iPhone USB权限/重枚举 → iAP2/NCM/USBMUX → CarPlay会话。
- 无线设置 → `transport=WIRELESS` → 已保存模式对应的MANUAL或P2P管理器 → CarPlay会话。
- 沿用已有GalaxyPlay默认 **MANUAL原生热点**，同时完整保留 **Wi-Fi Direct** 显式选择；两者都是本项目需实现的路径，不是互为防御性回退。
- MFi来源维持独立配置，不把USB_CH341解释成USB投屏，也不为切换网络方式改动认证身份。

### 3.3 L6 音频：明确的模板和核心修改点

迁入既有 L6 模板、`AudioOutputPolicy`、路由模板解析、`L7AudioRouting` 和焦点策略。

| 角色 | 模板策略键 | Android usage | 焦点gain |
| --- | --- | --- | --- |
| 媒体 | 101 | USAGE_MEDIA = 1 | GAIN = 1 |
| 导航 | 103 | USAGE_ASSISTANCE_NAVIGATION_GUIDANCE = 12 | GAIN_TRANSIENT_MAY_DUCK = 3 |
| Siri | 102 | USAGE_ASSISTANT = 16 | GAIN_TRANSIENT = 2 |
| 电话 | 104 | USAGE_VOICE_COMMUNICATION = 2 | GAIN_TRANSIENT = 2 |
| 铃声 | 独立角色 | 按铃声usage | GAIN_TRANSIENT_MAY_DUCK = 3 |

L6模板保持 `preferBus=false`、`outputBuses={}`。这些是已有L6方案，不是待用户猜测的设备编号。

**必须做的适配**：官方 v0.2.21 的 `AndroidMediaSink` 内嵌 `AudioFocusCoordinator`，默认不纳入NAVIGATION焦点且优先级为MEDIA→PHONE→ASSISTANT。旧GalaxyPlay同名独立类已提供电话→Siri/铃声→导航→媒体策略。不能并入两份同名实现：在新版核心抽出焦点策略接缝，注入L6优先级/gain及duck行为，保留新版焦点代次、通话与解码生命周期，再迁入相应回归测试。

### 3.4 原车音乐接入

**主实现**：迁入 GalaxyPlay 的 `GalaxyMediaKeys`、`CarPlayMediaSession`、`L7ReflectiveMediaCenter`、`GalaxyOemMediaContract`、媒体回调/封面/来源策略。

```text
DiPlay nowPlaying / artwork / playback
  → Galaxy媒体绑定
  → registerMusic(com.ecarx.carplay, client[, sessionPackage])
  → source列表 / currentSource / playback / progress
  → Flyme原车媒体中心

原车媒体中心 onPlay/onPause/onNext/onPrevious
  → 统一媒体命令入口
  → DiPlay.sendMediaButton()
```

本地L6原厂XSFMediaCenter明确 `EAS_SUPPORT=1`，Galaxy来源策略与原厂AutoMusic实际注册共同确认 **SOURCE_TYPE_ONLINE=6**；本项目L6使用来源6，不套旧分支 `CARPLAY_SOURCE=13`。星枢已有L6 EAS/Binder方案用来核对目标接口和数据格式，而非在新App并存第二套注册器。

DIM媒体字段与音频输出是两件事；需要直接DIM发布的内容按目标Autolink媒体协议接入，不移植领克专用本地MQTT音源声明。

### 3.5 仪表：完整导航地图＋音乐可视信息

**内容取得首先对标DiPlay-ECARX的完整地图投射**：原仓实拍已有高德车道级道路、限速与转向信息；代码为手机原生111地图→解码Surface→自建仪表窗口→DIM显示通路，不需要先在Android重建地图车道或限速图元。其原方法、窗口开关顺序及音乐出口记录于[ECARX仪表投射对标](ECARX仪表投射对标.md)。zmisgod本地Canvas叠加是另一份可用参考，不是唯一内容生产模型。

**需求定义，以用户最新澄清为准**：

- 音乐：封面、进度、标题、歌词等可视信息，不是音频声音；原车音频适配属于3.3另一项工作。
- 导航：完整导航地图，包含车道级导航、到达时间、距离、限速、转向等信息，不是仅发送TBT箭头/距离/路名。
- 研究必须从CarPlay内容取得追到仪表显示：导航地图怎样取得、音乐各字段如何取得、对方怎样绘制/组合、怎样把内容提交到HAB→QNX。只定位HAB通道、媒体注册、DIM字段或111的Surface接口都不能算整项完成。

**需从源码闭合的内容链**（不是已实现声明）：

```text
CarPlay完整导航画面及所需信息 ─→ 地图画面接收/解码 ─┐
                                                  ├→ 仪表内容绘制/组合
CarPlay音乐封面/进度/标题/歌词 → 信息接收与状态同步 ─┘
  → 图像/缓冲区提交
  → L6/L7专用HAB跨域输出
  → QNX仪表接收、合成与显示
```

官方集群111、主屏画面和协议信息回调分别作为源码追踪入口；必须核清参考实现用哪种内容源完成上述目标，不能先假定111单流天然包含全部地图信息和音乐界面。

**已定位的车型专用路线**：zmisgod的[AutoDisplay研究:18–27](../references/upstream/DiPlay-DisplayAuto/docs/FX11_OEM_OVERLAY_COMPOSITION_V25_V26.md#L18-L27)明确普通Android窗口与L6/L7专用HAB→QNX是不同路径；[v28记录:7–9](../references/upstream/DiPlay-DisplayAuto/docs/FX11_CENTRAL_OVERLAY_V28.md#L7-L9)指出AutoDisplay 4.3.9的HAB统一服务标注银河L6/L7。这是本项目应追的目标，不是博越普通Presentation/Overlay方案。当前锚点属于上游留下的逆向记录；底层HAB源码/载荷尚未在本工作区取得，不将文档提及写成实现已迁入。

**迁入与替换**：

1. 完整导航内容接收/解码/窗口生命周期先逐段对标ECARX已实现链；音乐信息绘制与其他布局再对照zmisgod。L6输出适配明确面向HAB→QNX，将参考的内容取得与具体显示端分开，不用普通Android Display屏号冒充目标配置。
2. `GeelyClusterProjection` 的服务调用封装保留为源码参考；目标服务名、方法与屏幕选择沿L6原厂链落实，不把FX11的三标识、display2/4、1920×720/532搬成L6配置。
3. 从jiopia实现抽取集群窗口建立、Surface绑定、导航开始/结束协同及DIM字段转换；不是把领克display1或test-keys要求加入L6产品。
4. L6 TBT显式绑定 `com.autolink.diminteraction/.DIMNaviInteractioncService`，descriptor为 `com.autolink.adapterbinder.IDimNaviInteractioncService`；按目标事务1/2/7/8/11/12/23更新导航状态、转向、距离、TBT事件、ETA和路名，再由原厂服务送FDBus。地图视频、TBT、媒体各自接到本项目统一会话，不建设“多个后端自动回退”体系。
5. `AndroidMediaSink.setSurface(111, surface)`与解除输出沿官方生命周期；正常结束清理本次会话使用的窗口和注册。

**Agent当前继续落实的代码段**：AutoDisplay 4.3.9 L6/L7专用HAB统一服务、Android侧图像提交格式/会话建立、QNX接收端与合成控制。上游记录的反编译目录为 `work/autodisplay-cluster-jadx/sources/`，位于其作者工作区而非该公开Git树；继续追对应材料和调用，不向用户索要可行性证明。原厂 `setPresentationToDimSwitch` 空实现与AutoMap display11残留路径已排除为本项目视频开关，不用其冒充HAB输出。

### 3.6 方控学习：确定走Autolink，不套L7广播

**实际输入**：

- 包：`com.autolink.hardkeyservice`。
- action：`com.autolink.hardkeyservice.HardKeyAdapterService`。
- descriptor：`com.autolink.adapterbinder.IHardKeyService`。
- 注册/注销事务1/2；回调descriptor为 `com.autolink.adapterbinder.IHardKeyCallback`，事务1/2/3分别按下/松开/取消。

**迁移**：星枢 `AutolinkSteeringTransport`、`SteeringGestureDecoder`、`SteeringWorkspace` 的学习/映射部分、配置原子保存、来源去重及对应测试；去除RULE/SCRIPT平台依赖。

**动作终点**：

| 映射动作 | 官方v0.2.21实际入口 |
| --- | --- |
| 播放/暂停/切歌 | `CarPlayController.sendMediaButton()`；HID索引PLAY1/PAUSE2/TOGGLE3/NEXT4/PREV5 |
| Siri | `requestSiri()` |
| 接听 | `answerCall()` |
| 挂断/拒接 | `endCall()` |

沿用已有400ms双击、800ms长按、15秒学习与跨源250ms去重作为迁移初始行为；学习过程不执行绑定动作，完成后预览、确认保存与撤销。旧 `L7SteeringWheel` 的语音广播不是L6原始按键学习输入。

原厂HardKey普通回调是广播分发；媒体中心回调和HardKey事件汇入同一命令调度器进行来源去重，不靠修改后视镜模式实现媒体按键功能。
