## 地图尺寸

原实现把111流固定请求为1920×536，主题只改变合成矩形；原产品 safeArea 又固定保留650/550px左右边距。缩放地图组件后，手机仍按旧画布组织地图。

新链路：

1. Cluster 原有 `SceneConfiguration.map` 携带组件世界坐标矩形。
2. AutoService 合并连续750ms尺寸更新；有实际预览输出时采用草稿，否则采用正式主题。`MapStreamSize` 根据宽高向上8px对齐，位置移动不改变请求尺寸。关闭预览恢复正式主题请求。
3. `onSnapshot.mapStreamSize` 为 v4 的新增可选字段，传给 CarPlay；保留现有 Binder 契约。CarPlay 持久保存最近尺寸，后续连接直接使用。
4. 产品 `clusterDisplayConfiguration` 按新宽高构造111显示声明，safeArea使用零内缩；由核心新增的中性宿主回调沿既有 `restartCarPlay` 生命周期关闭旧控制器/解码器并重新协商。核心不依赖 Galaxy 类型。
5. AutoService 的 SurfaceTexture 默认缓冲及合成时等比适配使用同一源宽高，避免一直按1920×536比例缩放。

这轮采用现有连接重建路径，**尺寸变化会短暂重连 CarPlay，尚未实现无缝在线改流**。没有杜撰任意尺寸的 AirPlay 更新命令；已有 `updateViewArea` 只切换握手前声明的区域索引，不能直接表达编辑器任意矩形。多个预览/正式区域仍共享一条手机地图流，预览关闭后重新恢复正式主题尺寸。新尺寸下手机是否接受、导航布局及连接恢复必须实车确认。

源码：`galaxy/contracts/src/main/java/com/galaxy/auto/contract/MapStreamSize.kt`；AutoService 的 `settleMapSize` / `configureScene` / `publish`；`GalaxyGlComposition.setMapStreamSize` / `render`；`GalaxyAutoServiceBinding`、`GalaxyHostAdapter`；核心 `HostProductActions.clusterDisplayChanged` 与 `CarPlayHostActivity` 的对应接线。默认回调为空，无产品实现时保持上游行为。补丁及摘要由 `scripts/record_patches.py --write` 登记。
