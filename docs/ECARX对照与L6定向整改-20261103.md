## L6的完整画面DIM路线核验

确实不能把DIM与QNX简单二选一：DIM是对外接口/服务层，下面也可以使用原车跨域通路。关键问题是本App能否复用原厂已接通的视频入口，从而无需自有接收程序。

本车材料继续追到具体实现：

1. `AutoMap/.../DIMInteractionImpl.java:161`与`oneOS_DimService/.../DIMInteractionImpl.java:54`的`setPresentationToDimSwitch`均为空；返回/反射成功不代表接通画面。
2. `AutoMap-dim/.../multi/DimCallbackImpl.java:26`的`startDimActivity`用`ActivityOptions.setLaunchDisplayId`，`:57`的`openDimView`遍历PRESENTATION目录，仅在Android ID 11时启动`DimActivity`。这是源码存在，尚未证明目标运行时存在该显示。
3. 为避免把共用残留当成L6现有能力，本轮直接从本机已采集L6地图DEX追实现：`classes5.dex`中的`com.flyme.auto.map.adapter.AMapDimAdapter`实现`EmptyDimAdapter`，`init`、`dimDisplay`、`tryDimDisplay`转给默认空实现；`classes8.dex`中`EmptyDimAdapter.DefaultImpls.supportDim/isDimDisplay`均返回false。只读还原文件位于`.work/research/ecarx-dae07bfc/l6-AMapDimAdapter.java:17`、`:46`、`:78`及`l6-EmptyDimAdapter.java:51`、`:75`，原DEX与还原摘要单列于证据清单。反编译文件只作研究，不编译进APK。
4. `XSFNaviService`的`NaviDashboardImplR`→动态登记的`IDisplayClient`只给出模式请求/回调，`AMapClient.addSurface`→`JVManager`则是“给地图一个Surface让原厂地图画进去”，不能当作已有第三方111视频输出入口。

**结论**：ECARX参考的完整画面确实可复用其原车副屏/DIM通道；当前L6样本还没有确认到等价的已接通入口。这不是用其他车型权限或屏号否决L6，也不等于已证明L6所有原厂图传入口不可用。已给`--navigation-state`加Android显示目录（ID/尺寸/flags/presentation/private），只读观察、不建窗口、不试写屏号。现场据目录及实际显示服务继续追，不能先把display 1、display 11或QNX display 2混为同一设备。**本轮不删除HAB、不切换输出后端，也没有宣称完整视频问题已修复。**

## iPhone麦克风猜测与验证

代码没有按“连接前/后通话”主动选择iPhone麦克风的分支。已请求上行时，`MicrophoneUplink`创建的是**车机AudioRecord**并向手机发RTP。iPhone也可能保留自身输入路由，因此通话中重连成功不能直接证明用了车机麦克风，也不能证明用了手机麦克风。

Apple官方提供“通话/录音中→控制中心→当前App控制→Audio Input→选择设备”的入口：[说明](https://support.apple.com/en-us/101993)。若设备列表提供iPhone麦克风，可由用户选择作对照；不能承诺对微信/抖音永久生效。iOS的`AVAudioSession.setPreferredInput`作用于iPhone内相应App的音频会话，当前Android接收端没有这个执行权限/接口。[Apple API](https://developer.apple.com/documentation/avfaudio/avaudiosession/setpreferredinput(_:))

`AirPlayInfoPlist`的`microphone=false`只是不声明车机输入格式，`microphoneEnabled=false`只是不回传车机上行；两者都不是“强制iPhone麦克风”的命令，不能以无声上行或删语音能力冒充修复。

本轮[MicrophoneCaptureStats.kt:37](../shared/src/main/java/com/shilapi/xcertplay/media/MicrophoneCaptureStats.kt#L37)补`rawPeakDbfs`与处理后`peakDbfs`；[MicrophoneUplink.kt:456](../shared/src/main/java/com/shilapi/xcertplay/media/MicrophoneUplink.kt#L456)在无声窗口核对系统模式、全局麦克风静音和本录音是否被系统silence。`--audio-input-state`保留活动上行与本会话最近16条脱敏摘要，短语音消息结束后仍能对照；不保留PCM/编码包、密钥或远端地址。Android无法从这些统计直接读取iPhone的最终输入选择，报告始终标unknown。
