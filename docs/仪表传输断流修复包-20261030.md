## 现场故障与结论边界

此前已完成 AutoService 自身本机 ADB/Root UID0、QNX 登录/UID0、接收端部署和真实画面显示。用户照片确认新版地图/表盘可见，同时出现原车“仪表显示异常，请联系经销商”，之后断流恢复原车画面。

`.work/logs/autoservice-field/receiver-ended-2037.log` 显示同一接收会话连续处理超过 6600 个事件，随后 `RECEIVER_LOOP_RESULT=-77`、`RECEIVER_CLOSE=0`。本车 QNX 的 77 为 EBADMSG；对应代码在采样帧数据 hash 不一致时拒绝提交并释放窗口。因此可定位到帧数据校验失败这条断流路径，不能把它解释为电脑远程 ADB 断开或原厂窗口必然抢占。

缓存可见性是否为此次失配的唯一根因尚未实车证明。本轮补齐跨 VM 读缓存同步、校验覆盖和有限重传，并保留两端诊断，作为下一次复测包；不能把编译通过写成断流或原车告警已经消失。

## 本轮实际改动

### QNX 导入映射先同步，再取私有快照

`galaxy_hab_qnx.c` 在 INIT 校验前同步整个本次导入区；每个 FRAME 在读取对应 slot 前调用 `msync(..., MS_CACHE_ONLY | MS_INVALIDATE)`。范围限定为本会话导入映射，失败记录阶段/错误码并走既有释放路径，没有跳过操作继续显示。

该组合有两类依据：

- 从已采集的目标 `libpmem_client.so` 的动态重定位确认 `msync`；静态指令 `0x59b0–0x59c0`、`0x6d04–0x6d14` 向其传入 `0x02000004`。这些是该库的分配/释放路径，证明目标 ABI 和所用 cache flags，不冒充原厂接收端逐帧逻辑。静态材料保留在 `.local/research/hab-frame-coherency/`，没有加载 OEM SO 或将它打入产品。
- [QNX 7.1 官方 msync 文档](https://qnx.com/developers/docs/7.1/com.qnx.doc.neutrino.lib_ref/topic/m/msync.html)明确区分 CACHE_ONLY 的 CPU cache 操作与普通文件同步，INVALIDATE 用于失效缓存。现有 DMB 只保留内存访问顺序，不能作为已经完成该 cache 操作的证明。

随后复制 slot 到接收端私有 scratch，在同一份快照上做校验和 Screen 复制。校验失败不写 Screen buffer、不 post、不发成功确认；保留上一张已提交帧，直到重传成功或有限失败后正常退出。

### GLC2 v2：每帧采样校验，覆盖所有共享槽

原方案每 30 帧校验，而 ring 为 6 槽，`sequence % 30 == 0` 总落在 slot0。现在自有 GLC2 v2 在**每帧**计算/校验既有采样 hash，使每个槽均被覆盖；这仍是采样 hash，不宣称逐字节密码学完整性。未启用自有扩展的原协议保留每 30 帧行为。

HELLO/READY/POSTED/RETRY 的版本字段统一为 2，版本、会话、export、stream、sequence 仍由 HMAC 绑定。旧 v1 接收端不会被误判为已具备修复能力：握手失败并释放本代资源后，进入现有 App→现存 UID0 helper→必要的 Root/QNX 接收端准备流程；部署仍按包内接收端哈希和 owner key 判断复用或更新，不修改原车启动项/HMI。

### 同一帧最多重写两次，不用新 hash 接受损坏数据

接收端在 hash 失败后发送与同一帧绑定的 RETRY。发送端只有验过该回执才重写当前 slot，不推进 sequence、不复用为其它帧；最多两次重传、共三次校验尝试。

发送端重写前核对自己仍持有的 slot hash；若本地内容也已变化，保留本地/期望 hash 和序号并退出。重写后也必须与最初期望 hash 一致，不通过重算期望值把不同内容当作原帧。页对齐尾部每次置零，保证协议覆盖的非像素部分确定。

持续失败、缓存同步失败、驱动错误仍完整释放本会话资源；不以无限重启、禁用校验或改变原车窗口层级维持画面。

### 可回溯日志与构建绑定

- Android 固定状态行包含 `consumption protocol=GLC2 version=2 frameChecksum=every-frame`；发生恢复时记录序号、累计重传、期望/本地 hash、局部损坏计数。没有像素、认证材料或任意 Shell 正文。
- QNX 默认只输出失败阶段，而不是每帧全链路 trace；保留 `RECEIVER_CHECKSUM_*`、`RECEIVER_CACHE_SYNCS/FAILURES/LAST_ERROR`、`RECEIVER_POSTED_FRAMES`。事件数与真正 Screen post 数分别记录，重传不能冒充显示帧。
- App 子进程状态读取在非主动关闭时失败，会进入现有 `ServiceTrace`，保留异常类型及源码栈。
- QNX 构建摘要现在递归包含重建 ABI 头和启动汇编，避免新 cache 常量声明未绑定到产物。目标 `msync` 动态导入也由本机目标 libc 的符号表核验后才链接。
