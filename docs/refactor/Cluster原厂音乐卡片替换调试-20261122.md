# Cluster 原厂音乐卡片替换调试

用户确认背景替换正常，要求开始调试音乐卡片。仍按离线边界执行。首个可复现问题落在 AutoService 媒体仲裁。

## 调试证据

- 在背景恢复候选 `e24984f2aa8960201d2caca73c4291a839e4f3ce` 运行 Android 定向验证，Service 13 例、Cluster 12 例、Common 52 例全部通过。覆盖媒体会话、媒体帧、元素租约、Cluster 页面、CarPlay 曲目身份和原始歌词。NDK Clang 的 AArch64 语法检查通过，涵盖帧解析、紧凑卡片和元素流水线测试源码。
- 生产入口探针依次提交无歌词曲目、可视歌词、同曲目的原始带时间轴歌词和迟到的可视歌词。原始歌词提交时会清除可视副本，最后一次 `ServiceMediaSession.publishVisual` 仍返回 `true`，断言失败。`ServiceSnapshotComposer` 会按同一曲目键把可视歌词优先提供给 GKM1 发布器，原始媒体 Bundle 仍保存原词。探针和日志位于恢复工作树的 `.work/cluster-music-debug-20261122/`。
- 媒体仲裁、可视歌词生产者及音乐卡片原生源码在恢复候选与本批基线相同。独立工作树从产品分支的 `e126ab31214b8d5b8fd0b5998e50f46ae69ba2d9` 开出。背景恢复候选仍有独立复审项。
- 产品链为 AutoCluster 元素开关、AutoService 当前媒体及可视歌词、GKM1 与 GCA1、卡片挂接及 GHR1。历史记录支持本车的媒体节点定位和原节点恢复，中文排版、当前画面和实际恢复待实车验证。 [媒体替换闭环](../Cluster图片与媒体替换闭环-20261111.md) · [实车初查](../Cluster新版实车初查-20261111.md)

## Cursor 实施范围

- 在 `ServiceMediaSession.publishVisual` 按当前选中媒体和现有带时间轴原词判定拒绝迟到回调。`selectMedia` 使用同一个判定。保留无可用原始时间轴时同曲目可视歌词回退、换曲清理和原车优先的现行行为。
- 在 `ServiceMediaSessionTest` 用生产入口覆盖同曲目晚到回调、缺少原始时间轴的正常回退及换曲后的旧曲拒绝。验证原词仍可读、可视副本为空和返回值正确。
- 在 `ClusterElementPipelineTest` 用实际发布器和 Hook 端口替身核对只改变音乐开关时，GHL1 中图片位保持，GKM1 对应启停，旧代次回执无法宣告卡片已挂接。复用已有图片、租约及回执断言。
- 业务源码和正式测试的写范围为以下三个文件。其余文件只读。原厂媒体透传、共享背景和恢复实现、Hook 与签名按现行契约运行。
