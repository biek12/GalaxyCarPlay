## 确定的新owner

```kotlin
internal class VehicleFeedDispatcher(
    private val post: (Runnable) -> Unit,
    private val isEnabled: () -> Boolean,
    private val acceptValues: (Bundle) -> Unit,
    private val leases: () -> List<ClientRegistry.Lease>,
)
```

落在`com.ecarx.autoservice.vehicle`。直接借用现有`ipc.ClientRegistry.Lease`，不复制Lease、订阅键、节流时刻或UID；现有Registry仍拥有租约生命周期。构造不调用任何边界、不建线程，不开采集连接或新的Binder通道。

生产装配使用`callbacks::post`、`{ !closed && !paused && features.vehicle }`、`{ sentinel?.accept(it) }`、`{ clients.all() }`。这些都是延迟lambda/既有方法引用；main仍是发布线程，Binder只读缓存。dispatcher唯一持有原`@Volatile private var signals = Bundle()`和`private var feedSequence = 0L`，AutoService删除这两个字段，不留镜像缓存或另一份序号。

### 按原方法逐项迁移

| AutoService原位置 | 新owner/API | 必须保持 |
| --- | --- | --- |
| publishFeed(values, at) | dispatcher.publish(values: Bundle, at: Long) | 先检查isEnabled；不通过时不改缓存、不调sentinel、不取租约、不投递 |
| 同方法缓存及通知顺序 | publish内部 | 保存原values引用 → acceptValues(values) → leases()一次 → 只筛feed非空；不加active/role筛选 |
| 同方法round和节流 | publish内部 | targets空则不增序号；非空则整轮++一次，即使最后全被节流/无值。lastFeedAt非0且at-last小于各自间隔才跳过；到期先写lastFeedAt=at再调用send |
| publishFeedTo(lease, values, at) | dispatcher.replay(lease: ClientRegistry.Lease, at: Long) | 用同一signals缓存，独占++一次序号；不新增enabled/间隔守卫，不改lastFeedAt，即使选取结果为空也保留已分配序号 |
| sendFeed | dispatcher私有send | 原VehicleFeed.select(values, lease.feed)；空结果不发、不补0；非空加原at/sequence，再post { runCatching { lease.callback.onVehicleFeed(out) } } |
| getVehicleValues中select(signals, accepted) | dispatcher.select(keys: Set<String>): Bundle | 只委托现有VehicleFeed.select取当前缓存，不触发采集、不增序号、不加元数据，不更改校验/错误边界 |
| dump两处Bundle(signals) | dispatcher.snapshot(): Bundle | 仅原顶层Bundle浅拷贝，用于已有诊断；不得把该副本变成业务推送缓存 |
| 三处signals = Bundle() | dispatcher.clear() | 只换空缓存；不重置feedSequence、不删订阅、不调sentinel、不增新关闭路径 |

send仍在调用线程先生成完整out（沿用VehicleFeed.select的子Bundle deepCopy），再交既有callbacks worker。不得把select留到异步执行时才读取新一轮缓存；不对异步回调追加closed/租约存活校验、重试或日志，保持原已接收回调语义。每位订阅者的异常在自己的回调里隔离。没有新close方法，不关闭共享callbacks。

## AutoService接线范围

- 在原signals字段附近创建唯一dispatcher；lambda捕获closed/paused等字段但构造时不求值。删除原feedSequence、publishFeed、publishFeedTo、sendFeed，不保留转发链或平行实现。applyDemand原样保留，仍使用VehicleDemand/collector及哨兵键。
- onCreate采集回调仍是`main.post { dispatcher.publish(values, at) }`，不能在采集worker直接改Lease。采集启动/停止、菜单、元数据、Root丢失及sentinel回调顺序不改。
- setVehicleFeed保留原顺序：Binder线程uid/键格式/间隔校验 → enqueue → require原Lease → VehicleFeed.validate(keys, modelPrefs()) → 写feed/interval/lastFeedAt=0 → applyDemand → 非空订阅时dispatcher.replay(lease, SystemClock.elapsedRealtime())。不搬鉴权、不先补发再重算需求。
- getVehicleValues保留uid与feedKeysValid、modelPrefs/validate及runCatching/getOrElse空Bundle；仅把select缓存的这一处换为dispatcher.select(accepted)。不根据订阅者身份删减原缓存拉取能力。
- 三处clear分别在onStartCommand停服分支的collector.stop之后、model分支的retainFeeds之后且collector.stop之前、applyFeatureSettings的collector.stop之后。原位置替换，不挪动关闭/恢复时点；retainFeeds/清零租约节拍仍按原代码执行，序号跨clear继续。
- dump两处补vehicle的Bundle保持同一行求值位置，改为dispatcher.snapshot()。其他快照字段和S2 ServiceSnapshots不变。字符串`record-signals`等协议字面量不改。

本批不迁Binder其他业务、catalogKeys、车辆目录/采集/需求、媒体、快照组装或OEM，不新增Gradle模块。注释明确main写、Binder读、缓存/Lease所有者、序号与取消边界；显式import。AutoService其他职责的历史注释债不扩为本批任务。

## 真实测试

调用生产dispatcher，post边界使用Robolectric真实Handler/Looper；租约使用生产ClientRegistry.attach创建，Binder内核通知可用现有测试边界。不要另写扇出/节流/序号算法模型，不使用真实车辆源。

- 禁用发布不会更新缓存或执行accept/leases/post；启用后即使无人订阅，也先更新缓存并执行accept，再读租约。用边界记录核对顺序，缓存可供select读取，无任何VehicleSource读取。
- 同一轮两个租约共享sequence但分别按250/1000ms节流（用显式at模拟时间）。覆盖恰好到期、全部未到期仍占用一轮序号，以及缺少订阅键时不发空包但保留原lastFeedAt更新顺序。不能加active筛选。
- replay即时补同一缓存，不受enabled/间隔守卫影响、不改lastFeedAt；与常规轮次共用连续序号。clear只清缓存，后续推送的序号不归零，订阅意图仍在原Lease。
- select保持仅请求键/无at和sequence、不补默认值，沿用生产VehicleFeed.select的deepCopy；snapshot顶层修改不污染缓存。异步回调拿到的是入队前生成的值，前一位抛错不阻断其他订阅者。

可合并为少量测试场景，不追求数量。既有Service全部测试和Cluster/U1继续执行，新套件必须真实非空；新运行class必须存在。格式在原109项基础加本批两文件，共111项，固定ktlint1.4.1/editorconfig，整文件二次幂等。
