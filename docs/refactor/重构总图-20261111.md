## 2. 依赖、状态和不变行为

- `auto-ui` 沿common已有组件及已迁出的实现补XML/资源封装和兼容API；Service/Cluster/CarPlay消费同一实现。具体源方法与缺口见[Common组件复用映射](Common组件复用映射-20261111.md)，不重新建设一套控件。
- `service` 是身份、车辆订阅、媒体入口和输出所有权的唯一业务执行端；应用 UI 不另建 Root/ADB/QNX，也不自行采集车辆数据。
- `cluster` 负责方案/草稿/预览和显式显示意图；原厂元素替换与完整遮罩保留，音乐卡片只在 Cluster 配置。CarPlay 提供数据不表示请求整屏接管。
- `mobile` 是 Gradle 宿主壳；大量 CarPlay 产品 UI/适配实际在 `galaxy/common`，不能只整理 14 行 mobile App 壳后说 Mobile 完成。
- 所有批次保留 applicationId、旧包名、Galaxy 命名、原签名、契约版本、prefs 兼容键、Flyme 视觉和已确认产品行为。未知协议不在重构中猜测；不新建备用路线/删能力。
- 本轮全程离线，不连接/安装车辆，不启动模拟器，不操作原厂 HMI。B1-R3 旧候选依旧冻结、未集成，其行为修复需以后用户叫审计时独立复验；U1 不偷带该候选。

## 4. U1 跨文件调用图

`ServiceActivity → ActivityServiceBinding → ServiceHomePresenter.render(state)`；状态来自既有 AutoClient observer 快照与现有设置读数，经 `ServiceHomeState`转换。用户点击→`ServiceHomeActions`→现有 ServiceFeatures/AutoStartup/RemoteSettings→AutoService Intent；Wi-Fi依旧 NativeWifiSettings；账号直接类型导航，诊断进独立 Activity。

`DiagnosticActivity → ActivityDiagnosticBinding + DiagnosticPageController`；controller沿同一 AutoClient 观察/执行调用，文件读取/认证覆盖导入在有界 IO；结果回主线程且销毁后失效。所有普通控件 inflate auto-ui XML/消费公共样式，不再创建 ServiceUi。

`L7兼容入口 / Cluster / Service → GalaxyViews/GalaxySettingRow/GalaxyDialogs → XML骨架+资源`。原 public API 兼容，动态内容只插入槽或行，不能在业务页另手造组件。
