# R0 标准用例：真实入口关闭与保留能力

范围与执行位置以 `R0-整屏投屏归档任务书-20261112.md` 为准。目标是用户刚确认的产品合同，不沿用“整屏能输出”的旧断言。新增用例集中三组即可，不堆参数边界数量，不复制被测逻辑。

| 编号 | 真实生产入口/输入 | 必须观察的结果 | 替身边界 |
| --- | --- | --- | --- |

## 真实构建/归档产物检查

1. 实际执行 verify_cluster_pages，保留日志、JUnit XML 和 result.json；只跑 --baseline 不合格。Cluster 仍需 ClusterAppNavigationTest 与 ClusterPageBehaviorTest。归档 ThemeShell/ThemeLibrary/Component 测试原件/摘要，不能为了凑旧例数保留它们为活跃能力。
2. 以同样离线 Gradle 参数实际运行新 service 用例和受影响既有回归。精确 suite 清单写入新 verify_projection_retirement.sh，零匹配/失败/跳过均失败；不执行无关原车认证/网络测试。
3. 从本轮 AGP 的实际 merged/packaged Manifest 和 Kotlin class 输出（或模块 classes jar）检查 ThemeActivity 组件与旧专用输出类不存在；明确记录路径/摘要。须处理旧 build 中残留的 class：输出目录不能用过期 class 当本轮产物；可只清本任务自身模块编译目录后重编译，不清缓存或其他工作树。源码 rg 只辅助调用闭包，不能替代实际产物证据。
4. 逐项读取基线 git blob、归档文件和 manifest.json 对比 SHA256；确认原文件不再在 main/test/androidTest 活跃源集中。快照允许同时有经过修改的运行版本，标明 snapshot，不误判重复类。
5. 核对 service Gradle 无可执行旧 Android bridge 构建/打包依赖、Root op4/6 无启动调用；QnxClusterHook 的 health hook-health、op11/12、PosixChecksum 和共享资产准备链仍在。此项是产物/调用闭包审计，不写成 QNX 已运行。
6. 最终报告绑定工作树 HEAD、源码/资源/KTS/归档摘要和实际 JUnit 数量；保存格式化范围及二次幂等结果。报告只写离线编译/测试，APK/实车字段为 false。

离线验证无法证明车上上一版本的接收端已退出、原厂窗口已恢复或新 Hook 实屏通过；当前禁止现场操作，应登记这些未验事实，不能为补证擅自连接车辆。
