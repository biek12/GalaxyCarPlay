## 确定迁移与调用顺序

| AutoService现位置 | 目标及调用 |
| --- | --- |
| notify Runnable、snapshotLock、latest、recipients四个字段 | ipc.ServiceSnapshots唯一持有；原字段从Service删除，不保留第二份缓存/锁或notify |
| Binder.getSnapshot中的锁内Bundle(latest) | uid()仍先同步校验，再返回snapshots.current() |
| dump中读取快照的同一行 | 换为snapshots.current()；--foundation-check早退及其他诊断分支顺序不变 |
| publish最后的缓存替换/接收者更新/removeCallbacks/post | kanziMedia?.update(snapshot, musicWanted)之后，在原位置调用snapshots.publish(snapshot, clients.all().map { it.callback }) |

`internal class ServiceSnapshots`构造只接现有调度/生命周期边界，不创建线程或第二个服务状态：

```kotlin
internal class ServiceSnapshots(
    private val post: (Runnable) -> Unit,
    private val remove: (Runnable) -> Unit,
    private val isClosed: () -> Boolean,
)
```

AutoService在callbacks初始化之后装配`ServiceSnapshots(callbacks::post, callbacks::removeCallbacks, { closed })`。不提前执行isClosed，不在构造器启动worker。所有其他callbacks.post、车辆feed扇出、onDestroy的callbacks.close和closed赋值时点原样保留；这个新owner不关闭共享worker，也不加新的close顺序。

ServiceSnapshots具体保留原实现：

1. 同一私有锁、初始空Bundle、初始空接收者列表、唯一可反复remove/post的通知Runnable。
2. `current(): Bundle`在锁内返回`Bundle(latest)`，不是缓存本体。维持原浅拷贝合同，不递归复制Bundle/数组/Bitmap，不添加序列号或新字段。
3. `publish(snapshot: Bundle, callbacks: List<IAutoCallback>)`在同一锁块更新原snapshot引用及接收者列表，再移除同一个通知Runnable；当前接收者非空才post。保持原赋值语义，不对输入额外深拷贝，不去重/筛角色或在发布前检查closed。AutoService在原位置创建接收者快照列表。
4. 通知执行时先检查isClosed，关闭则直接返回。像原来一样分别在两个锁块读取`Bundle(latest)`和`recipients.toList()`，不要顺手改成一套新原子事务。在锁外按列表顺序回调；每位回调收到各自的`Bundle(state)`，每位独立runCatching，前一位异常不得中断后一位。不要给该路径新增重试、日志、同步Binder发送或错误状态。

本次只转移缓存与通知所有权：publish中的快照组装字段、sequence/receivedAt、车辆仅键名合同、原厂需求、媒体、远程/哨兵、Hook与Kanzi更新顺序一字节语义不改。不要把publish整个方法交给能读写Service全部私有状态的万能host，也不新增Service API接口或依赖框架。保持getSnapshot/dump/异步onSnapshot消费同一缓存。

## 真实测试

新ServiceSnapshotsTest使用生产owner，调度边界传真实Robolectric主Handler的post/removeCallbacks；Main Looper显式idle，不另写可执行闭包列表/合并算法模型。可以记录传入Runnable身份，但记录后仍交真实Handler执行。

- 初始current为空；publish后current正确；修改一次current返回的顶层字段不污染后续读取。
- 同一Looper执行前连续发布两轮，只送最新状态和最新接收者；移除的是同一个notify，不得清掉Handler上的其他无关任务。通知投递前不执行回调。
- 多个接收者按原顺序：第一位改自己收到Bundle的顶层字段并抛异常，第二位仍收到原顶层值，缓存不变。异常隔离走生产runCatching，不在测试替身吞错。
- 已排队后closed变true时不发送；发布空接收者列表要撤掉前一轮待发通知。每个测试清理自己Handler上的任务，不启真实车辆/服务。

以上可合为少量场景，不按数量凑例。所有既有S1/P1/R0 Service/Cluster用例继续运行。新套件必须真实非空；校验新class存在。既有107项格式范围加本批2个新文件，共109项，固定ktlint1.4.1及editorconfig；新增owner/方法有说明线程、锁、拷贝和失败隔离的有效中文KDoc、显式import。AutoService其他职责的注释/拆分债仍按后续批次处理。
