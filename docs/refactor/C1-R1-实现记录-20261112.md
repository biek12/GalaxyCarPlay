## F1：导入调度真正有界（单一 pump）

`ui/BackgroundImageImport.kt`（唯一生产行为改动）：

- 原 `importImage` 虽覆盖 pending，但每次仍 `executor.execute(drain)`——默认单线程执行器队列无界，两次选择会排入两个待执行任务（Lead 独立夹具实际复现 expected 1 / actual 2）。
- 现改为一个调度 pump：同一 `lock` 保护 `pending`（容量 1 最新请求）与 `pumpScheduled`（已排入/正在运行标志）。`importImage` 只替换 pending；仅标志 false→true 时在锁外提交一次 pump，提交抛出拒绝异常则同锁复原标志并原样重抛，不留永久"已排入"假状态。
- pump 循环：锁内取走并清空最新 pending，锁外执行原 `runJob`；运行期间新请求只覆盖 pending，pump 收尾后接续最新一份；pending 空或 closed 时锁内复原标志并退出。取 pending 与标志交接同锁，避免丢唤醒。
- generation 校验、validateAndSave/原始 bytes/AtomicFile 流程、close（释放 pending、++generation、shutdownNow 自有 ExecutorService）、构造参数与回调交付合同全部不变；正在收尾或已 post 的回调由 closed/代次拦截，不触 UI/写配置/发命令。
- Presenter 与其他生产文件无行为变更（仅格式化差异，见 F2）。
