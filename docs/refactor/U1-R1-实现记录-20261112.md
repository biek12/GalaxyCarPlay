逐项映射见任务根 `METHOD_MAP.md`，验证证据见 `VALIDATION.md`，行为差异见 `CHANGES.md`。

## F1 · 同一实例的日夜刷新（P1，审计反例 2/3）

**问题**：`GalaxySettingTextLayout` 迁移时只 inflate 四个 TextView，颜色由 XML 静态给定；`GalaxyStyle.refresh` 只重执行带 palette 绑定的 View，因此已存在的设置行切夜后不变色。原实现由 `GalaxyTypography.text` 创建标签，带有颜色绑定，属迁移回退。

**修复**：

- `GalaxySettingTextLayout` 构造后给四个真实文字 View 接回 `GalaxyStyle.text`：label→`galaxy_ui_text`，value/description/feedback→`galaxy_ui_muted`。复用既有绑定表，不新建全局注册表。
- `setFeedback(error=true)` 仍由原方法覆盖反馈色绑定；覆盖后绑定即指向新颜色，refresh 不会强行还原 muted。
- `GalaxyViews.group()` 在同一个 XML 容器实例上 `GalaxyStyle.bind` 重解析 `galaxy_ui_group` 背景，不重新 inflate。
- `GalaxyModalDialog.onCreate` 给 XML 面板 root 绑定 `galaxy_ui_group` 背景，`dialogTitle`→text、`dialogMessage`→muted；`refreshPalette`/`GalaxyDialogs.refresh` 入口、已选列表项、输入内容、焦点与按钮 enabled 状态均保持原流程。

## F2 · XML 与代码共用实际文字样式（含行高）

**问题**：角色 `TextAppearance` 只有字号/颜色/字体，没有原 28sp 行高；代码仍用 `size/line/medium` 数值重建样式，形成两套有效来源。审计实测同环境 LABEL：原角色 28px、XML 行 35px。

**修复**：

- `values/dimens.xml` 新增 6 组角色度量（字号 + 行高，sp）：PageTitle 24/32、SectionTitle 18/26、Label 20/28、Value 18/26、Description 16/24、Feedback 16/24；另加 legacy 3dp 段落额外行距。
- `GalaxyUi.TextAppearance.*` 的字号/行高改引用上述 dimens，并加 `android:lineHeight`。**普通 `TextView.setTextAppearance` 不会应用段落 lineHeight**，所以代码路径在 View 层补 `setLineHeight(resources.getDimensionPixelSize(role.lineHeightRes))`，与 XML 用同一 sp 资源、同一四舍五入。不引入 MaterialTextView。
- `GalaxyTypography.Role` 增加 `textAppearanceRes` / `lineHeightRes`；`size/line/medium/secondary` 保留为明确的 legacy 元数据（`L7Typography` 等既有调用方仍读），不再作为工厂的有效样式来源。
- `GalaxyTypography.apply(size,line,medium)` 保留为确有动态参数的兼容方法；固定角色工厂不再调用它写静态值。
- `GalaxyViews.text(secondary)` 改为 inflate 新增 `galaxy_ui_legacy_text_{primary,secondary}.xml`，16/20sp、字重、颜色与 3dp 段距由 View style 表达；Kotlin 只保留日夜颜色绑定。
- `textButton` 改用新增 `galaxy_ui_text_button.xml` + 既有 `GalaxyUi.Button.Text`，删除 18/26、64dp、8/12dp 的数值覆盖。
- `iconButton`/`switch` 去掉与 `GalaxyUi.IconButton`/`GalaxyUi.Switch` 同值的 padding/min 尺寸覆盖（开关只保留 thumb/track 绑定）。
- `GalaxyStyle.button` 字号/字体改用 `setTextAppearance(Button|ButtonCompact)`；尺寸/内边距继续取 dimens；`Gravity/stateListAnimator/isAllCaps` 保留，因为程序化按钮（`L7ActionButton`）没有 XML style。
- `GalaxySettingRow` 的 orientation/gravity/padding/minHeight 迁到新样式 `GalaxyUi.SettingRow`，构造时以 `obtainStyledAttributes(attrs, ROW_ATTRS, defStyleAttr, R.style.GalaxyUi_SettingRow)` 读取；XML 与代码构造同一来源，80/96dp 仍由内容状态切换。

## F3 · 真实动态 radius（审计反例 3/3）

**问题**：`radius` 参数保留但形状固定 4dp，真实调用方 `GalaxyConfigurationTabs.category:43` 传 2dp 被静默忽略；实现记录“历史调用方只传 4dp”不成立。

**修复**：

- `GalaxyStyle.button` 每次 bind 取 `getDrawable(...)?.mutate()` 的独立副本，再把真实半径写到内容 `GradientDrawable.cornerRadius`；只影响本实例，不污染其他按钮，保留 surface tint 与宿主 decorate。
- `galaxy_ui_button_primary.xml` 由“两个 shape 的 selector”改为单一 shape，solid 引用新增 `color/galaxy_ui_button_primary_fill.xml`（disabled→`galaxy_ui_control`，其余→`galaxy_ui_accent`）；enabled/disabled 仍共享同一可调形状，状态切换不回退 4dp。
- 中文注释明确这是既有公开动态接口的运行时例外，并点名真实 2dp 调用方；不建 Drawable 遍历框架，不依赖 API 29 的 `StateListDrawable` 枚举。

## F4 · 真正有界的诊断 IO

**问题**：`DiagnosticActivity.ioExecutor` 用 `Executors.newSingleThreadExecutor`，其 `LinkedBlockingQueue` 无容量；`readLogs` 每次点击都排新任务。

**修复**：

- 默认执行器改 `ThreadPoolExecutor(1, 1, 0`ms`, ArrayBlockingQueue<Runnable>(2), 命名 daemon 工厂, AbortPolicy)`，类型仍是 `Executor`，`destroy` 走 `ExecutorService.shutdown`。
- `DiagnosticPageController` 增加 `logsPending`：提交前置位；未完成时重复点击直接返回，不重复排队；完成、读取失败、提交被拒都会复位。
- 新增本控制器内部 `submitIo`：捕获 `RejectedExecutionException` → 资源化“诊断任务正在处理中，请稍后重试”；不 CallerRuns、不静默丢弃、不把异常抛到主线程。
- 日志读取用 `runCatching` 包裹，I/O 异常转“读取运行日志失败，请稍后重试”，并复位 pending 允许重试。
- 认证导入沿用原 `runCatching` 成功/失败语义与持久化合同，只改为经 `submitIo` 提交。

## 兼容与边界

- 未改：AIDL/契约/`AutoClient`/`AutoService`/HAB/QNX/输出所有权、服务动作、权限与认证协议、扫描语义、签名/包名、依赖版本、用户默认选择。
- `Role` 的 legacy 字段与 `GalaxyTypography.apply` 保留，不删除 public API、不机械迁移调用方。
- `GalaxyStyle.button` 对任意 `Button` 仍自足（程序化按钮没有 XML style），因此保留少量非样式化静态设置，但不再写死字号/字体。
- 不新增控件/主题/DI/调度框架；`ui` 仍不反向依赖 `common`。
