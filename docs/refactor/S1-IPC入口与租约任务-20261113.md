### 调用身份

`internal class ServiceCallerIdentity`只接系统边界函数，不新建权限框架：

```kotlin
internal class ServiceCallerIdentity(
    private val callingUid: () -> Int,
    private val processUid: () -> Int,
    private val checkSignatures: (Int, Int) -> Int,
    private val packagesForUid: (Int) -> Array<String>?,
)
```

生产分别传`Binder::getCallingUid`、`Process::myUid`、`{ caller, own -> packageManager.checkSignatures(caller, own) }`、`{ uid -> packageManager.getPackagesForUid(uid) }`。后两个必须是延迟调用的lambda，不能在Service构造期取packageManager或捕获其方法引用。

`requireUid()`原样保留：读callingUid一次；自身UID直接通过，不调用签名检查；否则对原processUid检查`PackageManager.SIGNATURE_MATCH`；失败仍为`IllegalStateException("client_signature_rejected")`。不缓存结果，不改成包白名单鉴权，不把同签名第三方包直接禁用。

`source()`只生成诊断来源：保留com.ecarx.autoservice、com.ecarx.carplay、com.galaxy.autorecord、com.galaxy.autocluster，null转空，保留原数组顺序与重复，逗号拼接；未知包产生空来源。此列表不是授权条件。不能把Binder.getCallingUid移进主线程任务。

### 请求调度

`internal class ServiceRequestQueue`的构造参数固定为`main: Handler`、`isClosed: () -> Boolean`、`onFailure: (String, Throwable) -> Unit`。`enqueue(source: String, block: () -> Unit)`在原main上post，任务实际执行时检查`!isClosed()`，再`runCatching(block).onFailure { onFailure(source, it) }`。

不得在投递前用closed替代执行时检查；不得创建另一个服务停止状态、缓存UID、清空main所有任务、同步执行block或启动新worker。onFailure原顺序仍为：DiagnosticEvents.error("binder_request", error, mapOf("caller" to source)) → ServiceTrace.event("binder_request", error) → state("request:${error.javaClass.simpleName}")。保持原异常传播边界，不包第二层吞错。该回调在AutoService装配处按原语句提供。

AutoService只新增上述对象装配/import，并让原`uid()`/`enqueue()`成为单行委托；保留所有原调用点、return@enqueue及同步检查的位置。所有现有身份/role检查仍在原Binder方法，不把attach、FD接收、车辆feed、Shell/Root、媒体、Hook或快照搬入IPC调度类。既有直接main.post路径本批保持，不机械改走enqueue。

### 客户端租约

迁入ipc.ClientRegistry必须保留：最多16个租约、owner唯一、非OBSERVER角色唯一、uid固定、同一Lease对象的active/feed/interval/lastFeedAt/elements；linkToDeath在登记前，死亡回调中依然投递main并校验当前death实例。AutoService传入的`{ owner -> main.post { detach(owner) } }`也原样保留，不擅自合并两次投递。remove的unlink、close幂等、retainFeeds保意图/换车型滤键及清零节拍不变。

AutoService.detach和onDestroy次序不动；不改变THEME/PREVIEW归档回调、不恢复输出、不使MAP接管整屏。ClientRegistry的历史注释可去掉已归档类作为当前调用者的错误示例，但不能因此删业务。
