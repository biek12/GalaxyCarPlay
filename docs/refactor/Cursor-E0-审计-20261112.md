## 阻断与修正

### R1-01：Service 宿主工具未适配 Windows

`galaxy/service/src/test/java/com/ecarx/autoservice/platform/PlatformExecutionTest.kt:50–58` 的三次 ShellExecutor 调用写死 `/bin/sh`，cksum 也只按裸命令查找。Lead 实际执行中出现：

- `shellKeepsExitCodeBoundsOutputAndTerminatesAtDeadline`：`Cannot run program "/bin/sh": CreateProcess error=2`。
- `posixChecksumMatchesSystemToolAndIncludesFileLength`：`Cannot run program "cksum": CreateProcess error=2`。

这是宿主测试边界未准备齐，不是 QNX 或 Android Shell 业务失败。生产 `ShellExecutor.execute` 已有可注入的 shell 参数，使用它即可适配；不能改生产默认 `/system/bin/sh`，也不能跳过 Windows 用例或换成自写 checksum。

### R1-02：Windows 入口复制了整套验证流程

`scripts/verify_projection_retirement_windows.ps1:139–259` 重新维护下游 Gradle 任务、Service/Cluster suite、`$U1Check` 与 `$C1Check` 两大段报告逻辑，和已有三个 Shell 入口重复。原 E0 明确要求 Windows runner 共用原逻辑。不能继续让平台移动时同时改两套 suite/报告实现；修正为薄入口，传环境和参数后调用原 Shell 链。

### R1-03：实际 UTF-8 日志被错误解码

Windows runner 第 40–41 行使用 `Encoding.Default` 读子进程，而同一 runner 又设置 `PYTHONIOENCODING=utf-8`。交付的 `logs/format.log` 实际已出现 `鏍煎紡…` 等乱码，找不到正确的“格式门槛通过”。UTF-8 文本流要按 UTF-8 处理，或原字节保留；不能依靠 `errors=replace` 掩盖。修正薄入口时一并消除这层错误转码，并实际检查日志中文。
