# Cluster 可视化主题编辑器实施方案与实现

日期：2026-10-30。用户已确认总体目标、17类组件方向和Flyme视觉结构；随后要求组件细化、组件库三列只预览、组件专属属性，并继续授权完成全套实现及上车前准备。现已落实运行代码；构建、离线逻辑/原生Canvas与实车验收分开记录。

## 产品目标与已实现行为

AutoCluster独立拥有主题与制作界面：从星枢GT与多行歌词、双表GT、简境、霓序、胎压/踏板兼容模板或空白主题开始，拖拽/缩放/精确坐标、对齐、图层顺序、复制/删除、多选组合/解组、锁定和撤销/重做。三个Tab为“我的主题 / 编辑主题 / 组件库”，中控保持竖屏；宽屏画布下方为按组件分节的属性面板。旧Flyme网页未在本机找到，视觉沿已核对旧GalaxyPlay原生Flyme的细圆角、蓝强调、日夜表面与文字层次，用户已认可方向。

“组件库”固定每行三个真实组件样式预览，24类各3个，共72个，可打开详情看日夜/重播；浏览不会改变主题。添加只在编辑器“添加组件”内。指针表盘借鉴用户指定GT的功能结构自写；歌词等每类都有各自字体/排版/动画/数据设置，详见[完整组件细化与GT对标](Cluster组件属性与GT对标-20261030.md)。图片与字体通过本地文件选择进入包内，不加载远程主题脚本。

主题支持保存、继续修改、另存副本、重命名、删除、导入/导出和切换；背景纯色/渐变/本地图片。日夜可独立或共享，组件视觉属性可覆盖并恢复继承；数据绑定不随日夜改变。内置模板不可覆盖，首次保存产生自定义身份；自定义revision检测并原子保存，活动快照独立于草稿，“保存”不改变仪表，“应用”才替换。后台主题服务从已应用快照恢复，退出编辑不停止仪表。

完整CarPlay111地图仍由CarPlay硬解至Surface，AutoService复用OES纹理。Cluster场景决定地图位置/尺寸与透明孔，完整等比适配；保留源中的车道/限速/到达等内容，TBT只是辅助组件。草稿预览租约与正式输出独立，打开/关闭编辑不重启手机地图或HAB；演示数据只存在本机预览，不发布成真实车辆数据。

## 帧率与资源

默认输出/组件动画上限30，支持1–60热设置与按内容刷新；上限是配置，不承诺目标物理帧率。统一截止时间按地图到帧、字段变化/过期、动画与歌词/进度/时钟边界唤醒；旧100ms采集与主题轮询限制已删除。静态盘面Picture、字体/图片/布局与数值颜色解析缓存，资源准备在IO线程完成；有界最新状态不排旧帧。

最终仍经ImageReader读回、Java最新帧邮箱、隔离pipe、native RGBA→BGRA、HAB共享槽位、QNX Screen buffer复制，不能称为零拷贝。双方协商自有GLC2消费确认后省去QNX scratch；POSTED表示复制与Screen post返回成功，随后发送端才复用共享槽位。超时/坏确认结束本代发送且不覆写；已有有限重连与按需接收端启动继续保留。旧诊断v1研究链保留，正式新sender要求新receiver，二者须整套更新。

地图/主题/草稿纹理由一个EGL线程持有，按角色/token匹配新场景Surface；正式主题第一帧就绪才换活动场景与几何。退出释放自有引用、EGL/纹理、窗口/import，不修改原车窗口顺序、HMI或启动项。原车提示“仪表图传异常，请联系服务站”根因未明，性能重构不等于告警已修复；详见[告警原厂静态证据与取证顺序](投屏帧优化与原车告警-20261030.md)。
