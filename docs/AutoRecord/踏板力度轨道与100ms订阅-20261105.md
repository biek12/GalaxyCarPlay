# 踏板力度轨道与100ms订阅（2026-11-05）

用户要求参考 IMG_0659：油门/刹车用颜色表达力度，持续踩踏为区间，连续短踩不可被合并过滤，点击行首展开力度曲线；各字段和视频共用时间轴。随后明确要求修改 AutoService 的频率代码，之后对比性能开销。此前“暂不重新安装 AutoService”继续有效，本轮只准备源码、编译产物和后续测试入口，不连接或更新车机，不恢复本地模拟器测试。

## 已实施口径

### 原始动作与阈值事件分开

- `VehicleHistoryTracks` 从真实 `vehicles.jsonl` 样本生成原始轨道；刹车/油门只要存在有效的正百分比就保留，不套用20%/5%阈值、200ms去抖、300ms最短时长或1秒合并规则。
- 已观察到的抬起（0）会立即分开两次踩踏；缺失值和大于两倍采样周期加25ms的间隙会断开，不将未知区间画成持续踩踏。仅一个有效样本的短踩至少显示一个物理像素，但命中和时间仍使用真实毫秒，不人为放大持续时长。
- 原始踏板/灯光区间用于浏览，不把所有普通短踩和开灯都自动变成锁定事件；旧阈值事件文件保留原义，回放踏板轨道使用原始样本替代过滤后的条带。
- 没有收到的短于采样周期的动作无法恢复。100ms是目标请求周期，不是已证明的车机真实采集/端到端时延上限；若上游不推送足够快，重复读取缓存不能增加真实精度。

### 颜色、曲线及字段对齐

- 刹车红色系、油门绿色系，同一条内按每个有效样本的百分比改变深浅，轻踩浅、重踩深，不仅保存峰值。
- 点击油门/刹车行首箭头展开0–100%阶梯曲线。曲线保留实际观测的力度升降与零值，不通过平滑插值虚构中间读数；未知或超时区间不连线。
- 每个灯光、转向、里程、续航等字段有独立行，绘制及触摸共用同一份行布局，避免展开后标签和命中位置错位；所有行、曲线、游标统一段相对毫秒横轴。
- 时间轴置于固定高度的可滚动区域，避免多个轨道及展开曲线挤掉视频；只绘制可见行，力度数值在解析后缓存，避免每帧重复解析字符串。
- 明细时间显示到毫秒；数据条按各字段源时间读取历史样本，不使用当前车辆实时值。
- 已知本车历史上出现4339/4608等超出0–100的踏板原始值。未核验编码前不除256或猜比例，不把这些值当百分比，也不按重踩着色；点选时标明原始读数量纲未核验。

### 逐包记录与时间质量

- 录制侧 AutoClient 的车辆数据回调切到自有IO线程，界面客户端保持原线程语义；避免主线程建UI时积压数据回调。
- 录制租约保留逐包不可变快照，队列上限512包；写线程约每50ms检查并排空收到的更新，不再按250ms二次采样“当时最新值”而漏掉已收到的中间动作。溢出具名报错，不静默丢历史。
- 每条侧录保留原字段 `t`/`v`，增加 `a`（各字段相对于段起点的AutoService接收时间）、`q`（有效/缺失/过期状态）、`intervalMs`（实际协商周期）。厂商原始时钟域未核验时不冒充传感器物理动作时间。
- 回看优先采用各字段的 `a` 时间，旧录像无 `a` 时兼容原 `t`。这只能提高已有记录的准确映射，不能为旧250ms录像补出100ms样本。

## AutoService频率代码

- 契约最小允许周期由250ms改为100ms，默认周期仍为250ms；这是放宽合法输入范围，不改变v4的Binder方法、键名或旧客户端语义。
- 只读取被订阅且到期的键，未订阅不读取；按最近字段的到期时间调度。100ms、250ms和1000ms混用时，250ms键不会因为固定100ms步进而被拖成300ms。
- 原全目录诊断扫描仍默认关闭；显式打开时仍按250ms推进，不跟随高频订阅扩大为100ms全目录扫描。
- 快照增加 `minVehicleFeedIntervalMs`。AutoRecord请求100ms时按服务广告协商；旧服务未提供该字段视为已知旧下限250ms，并显示实际协商周期，不发送旧服务会拒绝的100ms请求。
- AutoRecord提供100ms选项，新默认请求100ms；已有用户明确保存的设置保留，后续现场需确认选中100ms。仍由AutoService实际执行读取，AutoRecord不自行直连厂商或另建Root采集路线。
- 新增采集累计耗时和超周期次数，供前后对比。调度仍单线程串行；100ms不能压缩真实的厂商IPC耗时，超周期会如实计数。
