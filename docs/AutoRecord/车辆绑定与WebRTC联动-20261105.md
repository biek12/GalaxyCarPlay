# 公共车辆绑定与网页联动（2026-11-05）

## 用户确认

AutoService 与 AutoRecord 共用车辆绑定码和二维码；网页支持扫码添加。车辆基本信息保存到自有服务器。账号归属长期有效，直到主动解绑；临时码有效期与归属有效期分开。界面沿 FlymeAuto 日夜设置卡片、文字角色和触控尺度。

用户随后明确否决 JPEG 在线预览；本次撤掉曾临时编写的 JPEG 传输，实时观看采用四路硬件 H.264 / WebRTC，不交付逐张图片轮询。录像和车辆数据原有能力不因在线功能删减。车辆安装沿既有授权的 AutoService ROOT 通道，同签名保留数据；不操作锁车、电源、原厂 HMI 或启动项，不启动模拟器。

## 归属与交互

- 两 App 的“车辆与账号”入口使用 `auto-client` 中同一个原生 Activity；设备身份、凭据、网络和归属缓存仅由 AutoService 持有。
- 申请后显示 5 分钟、一次性的绑定码和二维码。两 App 共用尚未过期的码；明确重新申请才使旧码失效。二维码为自有网页链接，材料放 URL fragment；网页识别后清理地址栏，未登录时经登录续接。
- 网页可使用手机系统相机直接打开二维码链接，也可在绑定弹窗启用相机扫描或识别二维码图片；仅接受本站绑定链接和合法码，不导航到任意扫描网址。
- 网页提交后，车端显示目标账号的名称和脱敏手机号；明确确认后才建立 owner。拒绝、过期和重放均由后端真实拒绝。
- 绑定不依赖 12/24 小时的远程调试窗口，不随网页 Cookie、临时码、App 或服务器重启过期。车端和网页均可主动解绑；网页解绑仍需近期二次认证。解绑撤销观看者、流会话和未完成作业。
- 暂停在线服务和关闭 AutoService 自动运行都停止在线工作，但保留归属。恢复后继续使用原设备身份和归属。

基本信息明确标注来源。当前发送适配配置车型、设备厂商/型号、Android/API 与 AutoService 版本；不猜测 VIN、车牌、年款或配置。后端只保存允许的基础字段，文字单项最多128字节。

## 业务链路

1. AutoService 独立向 `/device/v1/register` 登记设备 Web 身份。初次使用已有私有登记材料；不为了登记 Web 身份新开诊断窗口。
2. `/snapshot` 发布实际状态和基础信息；`/binding-state` 回读归属，`/binding-codes` 签发临时码，`/poll` 获取待确认账号与业务作业，`/binding-confirmations` 完成确认，`/unbind` 从车端取消绑定。
3. AutoRecord 的签名保护在线服务通过 AutoService 的追加式 Binder 接口提交允许的业务消息和只读媒体 FD。浏览器不能发送 Shell，AutoRecord 不取得服务器长期凭据。
4. 录像目录由后台线程扫描、按新段完成/目录变化增量触发发布；没有变化时最多每分钟核对，不阻塞录制 writer 或主线程。索引用 FD 提交，避开 Binder 大包；服务端现有上限4096段。
5. 用户打开历史片段后创建 `clip-prepare` 作业：按真实租约读取可用 MP4，传输选中片段与车辆侧录，再由网页 Cookie 鉴权与 Range 播放。不是绑定即上传整个录像库。现有单路256MiB/服务端8GiB上限保留。
6. 网页删除经车端原有 `SegmentAccess` 执行；锁定、写入和在用片段被拒绝，按片段回执。哨兵意图经 revision 与有效期校验，回读实际状态后才能报告成功；真实锁车/深睡唤醒仍未验收。
7. 实时观看采用 Camera2 PRIVATE → 公共 OES/GPU 分发 → WebRTC SurfaceTextureHelper → 硬件 H.264 → DTLS/SRTP → 浏览器四路 MediaStream。目标1280×800、15fps、每路1.2Mbps码率上限是配置，不是性能实测。编码器只允许硬件 H.264，不自动换成 JPEG 或软件编码。
8. 鱼眼/广角平面在 GPU 输出端选择；不同观看会话通过自己的 sender 选择对应 track，不替换本地页面、转向窗或录像 Surface。无观看者后释放 WebRTC、GPU输出和编码资源；轮询丢失8秒撤销观看租约。
9. 自有 coturn 使用每观看会话短期 HMAC 凭据；静态密钥只在服务器私有目录。TURN 不使用公共第三方中继；服务端未配置中继会明确拒绝建立观看会话。

### 真实绑定与直播故障

用户提交绑定请求后，进一步明确授权Agent在车端点击确认。已核对待确认账号177****0247，并通过真实车端按钮完成，服务器Bindings=confirmed、owner已建立。服务器随后收到275段真实录像索引（数量随循环覆盖变化），不再是空车辆/空索引演示。

用户手机打开实时后反馈“画面尚未接入”。服务器收到offer/ICE却无answer。实车crash缓冲给出明确JNI根因：`ClassNotFoundException: org.jni_zero.JniZero`，发生于libjingle原生加载。Field的R8仅保留org.webrtc不足；已追加org.jni_zero全包的JNI边界保留，并在单命令验证中加入APK DEX固定类名与arm64原生库检查。修正前直播初始化导致AutoRecord进程崩溃，自动恢复重新开始四路录制，不能称这段全程无中断。最终修正版本安装和直播结果另追加。

补充R8事实：M150 AAR另缺少可选`setJniClassLoader`生成桥`org.jni_zero.JniZeroJni`；本App不调用该方法，按R8生成的精确规则仅对该类忽略warning，仍完整保留JNI_ZERO实际native回调类，未放宽其他missing检查。

JNI_ZERO保留修复已实际同签名安装，摘要`d596a9be92f564fdd725a7bcb9bd387b079cd1731c86635dc413dae8c8180dd8`；APK DEX中JniZero/CommonApis/PeerConnectionFactory名称与arm64库检查通过。


观看会话回收修复：同一登录Cookie重新进入实时页时替换该Cookie之前的会话；不驱逐其他合法登录会话，并发上限仍为2。网页pagehide/离开路由尽力发送带Cookie/CSRF的DELETE。Go race回归覆盖同登录刷新释放与不同会话保留，已通过并部署。45秒观看租约与在线新鲜度一致，避免串行HTTPS回执耗时超过早期8秒常量时反复重建PeerConnection。
