### 1.2 `onSurface` / `role` 为什么不能当摄像头通道

| 冲突点 | 现状 | 摄像头需要的 |
| --- | --- | --- |
| 方向 | **服务端是生产端**：compositor 自建 `SurfaceTexture` 的 Surface，把 `role@token` 交给客户端消费（[`GalaxyGlComposition.kt:71`](../../galaxy/service/src/main/java/com/ecarx/autoservice/projection/GalaxyGlComposition.kt#L71)、[`:126-127`](../../galaxy/service/src/main/java/com/ecarx/autoservice/projection/GalaxyGlComposition.kt#L126-L127)、[`:182`](../../galaxy/service/src/main/java/com/ecarx/autoservice/projection/GalaxyGlComposition.kt#L182)） | 客户端（AutoRecord）建编码器输入 Surface，**服务端往里写帧**；只有 `setPreviewSurface` 是反方向，且仅限 `PREVIEW`（[`AutoService.kt:230-246`](../../galaxy/service/src/main/java/com/ecarx/autoservice/AutoService.kt#L230-L246)） |
| 角色集合 | 闭集 4 项：`carplay`/`cluster`/`observer`/`cluster-preview` | 需要 4 个方向 × 2 用途（预览/录制）＝8 条输出流 |
| 角色与包名绑定 | `MAP`→`com.ecarx.carplay`；`THEME`/`PREVIEW`→`com.galaxy.autocluster` | 摄像头消费者是 `com.galaxy.autorecord`，现有分支直接 `check` 失败 |
| 单角色独占 | 同 role 只能一个 owner（[`ClientRegistry.kt:21-23`](../../galaxy/service/src/main/java/com/ecarx/autoservice/ClientRegistry.kt#L21-L23)） | 预览与录制要同时存在；且需按方向复用 |
| 数量上限 | 客户端总数 < 16 | 若为每方向/每用途建租约，容易触顶 |
| 语义 | `onSurface(kind, surface)` 表达"某角色画面流已就绪"，无帧、无时间、无序号（[`IAutoCallback.aidl:5-10`](../../galaxy/contracts/src/main/aidl/com/galaxy/auto/contract/IAutoCallback.aidl#L5-L10)） | 录制必须逐帧给方向/序号/相机时间戳/时钟域 |

**判定：把摄像头硬塞进 role/`onSurface` 会同时改语义、改绑定、改并发模型，属于"反向解释既有接口"（AGENTS.md 禁止）。必须新增契约。**

## 2. AutoService 需要新增的摄像头域

### 2.1 五个能力块

| 块 | 必须表达 | 不得含糊的地方 |
| --- | --- | --- |
| **能力查询** | 车型/固件标识、每方向 → 实际 `cameraId`、原生尺寸与对齐值、可用 fps 区间、输出像素格式、旋转/镜像、**并发上限**、访问身份（app/root）、当前可用状态与原因 | cameraId 必须逐车探测，不照抄参考实现的 `前[2]/后[3]/左[0]/右[1]` 枚举位置（[需求稿 §8](需求与DeepSeek交接-20261103.md)，上游 GPL 参考仅作位置对照） |
| **会话租约** | `owner`(IBinder)、`sessionId`、`generation`、用途（预览\|录制）、申请/释放、死亡回收、服务重启使旧代失效 | 释放必须幂等；旧 sessionId 的任何迟到调用一律拒（`ERR_STALE_GENERATION`） |
| **图形输出** | 每方向一条独立的客户端 Surface 绑定；服务持有借用引用，停止/死亡时释放；同一 Surface 绝不交给两个生产者 | 禁止把四方向复用到同一 Surface 分时写 |
| **帧元数据** | 方向、`frameSeq`、`cameraTimestampNs`、`clockDomain`（camera/monotonic）、映射后 `monotonicNs`、`firstFrame`、实际尺寸、`droppedSinceLast`、`queueDepth`、`sessionGeneration` | 元数据必须能**与实际输出帧一一配对**，不允许只发"最新状态" |
| **有界队列与状态** | 每方向有界邮箱（深度 2–3，与现有 HAB 三份邮箱同量级，[`GalaxyHabComposition.kt:67`](../../galaxy/service/src/main/java/com/ecarx/autoservice/projection/GalaxyHabComposition.kt#L67)）；丢帧只丢最旧并计数 | 队列溢出必须上报，不得静默丢 |

### 2.2 状态机（每条迁移带 `reason` 与 `since`）

`IDLE → REQUESTED → (WAITING_AUTH | WAITING_OEM) → FIRST_FRAME → ACTIVE → (DEGRADED | RECONNECTING) → STOPPED`

| 状态 | 触发 | 上报内容 |
| --- | --- | --- |
| `WAITING_AUTH` | CAMERA 权限/厂商授权不足 | 缺哪一项、可自查的 appops/permission 结果 |
| `WAITING_OEM` | 原厂环视/倒车占用 | 占用人（若可观测）、已等待时长、重试还剩几次 |
| `FIRST_FRAME` | 会话已开、首帧未到 | 已等毫秒、是否需要重新配置 |
| `ACTIVE` | 持续出帧 | 实际 fps、帧序号、队列深度 |
| `DEGRADED` | 掉帧/超时 | 缺口区间起点、丢失估计及依据 |
| `RECONNECTING` | 设备断开（`onDisconnected`/`onError`） | 原因码、第几次、下次时刻 |
| `STOPPED` | 主动停止/用户关闭 AutoService 摄像头开关 | 正常停止 vs 异常停止 |

**为什么不能写进 `AutoService.kt` 主类**：该文件已 614 行，同时承担 Binder 鉴权、租约、车辆订阅节拍、投屏合成调用、远程桥、诊断 dump（[`AutoService.kt:96-102`](../../galaxy/service/src/main/java/com/ecarx/autoservice/AutoService.kt#L96-L102)、[`:258-273`](../../galaxy/service/src/main/java/com/ecarx/autoservice/AutoService.kt#L258-L273)、[`:426-458`](../../galaxy/service/src/main/java/com/ecarx/autoservice/AutoService.kt#L426-L458)）。摄像头的生命周期完全独立（设备会话 / 图形输出 / 元数据三条线程），塞进主类会：① 让相机打开、会话重建阻塞主线程，连带拖慢 250ms 车辆节拍与投屏；② 与既有 `detach`/`onDestroy` 的释放顺序纠缠不清（[`AutoService.kt:459-474`](../../galaxy/service/src/main/java/com/ecarx/autoservice/AutoService.kt#L459-L474)、[`:594-607`](../../galaxy/service/src/main/java/com/ecarx/autoservice/AutoService.kt#L594-L607)）。建议拆 `CameraCapabilities`/`CameraSession`/`CameraOutput`/`CameraMeta` 四个类，`AutoService` 只做 binder 入口 + 全局开关，线程纪律沿用 `SerialWorker`（[`SerialWorker.kt:7-29`](../../galaxy/service/src/main/java/com/ecarx/autoservice/SerialWorker.kt#L7-L29)）与 HAB 的 capture/compose 分离（[`GalaxyHabComposition.kt:31-38`](../../galaxy/service/src/main/java/com/ecarx/autoservice/projection/GalaxyHabComposition.kt#L31-L38)）。

## 3. 权限与身份（只给事实与核验项，不作断言）

### 3.1 【源码存在】

- 服务清单**没有** CAMERA 权限：现有权限只有 INTERNET / BOOT_COMPLETED / ACCESS_NETWORK_STATE / WRITE_SECURE_SETTINGS / READ_LOGS / FOREGROUND_SERVICE / FGS_CONNECTED_DEVICE / CHANGE_NETWORK_STATE（[`service/AndroidManifest.xml:2-13`](../../galaxy/service/src/main/AndroidManifest.xml#L2-L13)）。
- 前台服务类型**只有** `connectedDevice`（[`service/AndroidManifest.xml:22`](../../galaxy/service/src/main/AndroidManifest.xml#L22)），`startForeground` 也不带类型参数（[`AutoService.kt:331`](../../galaxy/service/src/main/java/com/ecarx/autoservice/AutoService.kt#L331)）。
- 身份校验是**同签名**：`Binder.getCallingUid()` 必须等于本进程 UID 或 `checkSignatures` 匹配（[`AutoService.kt:96-102`](../../galaxy/service/src/main/java/com/ecarx/autoservice/AutoService.kt#L96-L102)），服务另加签名级 `CLIENT` 权限（[`service/AndroidManifest.xml:7`](../../galaxy/service/src/main/AndroidManifest.xml#L7)、[`:22`](../../galaxy/service/src/main/AndroidManifest.xml#L22)）。
- **AutoRecord 当前接不上**：`record` 清单没有 `CLIENT` 权限、也没有 `<queries>`（[`record/AndroidManifest.xml:1-11`](../../galaxy/record/src/main/AndroidManifest.xml#L1-L11)），对照 CarPlay 侧的正确写法（[`client/AndroidManifest.xml:2-3`](../../galaxy/client/src/main/AndroidManifest.xml#L2-L3)）——这是阶段 B 的第一道门。
- 厂商能力现状是**反射**取得，不是编译期 SDK：`ecarxcar_service` → `ecarx.car.IECarXCar` → `car_signal`（[`EcarxVehicleSource.kt:74-89`](../../galaxy/service/src/main/java/com/ecarx/autoservice/vehicle/EcarxVehicleSource.kt#L74-L89)）；`android.car`/`ecarx.car`/`ecarx.adaptapi` 在清单里均为 `required="false"`（[`service/AndroidManifest.xml:16-18`](../../galaxy/service/src/main/AndroidManifest.xml#L16-L18)）。摄像头顶层服务名**未在源码出现**。
- 自授权通道已存在但范围很窄：`AppPermissionSetup` 只补 WRITE_SECURE_SETTINGS / READ_LOGS（[`AppPermissionSetup.kt:18-22`](../../galaxy/service/src/main/java/com/ecarx/autoservice/platform/AppPermissionSetup.kt#L18-L22)），走自有 RootService 执行 `pm grant`。CAMERA 若需 runtime 授权，可复用此通道（**通道存在 ≠ CAMERA 已授权**）。
- 工作身份：应用自身 UID 由 `Process.myUid()` 决定（[`RootOwner.kt:18`](../../galaxy/service/src/main/java/com/ecarx/autoservice/platform/RootOwner.kt#L18)）；需要更高身份时一律走自有 RootService/ADB 通道执行（模式见 [`AppPermissionSetup.kt:15-17`](../../galaxy/service/src/main/java/com/ecarx/autoservice/platform/AppPermissionSetup.kt#L15-L17)）。

### 3.2 【平台文档，车机未核验】

- `android.permission.CAMERA` 是运行时危险权限；目标机 Android 11 上后台访问相机与前台服务类型相关，`camera` 类型自 API 29 引入，Android 14（API 34）起另需 `FOREGROUND_SERVICE_CAMERA`。本工程四个应用 `targetSdk = 37`（[`service/build.gradle.kts:24`](../../galaxy/service/build.gradle.kts#L24)、[`record/build.gradle.kts:8`](../../galaxy/record/build.gradle.kts#L8)），与设备 Android 11 的组合下具体的 FGS 类型/权限判定**必须实机确认**。参考：<https://developer.android.com/develop/background-work/services/fgs/service-types>、<https://developer.android.com/reference/android/hardware/camera2/CameraManager>。
- `CameraDevice.StateCallback` 区分 `ERROR_CAMERA_IN_USE`（设备被他人占用）、`ERROR_MAX_CAMERAS_IN_USE`、`ERROR_CAMERA_DISABLED`（策略/权限禁用）与 `onDisconnected`，这是"原厂占用"唯一可靠的**源码级**观测面。

### 3.3 【待车机核验】（本文不断言）

1. L6 普通 app UID 能否 `getCameraIdList()` 看到四路，还是只有厂商服务/系统 UID 可见。
2. 是否需要厂商权限或服务（若存在，命名与授权方式未知）。
3. 是否需要 uid 0 / shell：目前所有 SHELL 动作都走自有 RootService/ADB，但摄像头是否必须走这条路**没有证据**。
4. 前台服务类型是否必须加 `camera`，以及被拒时系统行为（静默失败 / 抛异常 / 回调 error）。
5. 原厂环视/倒车是否持有相机独占。
6. `sensorTimestamp` 是否真在 `CLOCK_MONOTONIC` 域（见 §5）。

## 4. 原厂环视/倒车共存

**证据现状：本仓库对环视/倒车零代码零文档结论**（§1 grep 全空），因此本节只能给出"必须遵守的协作纪律 + 可观测信号 + 未证项"，不能给出已实现的共存方案。

| 纪律 | 依据 |
| --- | --- |
| 不杀原厂进程 | 现有代码只管理自有 helper/接收端，不 kill 非本包进程（AGENTS.md 安全与交接节） |
| 不强关环视、不调系统"关闭环视"接口 | 同上；无任何相关调用可依 |
| 不进原车 HMI、不改启动项 | AGENTS.md 当前执行边界 |
| 相机被取走时不循环抢开 | 竞态重开会放大占用与失败率；按断开→等待→有限次重连 |

可观测信号（按可信度排序）：

| 信号 | 可信度 | 用途 |
| --- | --- | --- |
| `onDisconnected` / `onError(ERROR_CAMERA_IN_USE)` | 【平台文档】可靠 | 判"被他人占用"，进入 `WAITING_OEM` |
| 挡位 `gear == R`（车辆目录已有该键） | 【源码存在】但只是**提示** | 倒车临近的前置降级，不作控制依据，也不代表环视已启动 |
| 原厂环视进程/Activity 存在性 | 【待核验】 | 若可读，仅作诊断展示，不作自动决策 |
| 系统相机服务策略广播 | 【待核验】 | 未知是否存在 |

未证项：原厂进入/退出环视时是否真的释放并回收 camera、释放延迟多久、是否给出任何通知、本车是否存在"摄像头上层服务"隔离四路。这些**必须实测**（§8 第 6 项）。

## 5. 时间戳方案

| 环节 | 方案 | 证据/缺口 |
| --- | --- | --- |
| 相机时间戳 | 取 `CaptureResult.SENSOR_TIMESTAMP`（ns） | 【平台文档】；域是否等于 `SystemClock.elapsedRealtimeNanos()` **待核验** |
| 映射到统一单调时钟 | 会话开始记锚点 `{monotonicNs, wallClockMs, timezone, sessionId}`，每方向算 `offset = monotonicNs_at_first_frame - sensorTimestamp`，并逐帧记 `jitter`（`mapped - raw - offset`） | 锚点字段与[技术口径 §5](编码与存储技术口径-20261103.md#L194)已定义，可复用；offset/jitter 为本文新增 |
| 元数据双写 | 同时下发 `cameraTimestampNs`（原始）+ `monotonicNs`（映射后）+ `clockDomain` 枚举 | 客户端不得自行推断时钟域 |
| Surface 编码 PTS | 生产端在每次 `eglSwapBuffers` **之前**调 `EGLExt.eglPresentationTimeANDROID(display, eglSurface, frameTimeNanos)`，值取自**同一帧**的映射时间 | 本仓库**零调用**（§1）；现有 EGL 封装只有翻页无时间戳（[`GalaxyEglContext.kt:31-41`](../../galaxy/service/src/main/java/com/ecarx/autoservice/projection/GalaxyEglContext.kt#L31-L41)），当前 HAB 投屏的 PTS 事实上是 swap 时刻——**这是既有行为，本轮不改，但绝不能作为录制的时间来源** |
| 一帧多 Surface（预览 + 编码） | 同一帧在两个 EGL 输出上必须写**相同** presentation time，来源是同一条 frame meta | 否则预览与录像 PTS 分叉 |
| AutoRecord 侧红线 | 禁止用"收到帧的时刻"顶替，禁止 `帧序号 × 固定时长` | [规格 §6.1-5](页面功能与设置规格-20261103.md#L315)、[技术口径 §5](编码与存储技术口径-20261103.md#L192) |
| 车辆侧 | 复用 `VehicleSignal` 的 `receivedAt/sourceTimestamp/epoch/maxAgeMillis`（[`VehicleSignal.kt:8-29`](../../galaxy/contracts/src/main/java/com/galaxy/auto/contract/VehicleSignal.kt#L8-L29)），与视频共用同一会话时间轴 | 已存在 |

补充约束：首帧时间差**不得归零**；四路 `offset` 各自独立；服务重启＝新 `clockEpoch`，新旧 epoch 不拼接。

## 6. 契约草案（形状，不锁死命名）

### 6.1 新增接口形状

```aidl
// 独立接口文件：IAutoCamera.aidl / IAutoCameraCallback.aidl（形状草案，命名待评审）
oneway interface IAutoCameraCallback {
    void onFrameMeta(in Bundle meta);    // 方向/frameSeq/cameraTsNs/monotonicNs/clockDomain/firstFrame/dropped/sessionGeneration
    void onCameraState(in Bundle state); // sessionId/generation/direction/state/reason/since/actualFps
}
interface IAutoCamera {
    int getCameraProtocolVersion();                    // 独立版本号，v1 起
    Bundle getCameraCapabilities();                     // §2.1 能力块全量
    Bundle acquireSession(IBinder owner, String purpose, in String[] directions, in Bundle options);
                                                        // → {sessionId, generation, errorCode, cameraIds, nativeSize}
    void bindSurface(IBinder owner, String sessionId, String direction, in Surface surface);
    void releaseSession(IBinder owner, String sessionId);          // 幂等
    Bundle getSessionStatus(IBinder owner, String sessionId);      // 诊断/轮询兜底
    void registerCallback(IBinder owner, IAutoCameraCallback callback);
}
```

错误码（`errorCode`，整数枚举，文本由客户端本地化）：`OK / ERR_UNSUPPORTED_MODEL / ERR_PERMISSION_DENIED / ERR_OCCUPIED_BY_OEM / ERR_NO_SUCH_DIRECTION / ERR_SESSION_LIMIT / ERR_CONCURRENCY_LIMIT / ERR_SURFACE_INVALID / ERR_STALE_GENERATION / ERR_DISABLED_BY_USER / ERR_SERVICE_STOPPING / ERR_INTERNAL`。

元数据配对规则：`onFrameMeta` 与写入 Surface 的帧严格同序，`sessionGeneration` 不符的一律丢弃；每方向队列深度 ≤3，溢出只丢最旧并递增 `dropped`。

### 6.2 新增接口 vs 升公共 VERSION：影响面与推荐

| 路线 | 做法 | 对现有消费者的影响 | 评价 |
| --- | --- | --- | --- |
| **A（推荐）** 独立接口 + 独立绑定入口 | 新建 `IAutoCamera`，`AutoService.onBind` 按 `intent.action` 返回第二个 Binder（现有实现只认一个 action，[`AutoService.kt:423`](../../galaxy/service/src/main/java/com/ecarx/autoservice/AutoService.kt#L423)）；`AutoContract.VERSION` 保持 4，摄像头自有 `VERSION=1` | **CarPlay / AutoCluster / 已装 AutoService 全部零改动**；只需给 `<service>` 加一个 intent-filter 与（可选）一个专用 permission | 与 v4 的"新增可忽略"纪律一致（[`AutoContract.kt:5`](../../galaxy/contracts/src/main/java/com/galaxy/auto/contract/AutoContract.kt#L5)）；摄像头与投屏/车辆无共享语义，无需捆绑版本 |
| B 在 `IAutoService` 末尾追加 `getCameraBinder()` | 只允许**追加**，禁止插入/改签名（AIDL transaction code 按声明顺序，插入会错位） | 旧 APK 不受影响；但新客户端对旧服务端调用会得到未知事务异常，需把"服务端不支持"当正常分支处理 | 可行，但把两套生命周期塞进同一接口，且 AutoClient 需新增容错分支 |
| C `VERSION` 升 5 | 全量重编 | **立刻打断**：`AutoClient.kt:84` 严格相等 → 已装 CarPlay/Cluster 全部 `protocol_version_mismatch`，必须四包同批更新（[`决策记录.md:256`](../决策记录.md#L256)） | 仅当**改变既有方法语义**时才做；本轮无此需求，不推荐 |

**推荐 A**，理由三条：① 摄像头是纯增量能力，不动任何既有方法语义，按仓库自己的升级纪律不构成 v5；② v4 破坏性升级的代价是三包强同步，本次没有需要付这个代价的语义变更；③ 独立接口天然把"摄像头不可用/被原厂占用"的失败面隔在子系统内，不会让投屏/车辆消费者承担摄像头故障。**唯一强制纪律**：若将来采用 B，只许在 AIDL 末尾追加。

### 6.3 AutoRecord 客户端纪律（独立 `AutoCameraClient`，不要塞进 `AutoClient`）

`AutoClient` 的 role 模型是闭集 + 单角色独占（[`ClientRegistry.kt:21-23`](../../galaxy/service/src/main/java/com/ecarx/autoservice/ClientRegistry.kt#L21-L23)），且 `onSurface` 方向相反（§1.2），因此新增客户端类，但**照抄其代次纪律**：

1. 每次 `onServiceConnected` 递增 ticket，所有回调先比对 ticket（模式见 [`AutoClient.kt:50-51`](../../galaxy/client/src/main/java/com/galaxy/auto/client/AutoClient.kt#L50-L51)）。
2. 代次不符的迟到 Surface 必须 `release()` 而不是丢弃（[`AutoClient.kt:61-68`](../../galaxy/client/src/main/java/com/galaxy/auto/client/AutoClient.kt#L61-L68)）。
3. 重连后**重放** `acquireSession` + `bindSurface`，旧 sessionId 视为失效（参照订阅重放 [`AutoClient.kt:89-95`](../../galaxy/client/src/main/java/com/galaxy/auto/client/AutoClient.kt#L89-L95)）。
4. 有限次重连（现有 `retries < 3`，[`AutoClient.kt:222-225`](../../galaxy/client/src/main/java/com/galaxy/auto/client/AutoClient.kt#L222-L225)），不得无限重开相机。
5. Surface 所有权：AutoRecord 拥有自己的编码器输入 Surface，跨 Binder 前用 writeToParcel 复制（[`AutoClient.kt:246-250`](../../galaxy/client/src/main/java/com/galaxy/auto/client/AutoClient.kt#L246-L250)），`close()` 时先 `releaseSession` 再释放本地 Surface。
6. 服务端必须装 `DeathRecipient` 兜底回收（现有模式 [`ClientRegistry.kt:24-29`](../../galaxy/service/src/main/java/com/ecarx/autoservice/ClientRegistry.kt#L24-L29)），客户端死亡不得让相机继续开着。
7. 用户"一键关闭摄像头"必须持久化并优先于客户端请求，与现有 4 个开关同机制（[`ServiceFeatures.kt:7-12`](../../galaxy/service/src/main/java/com/ecarx/autoservice/settings/ServiceFeatures.kt#L7-L12)、[`AutoStartup.kt:12-13`](../../galaxy/service/src/main/java/com/ecarx/autoservice/startup/AutoStartup.kt#L12-L13)）——需新增 `CAMERA("cameraEnabled")`。
