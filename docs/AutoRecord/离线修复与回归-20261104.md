# AutoRecord 六项离线整改与回归（2026-11-04）

## 范围

用户在初轮安装测试后要求停止连接车机，离线处理六类问题。本轮随后未调用车机远程通道、未部署公网服务、未安装车辆 APK；只操作本机仓库和专用 `AutoRecord_Offline / emulator-5568`。前一阶段的车辆日志与本轮模拟器结果分别记账，不能互相代验。

## 1. 429 复盘与安装通道

根因有三层，不能归为“包太大”或只用慢速 Shell 传包绕过：

1. 中继 `/bridge/artifact` 按文件计四包配额，却只在安装结果回传、撤销或会话到期时删除。上传后放弃安装的 APK、重启遗留 `.part` 会占槽；客户端每次上传又生成新 ID，重复操作最终永久触发 429。
2. AutoRecord 不在中继、AutoService 安装执行器及本机 CLI 的包白名单里；即使上传恢复，也不能走正常 install 作业。
3. 离线期间积压的 32 条未领取作业只在设备 poll 时过期，电脑继续提交会遇到队列 429。

修复：

- 上传同一 ID/摘要幂等返回，冲突内容拒绝覆盖；客户端使用摘要前 32 位作为稳定产物 ID。
- 删除无 owner 的 `.part`；孤儿 APK 按年龄/配额淘汰。在途上传和未完成安装引用的产物保留，仍有四个有效在途任务时返回带 `Retry-After` 的真实背压，不无界放大配额。
- 增加鉴权 DELETE 清理入口，禁止删除在途安装/上传；撤销/换授权窗口后在途上传不能再提交旧产物。
- 修齐三个安装白名单；满队列时淘汰过期作业，未知执行结果不自动重跑。
- 仓库部署入口默认回到正常 artifact/install 通路。压缩 Shell 传输仅为显式 `--transport shell` 诊断选项，不隐藏服务端故障；安装仍核对摘要并保留数据/签名。

`server/galaxyd` 的 `go test -race ./...` 已通过，新增覆盖重复上传、四包孤儿恢复、在途引用保护、重启残留分片、AutoRecord 包白名单及离线队列恢复。**代码尚未部署到公网服务**，不宣称生产 429 已消失。

## 2. 缺路状态与相机生命周期

原问题：格子构建时加入红色“缺路”角标，之后收到画面只更新 ImageView，没有移除角标。初轮车辆截图已证明“有画面仍缺路”。

现按每路状态动态更新：ACTIVE 隐藏缺路；等待首帧、已停止、未配置测试方向不标成缺路；真实错误保留原因。错误、断开、创建会话失败均关闭该会话的 reader/device/session；旧回调必须核对会话身份，不能删除同方向的新会话。首次等帧有超时，退出幂等，前台离开即释放。

另修初轮车辆捕获的预检线程崩溃：计算留在 worker，状态/结果经主线程 Executor 提交；停止、替换请求或宿主销毁使旧结果失效，销毁关闭预检线程。

## 3. 菜单与 CarPlay 尺度

- 首页、录像库和设置统一左侧 164dp 导航；删除首页独有的顶部三 Tab 实现。二级页沿用相同导航，回放仍可沉浸。

- 修正摄像头/订阅状态及首次引导的过时说明，不把尚未实现的后台录制写成当前能力。

模拟器上验证三页导航的位置/尺寸相同，并导出原生 Android View 的实际布局图。该 AVD 的 SurfaceFlinger 截屏存在阻塞，布局图使用独立测试 APK 的测量/布局/软件 Canvas 导出；**不是车机截图，也不是系统合成器截图**。

## 4. 速度、档位及车辆目录

旧实现固定为 `OfflineVehicleFeed`，任何页面都不可能取得真实车速。现接 `AutoClient` observer 租约，在权限 READY 且前台可见时订阅；离开前台取消，重连重新经过准备屏障再恢复，不产生仪表投屏需求。

- `RecordVehicleAdapter`：记录项映射为 AutoService 当前车型目录的语义别名；实际车辆属性 ID/区域与 L6/L7 差异仍由 AutoService 的 `VehicleCatalog.forModel` 处理，不在记录仪直连 SDK/ADB。
- 请求键取当前 `vehicleKeys` 交集，防止一个未知字段导致整组被拒；最大记录集不超过契约 32 键上限。
- 车速使用 `displaySpeed`，档位消费已转换的 `gear`；按 `receivedAt/maxAgeMillis` 的单调时钟判断新鲜度，断线清空，缓存旧结果不能覆盖较新样本，不补零。
- 后雾灯、车门、胎压等使用已有目录映射；AutoHold、总里程及“横向辅助”尚未完成含义/单位核验，保持不可用。`property.10057` 的通用控制类型不能擅自解释成横向辅助状态。
- 其他 App 的 `surface_closed` 不是车辆连接丢失，不连带关闭记录仪订阅。

离线测试覆盖有效零车速/P 挡、过期、断线、键数量及权限顺序。**没有本轮真实车辆数值验收**。

追加源码线索：本地 G733 `HardKeyService/sources/ecarx/car/hardware/vehicle/ECarXCarVfmiscManager.java:2525–2543` 存在 `getPA_AutoHoldStatus()`（561024171、area 1）与 `getPA_Total_Traveled_Distance()`（561024172、area 1）。同目录 `PATypes.java:12244–12269` 分别为 `PA_IntBase`，前者使用 `OnOff1`（0/1），后者未声明里程单位与倍率。它们证明原始读取入口存在，尚不足以把开关状态当作实际驻车保持、把原始整数当 km；本轮未接入这两个候选。材料根目录为 `/Users/anjon/Documents/ChatGPT/车机逆向/references/materials/inputs/g733-telemetry-evidence-20261025/sources/g733-20261024/`，枚举另见同材料的 `artifacts/jadx/g733-20261024/HardKeyService/sources/ecarx/car/hardware/annotation/OnOff1.java:8–9`。

## 5. 首次权限准备必须串行

正常车辆构建先在 App 检查 CAMERA：**已有权限时直接准备直连预览，AutoService 暂时离线不阻塞相机；车辆数据仍等待服务连接**。缺权限时的顺序：

```text
连接 AutoService observer 租约
→ 仅向 AutoService requestClientPermissions 请求
→ AutoService 校验调用者签名、租约及自身包名/权限白名单
→ 遵守自动运行与 Root 关闭选择，必要时沿既有 Root 准备后授权
→ 服务实际回读授权结果，经 IAutoResult 回调
→ App 再次 checkSelfPermission
→ 唯一 READY：允许车辆订阅和 Camera2 采集
```

准备期间不订阅值、不打开相机，连续点击也只产生一个请求。失败/超时/断线/销毁后旧回调失效；不并行弹系统授权框，不悄悄改用另一条授权路线。追加 AIDL 方法放在接口尾部，保留 v4 既有事务编号；使用此功能需更新 AutoService 与 AutoRecord。没有请求任意权限或为其他应用授权的接口。

`RecordPermissionSequenceTest` 使用真实 Activity/AutoClient 与替身 Binder 验证：服务说成功但本地未同步时仍不能采集；本地复核成功后才订阅并创建采集器；重复点击不重复申请。另验已有 CAMERA/服务不可用时仍准备直连相机。**真实车辆 Root 代授权尚未实测**。

还修复 AutoClient 关闭竞态：关闭后迟到的连接不得替换 owner；API 发布/关闭受短锁保护，detach 捕获关闭时的原租约。阻塞远端读取、关闭客户端、再注入迟到连接的回归验证原订阅租约被准确释放，避免后台留下采集需求。

模拟器构建是显式的 `emulator` build type，使用 Android 测试权限与电脑摄像头，不连接车辆 AutoService；不把它作为车辆授权验收。

## 6. 适配器、存储和编码预见性修复

相机采集器通过 `RecordCameraAdapter` 获取 cameraId 与实际尺寸：车辆用 `L6RecordCameraAdapter` 的既有实测参数；模拟器用 `EmulatorRecordCameraAdapter` 枚举自己的 Camera2/JPEG 能力，只配置一个真实测试输入，不把同一画面复制成四路。L7 扩展和服务自动扫描全部可通 ID 仍须独立落实与验收。

已修复：

- 清单原子覆盖失败时不得先删除旧清单；临时文件使用唯一名称；目录 fsync 使用真实目录 FD。
- 空视频不能被收尾为完整段，视频改名前同步文件。
- 小卷自动配额不得因 1GB 下限超过卷容量一半；预检拒绝不足一段或超过总容量的配额。
- 无 UUID 的可移除卷不可被保存为内置卷；匹配路径按目录边界，不匹配同前缀的其他卷；目标卷缺失不回切其他介质。
- 编码预检包含尺寸/帧率/码率/输入格式，硬/软/未知只认 SDK 分类位；非法实现不默认当硬编。
- “省空间”预设的 15fps 曾被持久化白名单漏掉，重建后回到 25fps，现修齐并增加读回回归。
- 车辆订阅间隔比较使用修改前旧值；设置提交补行驶只读保护，禁用行也禁用其实际开关。

独立模拟器测试 APK 已验证：真写/fsync/原子覆盖；明确点名 AVC 诊断组件，1280×720 合成黑帧 8 帧 → EOS → MP4 → 提取有序 PTS → 解码得到 1280×720 图像。生成帧的固定 PTS 仅用于该诊断，不用于真实相机录像。

该 API30 模拟器将 `OMX.google.h264.encoder` 的 hardware/software 均报 false，因此仍标为**未知**；只有测试 APK 的明确点名参数能用于诊断，产品硬/软选择不回退、不按名字猜。
