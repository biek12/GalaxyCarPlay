## 源码核对发现与修复

- 真机 `00:43:03.905` 捕获 `record-preflight` 线程的 `CalledFromWrongThreadException`，链为 `RecordingController.publish → RecordActivity.dispatchSnapshot → renderBadge`。预检结果改由宿主注入主线程 Executor 提交；停止、替换预检或销毁宿主后旧结果失效，Activity 销毁同时关闭预检线程。
- 真机截图四路均有真实画面但仍挂“缺路”角标；角标原来仅在构建时决定，现改为跟随每路 ACTIVE 状态更新。
- 相机断开、配置失败与请求异常原来未完整关闭 reader/session，旧回调也可能删除同方向的新会话。统一释放该会话全部资源，并核对会话身份后再更新状态；尚待修复后真机切换验收。
- 标定菜单原来禁止选择所有已占用 ID，而四个有效 ID 正好全占用，任何方向都无法改。改为明确展示两个方向、二次确认后一次交换与持久化；取消不改配置。交换后仍为待核对，只有单独确认四路方位后才标记已标定；不以远程画面猜地面方向。
- 引导、诊断及模块文档仍描述 AutoService 转发、已具备后台录制与旧容量估算。统一按当前直连预览及尚未接入的引擎状态描述，保留窗口从现有唯一计算入口取得。
- 设置间隔变更原来在覆盖旧设置后比较，条件永不成立；改为先保存旧间隔再比较。车辆订阅仍未接入，此修复不代表车辆数据已实测。
- 部署脚本依赖未入库的 `.work/push_base64.py`，且调用其不存在的 shell 子命令；改为仓库内 `autorecord_field.py`。压缩分块、偏移覆盖、续传前缀校验、安装前解压后校验和已装包摘要核对；安装只用 `pm install -r`，不降级、不清数据。现场验证不清系统 logcat，不把旧进程崩溃当成本轮结果。
