# 停车位置识别（未来规划）

2026-11-05 用户明确：停车后结合最近几段录像识别地下车库楼层、当前位置编号；本地做不了时由云端处理。本项是后续规划，本轮不启用视频上传、不调用第三方识别服务、不宣称已经定位车位。

## 流程

1. AutoService 提供已核验的停车状态、挡位及可用时间；P 挡稳定并结束行程后建立 parkingSession。短暂停车、上下客、再驶离需要更新/取消候选，不能每次挂 P 都上传一套视频。
2. 从该停车时刻向前取近几段四路视频，保留跨段源时间。按时间稀疏抽帧、画面变化和文字候选优先选证据；先提供抽帧/OCR 再按需取短片，避免无界上传四路完整录像。
3. 多帧联合识别：楼层标记（B1/B2/负一等）、坡道前后楼层变化、区域/柱号、停车位地面或墙面编号。临近车位和最终车位分别记录；单帧看到“B2”不等于最终停在 B2。
4. 云端返回结构化候选、置信度、证据帧时间/方向与冲突信息。结合进出方向和停车末帧验证最终编号，不能用不可靠地下 GPS 填出精确坐标。
5. App/网页展示“B2 · A区 · 125号（待确认）”和可点开的证据，用户可改正或标记未知；置信度不足时只报告有依据的楼层/区域，不编造车位号。

## 数据与接口草案

`ParkingSession`：`id,vehicleId,arrivedAt,departedAt?,sourceClipRefs[],state,revision,userConfirmed`。

`ParkingRecognitionJob`：`id,parkingSessionId,modelVersion,inputDigest,state,expiresAt,candidates[],errorCode`。

候选：`floor?,zone?,space?,confidence,observedAt,evidence[{clipId,direction,offsetMs,frameDigest,boundingBox}],conflicts[]`。编号保存原始 OCR 与归一值，置信度来源可解释；模型输出不得直接作为车辆控制、自动导航或自动泊车指令。

## 上传、保留与本地循环

- 用户显式启用云识别并选择网络/费用策略；未开启时仅本地记录停车时刻和待识别状态。
- 输入按 session 去重，任务可取消/超时，上传与推理失败不影响本地录制。等待网络的队列有界；用户驶离后作业不再自动覆盖新停车位置。
- 排队期间只申请有期限的片段保护，任务结束释放，不可永久占满循环配额。视频被覆盖、存储拔出、缺路、时间跳变都如实返回“不足以识别”。
- 最小化上云内容，可裁剪车位/指示牌区域并处理不相关人脸/车牌；证据、临时帧和结果分别设置保留周期并支持删除。不把影像放进错误遥测。
- OSS/对象存储凭据仅由自有服务签发短时受限上传授权；车端/网页不持有永久 AccessKey。

## 后续验收数据集

覆盖多层地下坡道、同编号不同楼层、编号被车遮挡、反光/暗光、无标识、邻位编号、跨分钟到位、挂 P 后挪车、断网补传、长时间后旧任务回执、重新停车和主动删除。分别统计楼层/车位正确率、错误报出率、未知率、证据命中率、上传量、耗时与车端 CPU/内存增量。真实标注来自用户确认，不能把模型自己的输出当真值。
