# 连续录制与驻车哨兵优化

2026-11-04，用户在两份故障修复过程中追加产品方向。本文件记录本次明确要求、源码现状与实施拆分；不将方案视为已实现，不将模拟器代替指定L6验收。

## 用户本次明确要求

1. 行车记录和驻车哨兵为核心，录制稳定性第一。分段时上一段保存与下一段录制并行，不允许因换段漏掉中间1–2秒。
2. 分钟切点对齐墙钟整分钟；按用户给出的例子，12:15:46启动，第一段到12:17:00（74秒），随后12:17:00–12:18:00，而不是首段只录14秒。整分启动按60秒；多分钟设置保持其周期，短段测试单独计时，不改变产品分钟语义。
3. 优化上车自动录制，状态栏中录制绿色、停止灰色；另有贴合屏幕左/右边缘的小悬浮图标。
4. 在线实时/历史观看接口可下一版实施；需要研究远程唤醒车机及驻车哨兵。用户指出银河官方App空调操作可唤醒车辆，这是能力线索，不是本项目已经获得相同唤醒接口的证据。
5. 后续有真实画面时再优化鱼眼→平面按钮、交互放大/全景视角、参考原厂倒车3D效果。OSS/云端存储为后续扩展，不能让上传阻塞本地录像。

## 当前源码事实与故障修复的区别

[RecordingEngine.kt](../../galaxy/record/src/main/java/com/galaxy/autorecord/recording/RecordingEngine.kt#L344) 当前每段依次关闭采集、EOS、封装、提交后重建相机和编码器。这会产生确定的分段空窗；移除300ms固定等待只解决错误等待，不等于无缝录制。修复后的onClosed屏障消除了已知消费者内存竞争，但也不能消除相机/编码器重建本身的时间。

[RecordSettings.kt](../../galaxy/record/src/main/java/com/galaxy/autorecord/core/RecordSettings.kt#L32) 已有autoOnBoot/background等设置；[Manifest](../../galaxy/record/src/main/AndroidManifest.xml#L1) 尚无真正承载录像的服务和开机Receiver。设置存在不能宣称已能后台/开机录制。当前Activity持有引擎、相机和车辆feed，退出时释放，须迁移所有权。

## 实施架构（待落地，不能标为完成）

### A. 持续采集与分段写盘解耦

- 每路Camera2设备、YUV Reader和MediaCodec按整个录制会话持有。普通分钟分段不解绑Surface、不关闭Reader、不发EOS、不重启编码器。仅整个会话停止或显式不兼容配置变更才进入已修复的关闭屏障。
- 编码输出与磁盘写入分离：复制有效编码包及真实PTS到有界队列；独立写线程持有muxer。预先创建下一段事务/目标muxer，不临到切点才分配资源。
- 切点请求关键帧。新文件必须以可独立解码的关键帧起始；编码器关键帧可能晚于请求时间，不能宣称request-sync-frame保证精准整分。以PTS路由边界，必要时保留包含边界前关键帧的短GOP重叠，并在清单记录名义区间、实际PTS和边界偏差。不能为了文件名看起来整分而删除边界附近画面或伪造时间戳。
- 上段muxer.stop/fsync/rename/清单与缩略图在有界收尾队列执行，新段继续接帧。事务有线程所有权，在哪个线程begin就在哪个线程commit/finish；不能将现有SegmentTransaction直接跨线程调用。
- 所有已接受编码帧须有且仅有可追踪的归属（若采用GOP重叠则明确记录重叠）。队列满/磁盘过慢必须上报具体错误、保留partial及计数；不能静默丢帧或无限堆内存。四路切点使用同一会话锚点，车辆侧录同域对齐。
- 首段结束点按“启动墙钟+至少一个周期，再向上对齐整分钟”计算。运行调度用单调时钟；墙钟被校时的情况单独记录，不能倒退PTS或重复覆盖目录。
- 首次版本先验收固定配置无缝分段；录制中切分辨率/编码格式/存储卷等不兼容设置的过渡须单独定义和验证，不借此声称任意配置切换都无损。

### B. 自动录制、状态与悬浮入口

- 录制所有权迁入自有前台服务。Activity只订阅状态与绑定/解绑预览；切页、退出页面、熄屏不停止用户已开启的后台录制。
- 上车状态消费AutoService已核验的电源/车辆信号；先定位目录字段、实际状态及恢复时序，不能用P挡或“App打开”冒充点火。开机、包更新、进程恢复通过一个幂等入口，遵守自动录制和用户主动停止选择。
- 原始设置默认值本轮不擅自改成已确认。前台通知是系统状态栏入口；Android对通知小图标有系统着色规则，需在目标Flyme核对是否能呈现要求的绿/灰，不能只设置Notification.color就宣称小图标已变绿，也不改原厂状态栏HMI。
- App内状态与贴边悬浮图标共用真实录制状态：准备/错误不得显示为绿色“录制中”；有有效帧持续写入才显示绿色，停止灰色。悬浮位置左右可选、贴边保存；只申请本App所需悬浮权限，缺权限时明确引导，不循环弹出或盖住原车关键控件。

### C. 驻车哨兵与唤醒

- 分开验证：屏幕关闭但Android存活、车辆部分休眠、整车深度休眠。前台服务/CPU wakelock不等于能唤醒已经断电或断网的车机。
- 核对原厂/星枢/车机材料中真实电源事件、摄像头供电和原厂环视占用，以及银河官方远程唤醒的调用链、认证归属和中继能力。保持已有AutoService远程通道；本地在线长轮询不能接收深睡设备尚未联网时的命令。
- 哨兵需定义布防、事件触发、事件前后缓存、保护片段、存储配额、低电量退出及用户关闭。低电阈值/最长驻车时长/是否允许保持车机供电属于产品选择，待真实供电证据后给出明确建议，不先写死猜测值或实施车辆控制。
- 本条确认了研究/开发范围，不扩大当前离线任务为现场空调/唤醒/车辆写操作授权；需要现场时沿既有授权流程安排。

### D. 画面与后续远程扩展

- 先取得真实内参/畸变标定和四路安装位姿，鱼眼展平保留原始录像；预览算法与证据原片分别处理，避免重采样损坏原证据。
- 四路拼接和3D环视需要标定、重叠区/时序与车身遮挡处理；单路放大/交互视角可独立实现。原厂3D只作后续源码/素材/接口研究入口，未读取即不声称可直接复用。
- 后续观看/云存储走独立有界读/上传任务、可续传和带宽限制，本地录像优先；本轮不新增云账户、OSS部署或上传录像。

## 验收门槛

1. 同一会话至少十次换段，逐路核对相邻源PTS、最后/第一有效帧、关键帧、独立解码、边界偏差、队列及丢帧计数；文件名连续不能代验画面连续。
2. 注入慢写盘、收尾异常、空间不足、停止/退出/相机抢占；既有帧有明确归属，异常保留partial与原因，进程无SIGSEGV。
3. 指定L6四路60秒分段长录，与改造前相同场景对比CPU/内存/线程/FD、温升与相机共存；模拟器单路只覆盖Android流程。
4. 自动录制覆盖上车、屏幕关闭、页面退出、崩溃恢复和主动停止；哨兵/深睡唤醒各自留实测证据，互相不代验。
