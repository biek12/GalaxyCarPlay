# AutoRecord 在线查看：网页需求与 Agent 交接

状态：2026-11-05 用户确认规划；本文件是供另一位 Agent 开发的需求与拟定契约，**不是现有后端接口已上线的说明**。车端录制稳定性优先。网页不得直接访问 AutoService 诊断 Shell、Root、ADB 或原车 MQTT/OSS 凭据。

## 1. 技术与分工

- 前端：Vite、Vue 3、TypeScript、UnoCSS、Pinia、Ant Design Vue（用户所说 Antd 的 Vue 实现）。采用 Vue Router，依赖由实施 Agent 核对当前兼容版本后锁定，不使用浮动 latest。
- 前端 Agent：响应式网站、播放器、状态管理、契约类型、明确标记的 mock 数据与异常场景；不得写入本工程车端目录、读取私有认证材料或直接部署生产服务。
- 后端：延续自有 `server/galaxyd` Go 服务的部署能力，新增独立 `/web/v1` 路由和用户/车辆授权域；当前 `/bridge` 运维会话不等于用户观看授权。实现账号、2FA、车辆绑定、流会话、历史索引、作业回执与审计。
- 车端：AutoService 负责出站连接、设备身份、能力和电源状态；AutoRecord 负责本地相机、录像、数据侧录及经授权的观看/传输。网页不承载车型 SDK。
- 视觉：简洁日夜主题、激活绿、清晰的四路方位。桌面和手机都能用，避免把车机固定分辨率搬到网页。UnoCSS 与 Ant Design Vue 样式优先级统一管理，播放器布局不受组件库全局 reset 影响。

## 2. 页面与完整状态

| 路由 | 内容 | 必须处理的状态 |
|---|---|---|
| `/login` | 通过手机号 + 2FAd 登录  | 错误、节流、会话失效；密码通过不等于已登录，手机号错误次数过多直接限流 |
| `/security/setup` | TOTP 二维码、确认验证码、恢复码一次展示 | 未确认不可标记启用；刷新后不再次泄露恢复码 |
| `/vehicles` | 已绑定车辆、多车切换、绑定入口 | 空列表、绑定过期、已归属、解绑中、无权限 |
| `/vehicles/:id` | 车辆在线/最后在线、录制与存储状态 | 在线、休眠、唤醒中、离线、未知、故障分别显示 |
| `/vehicles/:id/live` | 前/后/左/右四宫格、单路、鱼眼/平面、音量入口仅在确有音轨时显示 | 准备、首帧、卡顿、断线、摄像头占用、缺路、标定不可用 |
| `/vehicles/:id/history` | 精确日期时间范围、重要/异常/未看、分页、多选删除 | 本地可用、仅云端、未上传、已覆盖、缺失、处理中、部分失败 |
| `/vehicles/:id/clips/:clip` | 四路同步历史、车辆条、事件时间轴 | 时间空洞和各路缺帧明确呈现；不把后一路画面挪到前一路 |
| `/vehicles/:id/sentry` | 开关意图、实际布防状态、电源/存储条件、事件 | 待布防、已布防、唤醒中、录像中、受限、失败、已关闭 |
| `/security` | 修改密码/2FA、恢复码、会话管理 | 敏感修改前重新认证；撤销所有会话立即生效 |
| `/vehicles/:id/access` | 归属、授权成员、解绑 | 车主与观看者权限差异；转移归属重新验证车端 |

停车位置页面留为未来模块，不能用 mock 识别结果作为当前实车功能。

## 3. 账号、2FA 与绑定流程

建议首期自有部署采用邀请注册（账号开放注册策略待定），保留可替换的账号入口，不依赖尚未接入的短信/邮件服务。密码重置若无投递服务，走部署者签发的一次性恢复流程；不得放置永远成功的“邮件已发送”。

登录：密码校验 → 短时预认证 challenge → TOTP/恢复码校验 → 正式会话。未完成 2FA 的 challenge 不能读取车辆、影片或流地址。未设置 2FA 的新账号只能进入安全设置，完成确认后才可绑定/观看。

TOTP 依据 [RFC 6238](https://www.rfc-editor.org/rfc/rfc6238) 实现。更换认证因子前重新认证，并提供恢复途径；具体认证因子生命周期参考 [OWASP MFA 指南](https://cheatsheetseries.owasp.org/cheatsheets/Multifactor_Authentication_Cheat_Sheet.html)。以下为本项目拟定约束，需后端落地后验收：

- 独立随机 TOTP secret，服务端加密保存，建立后不再返回；首次验证码确认才提交启用。
- 单次 challenge 5 分钟过期；验证码限次、按账号与来源节流；同一已用时间步不能再次用于认证。
- 10 个一次性随机恢复码，只展示一次、服务端仅存哈希；使用后原子作废，重新生成使旧组全部失效。
- Cookie 会话使用 Secure、HttpOnly、合适的 SameSite；改变数据的请求校验 CSRF/Origin。Pinia 不持久化密码、TOTP secret、恢复码和长期 bearer token。
- 改密码、改/关闭 2FA、重新生成恢复码、转移/解绑车辆需近期二次认证。登录和恢复错误不暴露账号是否存在。

绑定：车机 AutoService 展示**独立车辆绑定码/二维码** → 网页已登录且完成 2FA 的账号输入 → 服务端验证设备签发与有效期 → 车端展示目标账号并确认 → 服务端原子建立 owner。二维码只含一次性绑定材料，5 分钟有效；过期、重放、被其他账号使用、车辆已有 owner 都有明确回执。不能拿当前远程调试验证码直接绑定账号，也不能仅凭 VIN 获取归属。

设备注册公私钥与网页账号分离，私钥留设备；车端通过已登记身份的出站连接发布绑定挑战。首期支持 owner、viewer 两种角色：viewer 仅可观看已授权车辆，不能删视频、改哨兵、转移归属、管理成员。每个后端请求均验证账号与该 vehicleId 的归属/授权，前端隐藏按钮不能代替鉴权。解绑/撤销授权立即终止流会话并撤销对象下载授权。

## 4. 在线、唤醒与实时播放

网页进入实时页后先取车辆状态；车辆休眠时由用户发起“唤醒并观看”。只有 capability `remoteWake.supported=true` 且车端电源适配完成才可调用；否则显示真实原因。HTTP 接受请求不表示车机已醒、已开相机或已录制。

唤醒作业状态：`queued → dispatched → waking → device_online → ready`，或 `failed/expired/cancelled`。车端真实心跳与首帧分别确认，超时只显示失败，不无限循环唤醒。不能把持有 Android WakeLock、服务器排队或官方 App 可唤醒当作本项目已支持。

拟定实时传输采用 WebRTC（鉴权信令、必要时自有 TURN）；实际编码并发/带宽先做车端预算。录像的原始编码与写盘优先，直播客户端数量有上限；多用户优先服务端分发。观看页离开/会话撤销后释放仅为观看建立的资源，不停止本地行车录制。

每路状态独立：cameraId 不对网页直接暴露控制权；方位是 `front/rear/left/right`。画面平面模式只在对应标定可用时显示，原片保留鱼眼，记录投影/标定版本。首帧超时、帧龄超限必须遮蔽旧画面并显示断流，不继续将静止帧标为“实时”。

## 5. 历史时间轴、车辆数据与删除

- API 时间统一 Unix 毫秒，边界 `[from, until)`，按片段区间相交筛选：`clip.end > from && clip.start < until`。界面明确显示时区，默认 Asia/Shanghai；请求不使用没有时区的字符串。结束时间必须大于开始时间。
- 片段由 sessionId、clipId、起止时间和各路文件状态组成；四路共用同一录像时钟。翻页采用稳定游标 `(start, clipId)`，不能录制中新片段插入便重复/漏页。
- 历史车辆数据消费 sidecar 真实样本，包含每键采集时间 `a`、质量 `q`、实际 intervalMs。油门与刹车保留短踩、抬起、力度变化；横条颜色区分力度，展开显示阶梯/曲线并标注真实采样点。
- 视频首帧 PTS 与 segment 的源时钟偏差必须沿用车端清单解释；不能简单把四个 MP4 的 0 秒全当成同一时间。数据过期、断采、缺帧各自留空，禁止插值编造刹车/油门/灯光状态。
- 锁定片段不可直接删，需先显式解锁。人工确认删除可以包含未锁定的事件片段；自动循环覆盖仍遵守事件保护策略。写入/收尾/回放/导出占用片段不能被删除。
- 单段与批量删除均后台作业，单位为整个片段：四路视频、车辆数据、事件、缩略图、索引一并处理。逐项回执，不能把部分失败当全部成功。
- “删除车端”和“删除云端”分开显示范围，首期只接已实现范围；不因删云索引误删车端原片。离线车辆的删除排队有有效期与幂等 ID，到期不在下次上车时突然执行旧删除。
- 本地已覆盖而未上传的录像不可播放；显示“已覆盖/未上传”，不能保留一个可点击但永久失败的播放入口。

## 6. 拟定 API 清单

以下全是新契约建议，实施方需提交 OpenAPI 与服务端实现；不要直接请求当前生产 `/galaxy` 猜路径。

| 方法与 `/web/v1` 路径 | 用途 | 主要结果 |
|---|---|---|
| `POST /auth/login` | 密码步骤 | challengeId、expiresAt、next=`totp/enroll` |
| `POST /auth/challenges/{id}/verify` | TOTP/恢复码 | 建立正式 Cookie 会话 |
| `POST /auth/logout` | 退出 | 撤销会话 |
| `GET /me` | 身份 | userId、2FA 状态 |
| `POST /me/mfa/enrollments` | 创建待确认因子 | enrollmentId、otpauthUri（仅此步） |
| `POST /me/mfa/enrollments/{id}/confirm` | 确认因子 | enabled、一次性 recoveryCodes |
| `POST /auth/reauth` | 敏感操作再认证 | 短时、绑定当前会话的 actionTicket |
| `GET/DELETE /me/sessions[/{id}]` | 列表/撤销会话 | 当前与其他设备会话 |
| `POST /vehicles/bindings` | 提交绑定码 | bindingId、pending_device_confirmation |
| `GET /vehicles/bindings/{id}` | 绑定结果 | pending/confirmed/rejected/expired |
| `GET /vehicles` | 授权车辆 | 列表与 role |
| `GET /vehicles/{id}` | 在线与能力 | presence、recording、storage、capabilities |
| `POST /vehicles/{id}/wake-jobs` | 唤醒请求 | 202 + jobId，非同步成功 |
| `POST/DELETE /vehicles/{id}/live-sessions[/{sid}]` | 开始/停止观看 | 信令会话与到期时间 |
| `GET /vehicles/{id}/clips` | 历史检索 | items、nextCursor；from/until/filter/source |
| `GET /vehicles/{id}/clips/{cid}` | 清单与播放授权 | 方位、起止时间、缺路、短时媒体地址 |
| `GET /vehicles/{id}/clips/{cid}/telemetry` | 历史样本与事件 | 游标、源时钟和各键质量 |
| `POST /vehicles/{id}/clip-delete-jobs` | 单段/多段删除 | scope、clipIds、actionTicket、幂等键 |
| `PUT /vehicles/{id}/sentry-intent` | 哨兵意图 | enabled、revision、作业 ID，等待实际状态回读 |
| `GET /jobs/{id}` | 作业结果 | 状态、逐项回执、reason、timestamps |
| `GET /events` | 授权范围内 SSE | presence/recording/sentry/job 更新与断点游标 |

所有修改请求带 `Idempotency-Key`；跨用户/车辆复用同一键不能命中别人的结果。401 未认证，403 无权，409 状态冲突（如片段占用/已锁），422 参数不合法，429 节流，503 设备/能力暂不可用。错误格式 `{code,message,requestId,retryAfterMs?}`，不返回 Shell、路径、堆栈或凭据。

车辆状态响应示例（**示例，不是实车测量**）：

```json
{"vehicleId":"example-l6","role":"owner","presence":{"state":"sleeping","lastSeenAt":1793851200000},"capabilities":{"remoteWake":{"supported":false,"reason":"power_adapter_pending"},"flatView":{"front":false,"rear":false,"left":false,"right":false}},"recording":{"state":"unknown","observedAt":1793851200000},"sentry":{"desired":false,"actual":"unknown","revision":1}}
```

历史片段响应至少含：`clipId,sessionId,startAt,endAt,source(local/cloud),availability,locked,eventCount,bytes,channels[{direction,status,mediaStartOffsetUs,durationUs,projectionVersion}],telemetry{schema,actualIntervalMs,availability}`。时间轴事件至少含 `key,startOffsetMs,endOffsetMs,kind,sourceQuality,ruleVersion`；瞬时事件和持续状态分别表达。

实时信令与媒体地址必须短时、仅授权车辆与流，不在日志/URL 查询串里带长期会话令牌。历史流采用支持范围请求的已授权 MP4 或经服务端封装的点播流，具体形式依真实 seek/四路同步结果确定；前端播放适配器隔离，不能以四个独立进度条代替同步播放。

## 7. 前端代码组织与 mock 交付

- `src/api/`：统一请求、CSRF、错误映射、DTO/运行时校验；`src/api/mock/` 显式开发模式入口。生产不得偷偷启用 mock。
- `stores/auth.ts, vehicles.ts, playback.ts, jobs.ts`：只缓存有界状态，切车时清理上车数据/播放器/请求；用户退出撤销 SSE、观看会话和媒体对象。
- `features/live/`：流会话与四路播放器；`features/history/`：列表、时间筛选、批量操作；`features/timeline/`：公共时轴和力度曲线。
- `features/security/`：2FA 与会话；`features/vehicles/`：绑定/归属；`features/sentry/`：意图与实际状态。
- mock 必须覆盖：双路缺失、100ms 踏板连续短踩、100→80→20→0 力度变化、跨段延续、视频不同起始偏差、未知/过期样本、跨午夜片段、分页中新片段插入、批删部分失败、车休眠/唤醒失败、无平面标定、无所有权、2FA 错误/恢复码重放。

## 8. 交付验收

1. 只通过密码/预认证不能访问任何车辆接口；他人 vehicleId、clipId、jobId、对象地址逐项越权验证。
2. 绑定码过期/重放、恢复码重放、会话撤销、2FA 更换、viewer 删除均有真实后端拒绝回执。
3. 四路以同一时轴 seek/暂停/倍速；测试夹具首帧错开和采样不齐时仍对齐。展示误差与源采样分辨率分别记录，不写“100ms 采集=100ms 总延迟”。
4. 1/10/100 个选择项删除显示成功/跳过/失败，刷新后索引与文件状态一致，活动录制无中断。
5. 断流遮蔽旧画面；页签切换、离开页面、退出账号后资源释放，长时间看播不拖垮录制；手机浏览器进入后台恢复有状态回执。
6. 未实际支持远程唤醒/标定/云上传时显示明确状态；不放一个永远转圈的按钮或假成功 toast。
7. 交付 README、锁定依赖、`.env.example`（无真实密钥）、契约、明确的 mock 启动方式、接口联调记录及异常场景结果。上线部署另行按既有自有服务器流程执行。

## 9. 后续云存储与停车识别接口位置

云上传默认关闭。开启时明确上传范围、网络条件、容量/保留周期；本地录制与循环保护优先。上传队列有界、断点续传、摘要核验、去重，不能在录像线程同步上传。服务端审计不含视频、车辆原始载荷、TOTP secret 和认证材料；媒体与侧录上传是独立用户功能，不能混入错误日志上报。

停车位置识别详见 [停车位置识别规划](停车位置识别未来规划-20261105.md)。未来 API 预留 `/vehicles/{id}/parking-sessions` 与 `/parking-jobs`，本期不实现；网页只展示真实 job 结果、置信度和证据，用户可校正楼层/车位号。
