## 1. 本轮用户已确认的四条

1. 在 GalaxyPlay 工程内新增独立 **AutoRecord 四向行车记录仪**，与 CarPlay、AutoService、AutoCluster 并列；实时画面与车辆数据统一由 AutoService 提供，AutoRecord 不自行连接 Camera2、厂商 SDK、ADB、Root 或认证材料。
2. **UI 风格继续继承 CarPlay 的 FlymeAuto 风格**：沿用项目既有的 FlymeAuto 日夜色阶、文字角色、设置行/分组卡、开关和触控尺度，不另起一套视觉语言、不复刻截图里的第三方样式。
3. 本轮要把**每个页面的功能定下来**，包括设置界面。
4. 设置界面至少要能设置 **存储位置、视频编码格式、软编码/硬编码**；相关选项由本文档整理成可实现、可验收的条目。

## 2. 全局规范

### 2.1 视觉与尺寸基线

- 页面色阶、文字角色、行高、圆角、控件尺寸一律引用[样式基线](FlymeAuto样式基线-20261103.md)，本稿不重复定义数值；AutoRecord 作为独立 App 复用 AutoService 同级的独立 Flyme 色阶，不依赖 CarPlay 宿主资源。
- 竖屏单形态（L6/L7 同为 8155 竖屏，按 D12 不做车型级 UI 分支）。页面宽度按 dp 布局：一级页 = 左侧导航栏 + 内容区；二级页 = 64dp 返回标题 + 分组卡。
- **布局分两档（RV-03）**：**内容优先页**（P1 实时画面、P1a 单路）收起左侧导航栏，改为标题栏下方一条 **56dp 三 Tab 切换条**（实时画面 / 录像库 / 设置），内容全宽；**管理页**（P2 录像库、P5 设置及全部二级设置页）保留左侧 164dp 导航栏；**P3 同步回放**为二级沉浸页，只保留左上返回。理由是 P1 的有效信息是画面，导航栏宽度在竖屏下直接从画面里扣走；而"录制状态可见"由标题栏录制徽标常驻保证，不依赖导航栏。三 Tab 与导航栏**同一组路由与同一返回栈**，只是呈现形态不同，不得出现两套导航状态。
- **竖屏宽度口径（新增，原稿缺失）**：本稿不假定具体 dp 宽度，改为按**可用内容宽度**定义：内容优先页 = 整屏宽；管理页 = 屏宽 − 164dp。四宫格每格最小可读宽度定为 **≥200dp**（约 1080p 素材在该宽度下的有效辨识距离）。实现时若管理页内容宽 < 440dp（即屏宽 < 604dp），P1 必须走内容优先档、P2 卡片改为单列——这条是可判定的，不留"看情况"。
- 导航栏宽度按项目实际生效口径 **164dp**（内层 132dp + 两侧 16dp），导航项 90dp 高、图标 48dp；`l7_ui.xml` 里的 `l7_nav_width=125dp` 当前源码无引用，**不得当实际值**（证据见[样式基线](FlymeAuto样式基线-20261103.md) §4）。
- 标题栏左右槽在项目里各 64dp；AutoRecord 标题栏右侧要放录制/存储/连接三个徽标，右槽改为**内容自适应宽、高度仍 64dp**；窄屏放不下时徽标降级为"图标 + 极短值"（REC 点 + 时长、卷名缩写、状态点），不得挤压标题文字或换行。
- 视频格一律 **16:9**、不裁切有效视野、不做圆角裁切以外的变形拉伸；四宫格 2×2，格间距 12dp，方向标签固定在每格左上角。
- 触控目标不小于项目既有设置行尺寸（80dp 行高/64dp 图标按钮），图标自绘于 24px 画布，不复制 OEM 与截图素材。

### 2.2 常驻状态元素（所有页面可见）

| 元素 | 位置 | 内容 | 规则 |
| --- | --- | --- | --- |
| 录制徽标 | 标题栏右侧 | REC 红点 + 已录时长（`hh:mm:ss`）+ 当前片段进度 + **录像健康点**（绿=四路齐全、黄=有缺路/写入过慢、红=未在写） | 未录制时显示"未录制"灰态；录制中任何页面都可见；**点击展开操作条**（停止录制 / 锁定最近片段 / 打开实时画面），见 §2.3-7；健康点异常时点开直接进 P11 对应分组 |
| 可回溯时长 | 存储徽标内联（次行小字） | `可回溯 ≈ X 小时 Y 分`（按当前码率与配额估算） | 仅估算，须标注"估算"；配额或画质变化后重算；见 §5 P6 的容量口径 |
| 存储徽标 | 标题栏右侧（录制徽标左侧） | 介质名（内置/U 盘卷名）+ 剩余空间 | 低于最低剩余时转为警示色并附原因；不在此处做删除操作 |
| 连接徽标 | 标题栏右侧（最左） | AutoService 连接状态：正常/重连中/未连接/版本不匹配 | 非正常态可点进诊断页；不得用实时数据消失冒充"车辆静止" |
| 缺路角标 | 四宫格对应格的右下角 | "缺路 mm:ss–mm:ss" | 某路断流必须标出区间；不得复制其他方向画面 |

### 2.3 全局交互纪律

1. **录制与页面解耦**：切换页面、单路放大、进设置、回桌面、息屏都不停止用户已开启的录制；进入/退出实时页不重新打开摄像头，也不反复申请/释放会话。
2. **前台服务**：录制期间保持前台服务并显示常驻通知（内容见 2.4），通知带"停止录制"动作；通知点击进入实时画面。
3. **设置保存与生效分开**：所有设置改动立即持久化；影响编码/写盘的参数在**下一个片段**生效，当前片段不中断；界面必须提示"下一段生效"。
4. **用户关闭就是关闭**：用户停止录制、关闭自动录制、或在 AutoService 关闭对应功能后，任何旧回调/恢复任务/其他页面都不得重新开启；AutoService 的全局关闭选择优先于 AutoRecord 设置。
5. **不静默降级**：存储不可写、编码器创建失败、四路达不到参数、车辆数据源失效，必须显式报出"哪一路/哪个源/哪个卷/哪条原因"，禁止换参数、换目录、补零或复制画面冒充正常。
6. **历史数据只读**：回放只使用录像当时保存的样本，禁止叠加当前实时值；缺失显示"未知/缺失"，不补零、不跨断流区间无限沿用。
7. **一键停止 = 点击不是长按（RV-07）**：录制徽标点击后展开操作条（停止录制 / 锁定最近片段 / 打开实时画面），条目高 80dp。**停止录制必须二次确认**（"将结束当前片段并保存，确定停止？"），因为它是不可逆的中断动作；长按手势本稿撤销——隐藏手势在行车场景不可发现，且危险动作不能靠误触触发。
8. **行驶中操作限制（RV-07，新增）**：挡位数据可用且**非 P 挡**时，进入"行驶中模式"——设置页（P5 及 P6–P12）只读展示并可返回，顶部一行说明"行驶中不可修改设置，请停稳后操作"；P1/P2/P3 与操作条（停止录制、锁定片段）保持完全可用。挡位不可用或过期时**不进入**该模式（降级为可编辑 + 一行提示"挡位不可用，请自行确认已停稳"），不得因数据缺失锁死用户。
9. **取证快捷（RV-01）**：任意页面操作条都提供"锁定最近片段"，P1 操作区保留同功能按钮；锁定的对象是**当前正在写的片段 + 最近一条已完成片段**（跨段事件常被切在两段里，只锁一段会漏证据），锁定成功给出"已锁定 2 段（含当前段）"的明确回执。

### 2.4 系统通知（非页面）

| 场景 | 标题 | 正文 | 动作 |
| --- | --- | --- | --- |
| 录制中 | 正在录制 4 路 | `hh:mm:ss` · 当前片段 `mm:ss` · 已写 `x.x GB` · 内置/U 盘 | 停止录制 / 打开 |
| 录制异常 | 录制已暂停 | 具体原因（U 盘已拔出 / 空间不足 / 摄像头不可用：左后） | 打开诊断 / 重新开始 |
| 后台自动录制已关闭 | AutoRecord 未录制 | 自动录制已按设置关闭 | 打开设置 |

通知文案不得包含车牌、手机号、文件绝对路径等敏感信息。

### 2.5 文案与格式规范

| 项目 | 规则 |
| --- | --- |
| 时间 | 录像卡片与回放用 `yyyy-MM-dd HH:mm:ss`（本地时区），时长用 `mm:ss`（≥1 小时用 `h:mm:ss`） |
| 容量 | `GB`/`MB` 一位小数；剩余空间与配额分开显示，不合并成"可用" |
| 车速/转速/角度 | 带单位（km/h、rpm、°），正负号保留符号；未知显示"—"，不显示 0 |
| 状态词 | 统一用：录制中 / 未录制 / 缺路 / 部分有效 / 可恢复 / 文件缺失 / 损坏 / 已锁定 / 未播放 / 已播放 / 空间不足 / 已满 / 只读 / 已移除 / 写入过慢 / 不可写 / 等待摄像头 / 等待原厂释放 |
| 错误定位 | 错误必须带来源：`前`/`后`/`左`/`右`、`车辆数据`、`内置`/`U 盘卷名`、`编码器（实际名）` |

## 5. 逐页功能定义

### P1 实时画面

| 区域 | 内容 | 规则 |
| --- | --- | --- |
| 标题区 | "实时画面" + 录制徽标 + 存储徽标 + 连接徽标 | 见 2.2 |
| 四宫格 | 左上前、右上后、左下左、右下右（2×2，16:9） | 每格左上角方向标签；点击进入 P1a；某路无帧显示该路状态（等待/缺路/权限/被占用）而不是黑屏无解释 |
| 数据条 | **默认折叠为一行 4 项**（车速、挡位、转向灯、巡航），点"展开"显示两行全量 | 第 1 行：车速、挡位、转速、转向角、油门/刹车、转向灯；第 2 行：横向辅助、巡航+设定车速、近/远光、示宽/后雾、Auto Hold、驻车、油量/电量、续航、总里程、内外温度。折叠态占据高度 ≤56dp，展开态 ≤112dp；展开偏好持久化（RV-04） |
| 操作区 | 主按钮"开始录制"/"停止录制" + 次按钮"**锁定最近片段**"（录制中可用）+ "最近录像"收进录制徽标操作条 | 主按钮状态只跟真实编码与写盘结果走：请求中、录制中、停止中、失败（带原因）。"锁定最近片段"锁定当前段 + 最近已完成段，命中已锁定则显示"已锁定"并允许解锁（RV-01，见 §2.3-9） |
| 内嵌提示条 | 事件/状态提示：空间不足、U 盘拔出、摄像头不可用、AutoService 未连接、温度保护 | 一条一条显示，可进入对应设置或诊断，不堆叠超过一条 |

交互与状态：

1. 进入页面只复用已有预览 surface，不重开摄像头；离开页面（含息屏）只释放预览输出，编码输出与车辆订阅保持。
2. 切换单路/四路只切换预览布局与 surface 复用，不改变录制范围、不改变订阅。
3. 开始/停止录制的按钮与通知里的动作共用同一状态机；停止成功后必须显示"已保存 N 段/MB"，失败显示原因。
4. 录制中"停止录制"先按固定顺序收尾当前片段（编码器 EOS → drain → `muxer.stop()` → `release()` → `fsync` → 原子改名 → 写索引），再显示已保存；期间按钮显示"停止中"，且不得直接 release 丢掉 moov。
5. 数据条只显示 AutoService 推送的当前值与时效：过期显示"—"，来源断开显示"数据不可用"，不得沿用旧值。
6. 某路首帧未到时显示"等待摄像头（前）"；原厂环视占用时显示"等待原厂释放（左）"；不得静默合并到其他格。

7. **开始录制走两阶段预检（RV-08）**：点击"开始录制"后先进入"预检中"（≤5s，显示进度：连接 → 四路首帧 → 编码器创建 → 目标卷校验 → 时钟基准），全部通过才进入正式录制并开始写盘。任一路失败时**不自动降级**，弹出"哪几路不可用 + 原因"与两个选项：①仅录制可用路（按钮写明"将记录 3 路，缺左"）②取消。用户不选即视为取消。规则细化见 §14.2。
8. **录制中显示健康与回溯窗口（RV-02）**：标题区录制徽标带健康点；存储徽标内联"可回溯 ≈ X 小时"。低于 2 小时时转为警示色，并给一行"建议锁定重要片段或导出"的提示（不自动改配额）。

验收点：切页/息屏/回桌面录制不断；四路方向与实际一致；按钮状态与文件真实增长一致；缺路标注到分钟级区间；无"黑屏无解释"；预检失败必给路数与原因、不静默降级；可回溯时长为估算值且随设置重算。

- 顶部四段切换：前/后/左/右（选中态用项目 accent）；再点"四路"或返回键回四宫格。

| 卡片 | 四向拼接缩略图（2×2 小图）+ 开始时间 + 时长 + 介质标签 + **最多 2 个角标** | 角标优先级（RV-05，从高到低）：文件缺失 > 部分有效 > 可恢复 > 缺路 > 已锁定 > 含事件 > 未播放 > 含车辆数据。第 3 个及以后收起为 `+N`，点开在 P4 信息里看全。缺路卡片缩略图对应格显示占位而不是借用其他方向；可恢复与文件缺失不得显示成"未播放/已播放"的正常态 |

交互与状态：

1. 列表数据来自本地索引；索引损坏或重建中显示"正在重建索引（M/N）"，不显示空态冒充无录像。
2. 删除必须二次确认并说明"同时删除四路视频、车辆数据与索引"，完成后卡片立即消失。
3. 筛选条件跨进出库页保持；提供"清除筛选"。
4. 卡片"含车辆数据"角标来自片段清单，不是按当前订阅推断。

验收点：分组与计数正确；筛选组合结果正确；分页不重复不丢；介质拔插后列表按真实可用性刷新；删除不留孤儿文件与索引项。

### P3 同步回放

| 区域 | 内容 | 规则 |
| --- | --- | --- |
| 顶部 | 返回 + 片段标题（`yyyy-MM-dd HH:mm:ss` + 时长）+ `⋯`（P4） | 沉浸态，收起导航栏 |
| 画面区 | 全部/前/后/左/右 五段切换；四宫格或单路 | 切换只改布局，不重新解码整段；缺路显式占位 |
| 数据区 | 历史数据条（同 P1 布局，值来自历史样本） | 逐项显示时效：样本缺失显示"缺失"，超时显示"过期"，不补零 |
| 播放控制 | 播放/暂停、上一事件/下一事件、进度条（可拖动）、当前/总时长、倍速 | 倍速默认 1×，档位见 P10；跳转后四路与数据条、事件游标一起定位 |
| 事件时间轴 | 多轨（默认展开，可折叠）：刹车、油门、横向辅助启用、横向辅助退出、巡航启用、巡航退出 | 游标竖线随播放移动；区间用条带、离散用点/菱形；支持类型筛选、"选中事件/全部事件"、事件计数、点击跳转 |

交互与状态：

1. 拖动进度条时先显示目标时间预览，松手后统一 seek 四路 + 数据 + 游标；seek 期间显示"正在定位"。
2. 前后跳转本稿定为：跳到上一/下一事件；无事件时退化为 ±10 秒（【本稿定案】，避免"帧/秒/片段"歧义）。
3. 回放只依赖本地文件与旁路数据，AutoService 断开时仍可完整回放；期间不得发起车辆采集。
4. 片段缺失某一路时，其他路照常回放并标注缺失区间；不得用拉伸时间对齐掩盖。
5. 回放结束停在最后一帧，显示"播放完毕"与"重播"；不自动跳下一片段（连续播放作为 P10 选项）。
6. **跨片段衔接（RV-09）**：片段与相邻片段同属一个录像会话（结束时间与下一段开始时间间隔 ≤ 1 个分段时长且无缺路跳变）时，底栏出现"上一段/下一段"；P10 开启"自动下一段"后跨段连续播放。跨段播放时**不拼接时间轴**——每段仍用自己 sidecar 里的数据样本与事件，界面在段界处给一条 1px 分隔线并标"分段点"，避免把两次会话的数据接成一条。
7. 事件跨段的片段必须在 P4 信息里显示"事件跨段：前/后各 N 个"，导出时默认建议合并两段（见 §14.4）。

验收点：四路与同一会话时间轴误差不超过一个实际帧间隔（目标值待现场实测后固化）；机动车数据随拖动正确跳变；短事件（<1s 刹车）在轨道上可见；断开 AutoService 后回放全部功能可用。

### P6 存储与保存

分组卡 1「存储位置」：当前介质（内置/U 盘卷名）、路径简写、可用/总量、卷状态（可写/只读/已移除）、"选择存储位置"（弹出卷列表，含刷新）。
分组卡 2「空间与覆盖」：录像配额、循环覆盖、最低剩余空间、当前占用与锁定占用、**可回溯时长（按当前码率与配额估算，如"≈ 4 小时 20 分"）**、清理入口（按容量/按天数）。

容量口径（RV-02，必须按此换算并对用户显示）：

| 项 | 口径 |
| --- | --- |
| 单路码率 | `0.08 × W × H × fps`（技术口径 §3）；1080p25 约 4.15 Mbps/路 |
| 四路合计 | 单路 × 4；1080p25 约 16.6 Mbps ≈ **2.07 MB/s** |
| 1 分钟段体积 | 约 124 MB（估算，随场景复杂度浮动 ±20%） |
| 可回溯时长 | `配额 ÷ (四路合计码率 ÷ 8)`；**32 GB 配额 ≈ 4.3 小时**（按十进制 GB 估算；按 GiB 约 4.6 小时） |
| 显示要求 | 配额、画质、帧率任一变化后立即重算并标注"估算"；可回溯时长 < 2 小时转警示色 |
分组卡 3「分段」：分段时长、当前片段进度（只读）、片段命名规则说明（只读）。

规则：

- 切换存储位置前先做可写校验与空间校验；失败保持原值并就地报错，不静默切换。
- 切换发生在录制中时：当前片段继续写完到原介质，新片段写新介质；界面提示"当前片段完成后切换"。原介质掉线则按第 8 节"存储不可写/已移除"处理（提示 + 暂停录制），不自动换介质。
- 配额与覆盖的计算口径：先删最旧的未锁定、已完成、未导出的片段，直到满足最低剩余；不允许为了配额删除锁定片段或正在写入片段。
- 不允许自动格式化任何介质，不删除非本 App 目录内的用户文件。

### P7 编码与画质（用户点名要求的设置）

分组卡 0「画质预设」（RV-06，新增，置顶）：三档单选 —— **均衡（默认）** / **省空间** / **最高画质**，每档右侧显示"四路合计码率 + 可回溯时长"的换算结果；选择后一次性写入下方各字段。任一手动改字段即变为"自定义"。预设只定义**参数组合**，不新增持久化键（写的是 S-ENC-01…06 同名字段），因此不引入第二套状态。目的：避免用户在 4 个维度上自由组合、踩到"四路跑不动"的组合。
分组卡 1「视频格式」：编码格式（H.264 / H.265）、封装（MP4，只读）、音轨（默认关闭，见第 12 节）。
分组卡 2「编码实现」：硬件编码 / 软件编码（含代价说明与并发限制，见第 6 节）。
分组卡 3「画质」：分辨率、帧率、码率、关键帧间隔。
分组卡 4「当前生效组合」（RV-06，原"能力与实测"收缩为一行摘要 + 入口）：只显示一句可核对的事实，例如"**H.264 · 硬件 · 4 路 1920×1088 → 2016×1080 @25fps · 合计 16.6 Mbps · 四路并发已验证**"；末尾"查看实测详情 ›"进入 P11 的编码分组。完整编码器清单、profile/level、对齐值、失败阶段等工程细节**不在设置页展示**——它们是诊断信息，不是用户决策依据。

规则：

- 编码格式与编码实现的组合必须做可用性校验：探测不通过时该选项置灰并给出原因（例如"本机未报告 HEVC 硬件编码器"），**不允许选择后静默回退到其他编码器**。
- 修改只在下一片段生效；录制中修改显示"下一段生效"，当前段不中断。
- 软件编码的可用路数上限由探测与实测决定；超出时必须在前端就禁止（置灰 + 原因），不做"先跑再崩"。

### P8 录制与后台

分组卡 1「自动录制」：开机自动录制（默认关）、App 启动后自动录制（默认关）、录制中防止误删（默认开）。
分组卡 2「后台与息屏」：后台继续录制（默认开）、息屏继续录制（默认开）、锁定屏幕亮起时是否回到实时画面（默认关）。
分组卡 3「关闭联动」：显示 AutoService 摄像头/车辆数据功能开关的当前状态（只读镜像），提供"跳转 AutoService 设置"；显示"停止全部录制"（一次性动作，不改自动录制设置）。

规则：以上开关都接实际生命周期并持久化；关闭后旧任务不得复活；AutoService 关闭优先。

### P9 车辆数据与事件

分组卡 1「采样」：车辆数据订阅间隔（250/500/1000ms，默认 500ms；250ms 为"事件优先"档，界面注明"更细的事件精度，开销更高"）。
分组卡 2「记录项」：截图最小集固定开启（不可关，显示为锁定行 + 说明"回放必需"）；扩展项（其余已核验目录键）按用途分组，可单独开关，默认关。
分组卡 3「事件规则」：刹车阈值（进入 5% / 退出 3%）、油门阈值（进入 20% / 退出 10%）、去抖时长（200ms）、最小事件时长（300ms）、合并间隔（1s）、规则版本（只读，随修改递增）。
分组卡 4「事件标记与保留」（RV-10，新增）：开/关"含事件片段优先保留"（默认开）+ 说明"含事件的片段不参与循环覆盖，直到锁定配额上限"。**文案红线**：写"事件标记"，不写"碰撞检测/事故认定"——本产品只依据制动、油门、横向辅助等信号阈值打标记，不做碰撞判定，也不承担定责；界面必须有一行说明。

规则：规则修改只影响新片段，历史片段按记录的规则版本解释；界面必须写明"历史事件不回算"。
事件标记的保护口径：事件段与锁定段共用"受保护配额"，二者占满配额时**报告并停止新录制**，不删除受保护片段、也不静默关闭保护（见 §14.3）。

### P10 回放与显示

分组卡 1「默认布局」：默认画面（四宫格/单路）、默认单路方向、数据条默认展开行数。
分组卡 2「播放」：默认倍速（0.5×/1×/2×，默认 1×）、播完行为（停在最后一帧/自动下一段，默认停在最后一帧）、前后跳转（上一/下一事件；可选 ±5s/±10s，默认事件）。
分组卡 3「事件轨道」：默认展开/折叠（默认展开）、记住上次筛选（默认开）、轨道密度（标准/紧凑）。
分组卡 4「界面」：日夜模式（跟随系统/浅色/深色，默认跟随）、字体缩放（跟随系统，只读说明）。

## 6. 编码实现语义（设置页必须如实表达）

本节是产品语义，技术细节与证据见[编码与存储技术口径](编码与存储技术口径-20261103.md)。

| 选项 | 产品含义 | 必须如实展示 | 必须拒绝的情况 |
| --- | --- | --- | --- |
| 硬件编码（默认） | 使用平台硬编码器，画面以 Surface 直接进编码器 | 实际编码器名称、硬/软标记、四路并发是否成立 | 编码器创建失败、并发不足、参数不支持 → 报错并保持原设置 |
| 软件编码 | 使用 CPU 编码器；需要 AutoRecord 自行取得 YUV 数据，代价更高 | 当前可用的软件编码器、可支持的**实际路数/分辨率/帧率**、CPU 占用说明 | 超出实测能力的组合（如四路 1080p 软编）→ 置灰并说明原因 |
| H.264 | 默认格式，兼容性优先 | 实际 profile/level | 编码器不支持所选分辨率/帧率 |
| H.265 | 可选格式，体积可能更小但需本机支持 | 是否具备硬/软 HEVC 编码器、四路并发是否成立 | 本机无可用 HEVC 编码器 → 置灰 |
| 分辨率 | 默认"跟随摄像头原生"；可降采样，禁止上采样放大 | 每路实际输出尺寸（含 16 对齐后的真实值） | 请求值超过原生或编码器上限 |
| 帧率 | 默认 25fps；可选范围内取值 | 每路实际编码帧率 | 超出摄像头与编码器范围 |
| 码率 | 默认"自动（按分辨率/帧率计算）"，可手动档位 | 实际配置的 bps 与四路合计 | 合计超出介质写入吞吐的实测值（需实测后固化阈值） |
| 关键帧间隔 | 默认 1 秒；影响拖动 seek 精度 | 实际 GOP | 编码器不支持 |

**不得在界面或文案中承诺**："软件编码一定可用"、"H.265 一定更省空间"、"U 盘一定可以写入"、"四路 1080p 一定流畅"——这些都要以本车实测为准。

### 6.1 由技术口径确定的硬性约束（实现不得违反）

以下每条都能在[编码与存储技术口径](编码与存储技术口径-20261103.md)里找到依据，属"实现职责"而非待确认项：

1. **硬/软/未知是三态**：用 `MediaCodecInfo.isHardwareAccelerated()`/`isSoftwareOnly()` 判定，两者皆假显示"未知"；禁止按 `OMX.qcom.`/`c2.android.` 名字前缀猜硬软。
2. **软编码 = 自建取帧链**：软件编码器只吃 ByteBuffer YUV，AutoRecord 必须自己从 AutoService 给的 Surface 取 YUV（`ImageReader` 路线优先，`glReadPixels` 路线仅在需要 GPU 处理时），并处理 `rowStride/pixelStride`。因此**软编码选项旁必须写明"需自取 YUV、代价更高"**。
3. **路数限制**：软编 1 路在实测通过后开放；软编 2 路必须显式告警并展示实测 CPU/掉帧；**软编 3 路及以上、以及任何"四路软编"组合一律置灰**并写明"未在本车验证"；选了软编但本机无软件编码器 → 拒绝创建并报错，**不回退硬编**。
4. **实际值优先**：编码器名在 `create` 之后回读，尺寸显示对齐后的真实值；码率、GOP、帧率显示实际生效值而不是设定值；"编码器创建成功"不等于"录制成功"，只有出帧 + 写盘 + 段收尾改名完成才算。
5. **PTS 必须来自真实帧时间**：禁止 `帧序号 × 固定时长`；生产端必须逐帧写呈现时间（AutoService 的强制义务，见需求稿 §6.6）。掉帧、迟到、首帧差如实记录，不拉伸、不补帧。
6. **收尾顺序不可交换**：编码器 EOS → drain 完剩余帧 → `muxer.stop()` → `release()` → `fsync` → 原子改名 → 写索引。用户主动停止也必须走 EOS，不得直接 release 丢 moov。
7. **写盘事务**：先 `fsync` 再 `rename` 再写索引；索引可重建，sidecar（`segment.json`/`vehicles.jsonl`/`events.json`）是真相。断电后按 `.writing`/`.partial` 扫描：moov 完整→"可恢复"，残缺→"部分有效"，索引有而文件无→"文件缺失"，有文件无索引→重建索引后标"已恢复"。
8. **每段开始前重查存储**：卷状态（MOUNTED/REMOVED/READ_ONLY）、可写探测、绝对剩余下限、下一段预估、配额，顺序固定；循环覆盖只删最旧且未锁定/未在写/未导出的段。
9. **卷以 UUID 标识**：不持久化绝对路径；`externalFilesDirs` 下标与卷顺序不保证一致，必须用卷目录做前缀匹配绑定。
10. **上车先做能力核验再放开选项**：按[技术口径 §7](编码与存储技术口径-20261103.md) 的 14 项待核验执行，第一批为编码器枚举、四路硬编并发、HEVC 编码器存在性。探测完成前：H.265 置灰、码率只给自动档、配额与高档码率按"待实测固化"呈现，不得标记为"推荐/已验证"。

## 11. 与 AutoService 的分工红线（沿用需求稿，不扩大）

- AutoService：唯一摄像头与车辆采集 owner，负责能力、方向、会话、图形输出、帧元数据、权限与关闭选择。
- AutoRecord：录制业务、编码与写盘、索引与历史样本、事件规则、回放、导出、界面；不取 SDK/Root 身份，不启动全目录车辆扫描。
- 契约：需要新增摄像头能力与会话方法；若公共版本变化，CarPlay/AutoService/AutoCluster/AutoRecord 必须同版本配套，禁止只改服务端。
- 帧时间：AutoService 必须对每帧给出摄像头时间戳到统一单调时钟的映射并逐帧写呈现时间；AutoRecord 不得用"收到帧的时刻"顶替，也不得用帧号推算时间。
- 数据落盘：四路各自 MP4 + 段目录 sidecar（`segment.json` 自描述、`vehicles.jsonl` 只追加车辆样本、`events.json` 事件、`thumb.jpg`）为真相，`index.db` 只作可重建索引；原始车辆样本只进用户录像数据，不进诊断日志。目录结构、字段与恢复口径见[技术口径 §5–§6](编码与存储技术口径-20261103.md)。

## 14. 关键流程与状态机（v1.1 新增，RV-01/02/08/09/10 的落点）

原稿把"页面元素"和"状态枚举"写得很细，但**没有一条端到端的用时流程**。缺流程的后果是：每个页面单看都合理，连起来却是用户要自己记住"先做什么"。本节补四条主流程，每条给出触发、步骤、失败分支与可测验收点。图示见[评审与优化](评审与优化-20261103.md)。

### 14.1 取证主链路（事故 → 拿到可交付的一段证据）

**目标**：从"我现在要留证"到"证据已受保护"不超过 **2 次操作**；到"能交付的 MP4"不超过 **5 次操作**。

| 步 | 触发 | 系统行为 | 失败分支 |
| --- | --- | --- | --- |
| 1 | 用户在任意页面点操作条"锁定最近片段"，或 P1 次按钮 | 先锁**当前段**（打锁定标记，写入 `segment.json`）→ 再锁**最近一条已完成段** | 当前段尚未收尾：只写锁定意图，收尾后生效并回执"收尾后已锁定"；两段都已锁定则回执"已锁定（此前已锁）" |
| 2 | 自动：事件规则命中（刹车/油门/横向辅助等） | 给所在片段打**事件标记**；`event.protect` 开启时事件段不参与循环覆盖 | 规则版本缺失 → 按当前版本打标并注明"规则版本未知，不参与保护" |
| 3 | 用户点录制徽标操作条"最近录像" | 直达 P3 播放最近段，并定位到**最后一个事件前 5 秒**（无事件则到段首） | 最近段缺路/损坏：照常打开并显式标注，不静默换别的片段 |
| 4 | 用户在 P4 看"事件摘要"并点击 | seek 到该事件时刻，四路 + 数据条 + 游标一起定位 | 目标时刻无有效样本 → 显示"缺失"并停在最近有效帧 |
| 5 | 用户在 P4 点"导出" | 导出弹层默认勾选：本段（若信息显示"事件跨段"则默认加勾相邻段）+ 四宫格 + 叠加数据条 → 导出到用户选定位置 | 空间不足/目标不可写 → 明确报错并保留导出设置，不静默降级为单路 |

**验收点**：锁定的片段在循环覆盖中不被删除；锁定 2 段的回执与实际受保护段数一致；事件标记不出现"碰撞/事故"字样；第 3 步落在事件前 5 秒而不是段首；导出取消后无残留临时文件。

### 14.2 录制启动：两阶段预检（RV-08）

原稿只定义"失败要报错"，没定义"部分成功怎么办"，实现时容易变成"一路失败、三路照跑、用户不知道"。改为两阶段：

```text
[点击 开始录制]
      │
      ├─ 阶段1 预检（≤5s，可取消，不写盘）
      │    ① AutoService 连接与契约版本
      │    ② 四路会话 acquire + 每路首帧到达（超时上限 3s/路）
      │    ③ 每路编码器 create + 参数可用性校验（尺寸/帧率/码率/GOP）
      │    ④ 目标卷可写探测 + 剩余 ≥ 一段预估 + 时钟基准已建立
      │         │
      │         ├─ 全部通过 ──────────────→ 阶段2
      │         └─ 有失败 → 弹"缺哪几路/什么原因"
      │                       ├─ 用户选"仅录可用路" → 阶段2（带缺路标记）
      │                       └─ 用户不选 / 选取消 → 回到未录制（不留半开资源）
      │
      └─ 阶段2 正式录制
           四路 codec.start → muxer.start → 首帧出帧确认 → 首段写入并 fsync
                │
                ├─ 首段落盘成功 → 状态置"录制中"，录制徽标转红
                └─ 首段写入失败 → 全部释放 → 明确报"写入失败：卷/编码器 + 原因"
```

| 规则 | 内容 |
| --- | --- |
| 预检可取消 | 阶段 1 任意时刻可取消，取消后必须释放已 acquire 的会话与已 create 的编码器（不得留半开资源） |
| 默认不降级 | 缺路时不自动进入录制；"仅录可用路"必须由用户点选，且按钮上写明路数与缺哪路 |
| 状态词 | 未录制 → 预检中 → （已取消 / 预检失败）→ 录制中 → 停止中 → 未录制；**禁止**出现"请求中"停留超过 5s 而无说明 |
| 首段才算成功 | 编码器创建成功不算开始录制；首段 fsync + 原子改名成功才把状态置"录制中" |
| 与 §14.3 的边界 | 录制中存储失效不回到预检，走 §14.3 的暂停分支 |

### 14.3 存储不足与介质移除：收敛决策树（RV-02/RV-09）

原稿写了"先删最旧、不删锁定、不换介质"三条原则，但没有把"删无可删时怎么办"收敛。补成决策树：

```text
[每段开始前 · 顺序固定]
 ① 卷是否仍挂载？
     └ 否 → 暂停录制 + 报"卷已移除（卷名）" → 不自动换介质；用户改设置或插回原卷后手动继续
 ② 可写探测（真写 1 字节 + fsync + 删除）
     └ 失败 → 暂停 + 报"只读/不可写（卷名）"
 ③ 剩余空间 ≥ 下一段预估 + 最低剩余？
     ├ 是 → 开始新段
     └ 否 → 循环覆盖是否开启？
            ├ 否 → 停止录制 + 提示"空间不足" + 入口：改配额 / 清理 / 换介质
            └ 是 → 存在"可删片段"（最旧 且 未锁定 且 未在写 且 未导出 且 非事件保护）？
                   ├ 有 → 删除并复查 → 回到 ③（单拍最多删 N 段，避免长时间卡住）
                   └ 无（配额全被锁定/事件保护占满）
                        → 停止录制 + 报"受保护片段占满配额（锁定 X 段 / 事件 Y 段）"
                        → 给三个动作：管理锁定片段 / 关闭事件保护 / 改配额
                        → 不删受保护片段，也不静默关闭保护
```

**受保护配额**：锁定段与事件保护段共用同一上限（默认 = 配额的 50%，超限触发上分支）。这个比例是**估算默认值**，需在车机上按实际使用跑一轮后固化。

### 14.4 跨片段事件与导出（RV-09）

一段事件的起止被打在分段边界两侧时，只锁一段会丢证据。规则：

1. 回放/导出判断"跨段"的条件：相邻段间隔 ≤ 1 个分段时长、同属一个录像会话（会话 id 一致）、时段内无缺路跳变。
2. 跨段时 P4 显示"事件跨段：前 1 段 / 后 1 段"，导出弹层默认合并为**一个 MP4**（对外交付友好），并在文件内保留一条分段点注释；同时保留"分成多个文件"选项（原始取证偏好）。
3. 合并导出的 PTS 必须重排为连续时间轴并在旁路写映射表（`export.json`：源段 → 导出时间区间），保证可回溯到原始段；**不得**用修改源文件时间的方式实现连续。
4. 导出是只读操作：不改源段、不删除源段、不移动源段。
