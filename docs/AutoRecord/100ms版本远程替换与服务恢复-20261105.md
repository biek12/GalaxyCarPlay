# 100ms版本远程替换与服务恢复（2026-11-05）

用户要求开始远程替换，并询问AutoService自更新后能否自拉起、是否有替代办法。该指令解除此前本批源码“暂不安装”的限制；仅经既有AutoService远程通道更新自有同签名APK，保留数据，不使用电脑远程ADB，不操作原厂启动项/HMI或车辆控制。

## 已有恢复能力

- `galaxy/service/src/main/AndroidManifest.xml` 注册 `MY_PACKAGE_REPLACED` 与开机广播；`startup/AutoBootReceiver.kt:8` 调用 `AutoStartup.start`，遵守已保存的automatic开关。
- `AutoService` 使用前台Service和START_STICKY，并有 `ProcessRecovery` 预先登记的进程外恢复闹钟；`AutoRecoveryJob` 提供较慢的系统周期恢复机会。这些能力不能互相冒充“所有系统条件下必定恢复”。
- 本车安装前回读 `automatic=true`。更新不关闭或重置远程授权窗口、设备身份与原签名，不再要求重复验证码。

## 更新前状态与过程

旧AutoService PID2857、APK摘要 `c896bd364c0f7f8ce114e4abb451f1d30f5248d666f5ca047f27342e2428b4d0`。旧AutoRecord PID9314已录至第72段、累计编码4,410,249,472字节，四路有效、队列0、discarded计数0。这是该轮状态采样，不代表整个长录期间所有帧均验收。

先采集约30秒旧250ms资源快照（`.work/vehicle-frequency/old-250-before-update/`），只能作为短基线；不能替代此前设计的稳定三档180秒对比。

先正常停止并保存AutoRecord，再执行同签名 `pm install -r` 更新。包替换广播会令App进程短暂运行，因此不能以“进程还存在”推断录制未停止。尝试在无进程条件下修改订阅设置的保护检查终止了设置操作；后续观察到录制已恢复，未强制停止正在工作的录制，也未修改其250ms原设置。

AutoService自更新前，预先上传新包，并经自有Root通道启动一次性 `/data/local/tmp/galaxy-update-recover-20261105.sh`。它由独立setsid shell运行，最多检查18轮，只有已装APK摘要与候选一致、automatic没有关闭且前台服务尚未运行时，才执行 `am start-foreground-service` 启动本项目AutoService。它不部署常驻启动项、不重启原厂进程；用户关闭automatic则直接退出。

## 实际恢复证据

AutoService安装回执为 `execution_interrupted_check_state`，符合自更新可能中断旧进程回传；没有因此重复提交安装。之后原授权会话重新可用，ROOT回读已装APK摘要与候选一致。

一次性恢复日志：

```text
1793849674 new_service_already_foreground attempts=3
```

没有 `bounded_start` 记录。新AutoService PID19046已前台运行，automatic=true、Root身份链 `root_ready`、车辆订阅已恢复。因此**本次自动恢复成功，独立Root备用拉起未被使用**；仅凭这条日志不能进一步区分究竟是包替换广播、已有客户端重绑还是系统恢复首先触发。

独立脚本完成后退出，回读日志保存到本机后删除其车机脚本和日志，不留下永久守护进程。
