## 1. 录像库实现

- `galaxy/record/src/main/java/com/galaxy/autorecord/core/SegmentAccess.kt:7`：本 App 内按段目录的使用租约；`hold()` 给录制/收尾、导出、解码使用；`delete()` 与所有持有者互斥。关闭租约幂等，删除期间不能新增使用者。
- 同文件 `:27`：`LibraryTimeWindow` 按 `[from,until)` 与片段区间相交筛选，开始之前但结束之后的录像保留；结束不大于开始时拒绝。UI 日期与时间选择当前精度为分钟，展示完整时间。
- `galaxy/record/src/main/java/com/galaxy/autorecord/ui/LibraryPage.kt:23`：更多筛选中的开始/结束、清除筛选、显式选择/退出多选、全选筛选结果；原有每次仅显示 12 卡再加载保留，避免全量缩略图解码。
- `galaxy/record/src/main/java/com/galaxy/autorecord/ui/RecordActivity.kt:640`：删除在 `RecordIo` 后台执行；重新检查自有根目录、锁定和 writing 清单，再删除整个段目录及 locks/played 标记，最后一次刷新。部分失败逐项报告，包含四路视频、vehicles、events、缩略图与段清单。
- 手动删除经明确确认后允许删含事件的未锁定段；循环覆盖仍遵守事件保护。锁定段先解锁，写入/收尾/回放/导出占用时不删。
- `galaxy/record/src/main/java/com/galaxy/autorecord/ui/SegmentActions.kt:83`：详情使用已扫描元数据，不在主线程重读整份车辆历史和事件。
- `galaxy/record/src/main/java/com/galaxy/autorecord/recording/RotationJanitor.kt:103`、`galaxy/record/src/main/java/com/galaxy/autorecord/recording/ContinuousSegmentWriter.kt:55`、`galaxy/record/src/main/java/com/galaxy/autorecord/playback/SegmentPlayer.kt:156`、`galaxy/record/src/main/java/com/galaxy/autorecord/export/ExportTask.kt:77` 接同一租约。相机与 native codec 的既有关闭确认纪律保持，文件租约不能代替资源关闭确认。

## 2. 预览分发与转向窗

`galaxy/record/src/main/java/com/galaxy/autorecord/preview/PreviewDistributor.kt:11`：一个 EGL 上下文，在既有相机线程消费各路 SurfaceTexture/OES，按需绘制页面与悬浮窗；最多四路稳定输入。HAL 会话保持 PRIVATE 预览输入 + 录制输出两类目标，不为窗口新增第三个 HAL 输出或另开同 cameraId。录制期间保留稳定的 PRIVATE 输入，页面隐藏只撤显示目标，避免退后台为了预览而重建会话。

录像编码和车辆侧录路径保持原时钟；GPU 只处理预览。着色器无逐帧 Bitmap/CPU 像素解码；uniform 位置缓存。输入及 EGL 资源在 CameraDevice.onClosed 完成后释放；无页面/辅助/录制需求且相机全部关闭时释放空闲 GPU 资源。此为源码实现，不等于已测 GPU/CPU 降低；新增 GPU 分发的开销必须实测。

`galaxy/record/src/main/java/com/galaxy/autorecord/preview/LensProfile.kt:8`：当前支持显式 `opencv-fisheye4` 零 skew 模型（数学口径见 [OpenCV 官方鱼眼模型](https://docs.opencv.org/4.13.0/db/d58/group__calib3d__fisheye.html)），配置含 schema、cameraId、分辨率、fx/fy/cx/cy/k、verified、source。没有可核验参数时不套默认镜头视角，不把拉伸/裁切称为去畸变。显示视场 100° 只定义输出视图，不作为镜头标定值。当前未发布本车可用配置，实时入口会明确提示标定尚未核验。

`galaxy/record/src/main/java/com/galaxy/autorecord/runtime/TurnAssistRuntime.kt:13`：只额外订阅 `leftTurn/rightTurn`，复用版本化 AutoService feed。主线程以 100ms 检查状态，真实采集频率仍取设置与服务下限较大值；不能把该 tick 当成车辆真实更新率。首次方向候选等待 300ms，最后亮灯后保持 1200ms 覆盖闪烁熄灭间隙；1200ms 内观察到左右都亮则撤销窗口，覆盖分包轻微错时的双闪。常数是软件策略，需以本车灯光实际节拍校核。

数据未知/过期/断开立即撤窗；无首帧 8 秒、已有帧超 1500ms 不更新则撤窗，防止把旧帧作为当前侧方画面。关闭窗后本次方向不重弹，信号结束再复位。左右贴边、窗口不夺焦点；用户关闭设置后撤订阅与窗口。窗口销毁按旧 Surface 身份撤销，迟到回调不能解绑新窗。

`RecordSessionService/Hub/ResumeActivity` 承接辅助待机与后台恢复，不另建竞争的恢复目标。仅辅助待机不持有录制 WakeLock。启动资格仍经 Android 11 前台入口恢复，不能以 SAW 权限本身当成相机已可用。驻车深睡唤醒不由此实现。

## 3. 原车 AVM 事实

本轮私有研究材料在 `.work/record-detail-20261105/`，不打包原厂 APK、native 库、私有标定文件到产品或公开源码。

1. 原厂入口 `/system/app/oneOS_XCParking/oneOS_XCParking.apk`，包 `com.ecarx.parking`。反编译 `oem/parking/jadx/sources/com/ecarx/parking/MainAvmActivity.java:180` 调用 `setFunctionValue(587399424,1)`，`:188` 关闭时设 0。Java 入口没有平铺算法，不能把这个设置项当成可供 AutoRecord 使用的平面视频流。
2. 已授权 QNX UID0 只读登录后，实车发现 `/calibration/camera_calibdata.bin`（616 字节），四路 `calibframe_*_1280x800.uyvy` 与 `framein_*`。只读取标定文件，未拉取这些车辆图像。
3. 原车资源在 `/apps/cluster/FX11_HEV/resource/avm/Assets_G733/`，原生 `/apps/cluster/FX11_HEV/lib/libarcsoft_avm_sdk.so` 与 `libArcsoftAVM.so`。前者实际读取成功，SHA256 `116653cf7e15085886ff924f32687c049f45a3c15632f555593309615d9048e9`；仅私有分析，不加载/打包到 AutoRecord。
4. SDK wrapper 固定二进制地址：`read_inter_param(_camera_inner_param_**) @0x1d890`、`arcsoft_camera_get_innerparam @0x2f898`。后者通过 `qcarcam_g_param(...,30,...)` 取各相机内参，前者按 left/right/front/back 日志打印 fx/fy/cx/cy/k1…k4。原厂有真实传感器内参来源，不应只据外观拟一个鱼眼半径。
5. 616 字节文件呈 8 字节头 + 四组 152 字节数值记录；这是字节布局观察，**尚未证明全部字段/镜头投影模型/相机方向顺序**。不得将看到的浮点数未经调用链核对就塞进鱼眼多项式。
6. QNX `resource/avm/config.ini` 同时含 KX11 模型、通用参数，参考仓库的 SView 路径本车未发现；不能以目录同名就当本车 L6 标定。当前仍需核对实际 G733 数据读取与投影实现。

## 4. 原车哨兵事实

- APK `/system/app/AutoSentineMonitor/AutoSentineMonitor.apk`，包 **`com.flyme.auto.sentinemonitor`**；不是泛称安全 App `com.flyme.auto.safe`。
- 原厂设置 `SettingsActivity.java:315` 绑定 action `com.flyme.auto.sentinemonitor.action.OPERATE_SERVICE`。AIDL `operateSwitch(boolean,String,IOperateCallback)` 是开关入口。
- 本车反编译 `oem/sentinel/jadx/sources/com/flyme/auto/sentinemonitor/service/SentineOperateService.java:26` 检查 `checkSignatures(Process.myUid(),Binder.getCallingUid())`；普通同名 API 不代表本 App 有权限，Root UID 也不能直接冒充平台签名。
- `c2/i.java:83` 起关闭流程，`:100` 起启用流程，`:131` 起校验 U 盘/空间/电量/支持状态；SDK `ICarFunction.setFunctionValue(536951296,...)` 表达 off=`536951297`、standby=`536951298`。`SentineService.c(int)` 另映射 on=`536951299`、alert=`536951300`、alarm=`536951301`。VSTD 是哨兵状态，不能复用成驾驶模式。
- `service/b.java:9` 电源监听：state2 为 SUSPEND_ENTER；state3 从 STR 恢复和 state6 上电写服务状态 `536954368=1`；state7 SHUTDOWN_PREPARE 写0并退出自身进程。这说明原车并非简单永久 WakeLock。
- `SentineService.java:1813` 的 `onVstdCtrlReqEvent` 接车身控制请求，含等待、可用空间与电量判断及回执；`:874` 注册 CarPowerManager。JADX 该方法有重复/可疑控制流，不能把反编译伪 Java 分支直接当可靠控制程序。
- 原车使用 ArcSoft native 监控和自有 TBox/MQTT 链路；没有迁移其云凭据，也没有调用原厂控制接口。单纯开启原厂哨兵还可能与本 App Camera2 并发争抢，不能直接同时开启后宣称完成。

下一步需要核对原厂 SDK 功能→VHAL/电源域映射、由 AutoService 实现仅哨兵用途的专用适配与能力回读，再分别验收布防、锁车休眠、触发唤醒、低电量退出、用户关闭、异常恢复及相机仲裁。完整链未通前不展示“哨兵监控运行中”，也不把黑屏常亮/定时闹钟作为已完成的唤醒方案。
