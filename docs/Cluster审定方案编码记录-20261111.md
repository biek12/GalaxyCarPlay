## 已写入的代码

1. 新增`:auto-ui`：从CarPlay迁出设置行及长值排版、列表卡、分组、按钮、模态弹窗／焦点恢复、选择确认、开关／回填、文字角色与主题样式。旧L7入口为兼容委托，原生Wi-Fi跳转留在AutoService。详见`galaxy/ui/README.md`。
2. AutoService：独立Wi-Fi观察／原生设置入口；统一CarPlay和Android原生媒体会话入口（按系统会话优先级，排除CarPlay桥回采）；原始媒体与可视歌词分开。原生会话读取需要系统媒体访问权限，沿现有自有权限准备流程为专用媒体监听组件准备，组件不读取通知内容。原车App若未发布Android MediaSession，仍须核验并接其实际厂商媒体回调，不能宣称覆盖了所有原厂App。
3. 契约v5：来源App／来源包名／真实媒体ID、稳定曲目身份，封面请求携带曲目校验，AutoCluster独占可视歌词发布租约，原厂封面语义化FD接口。车辆按需订阅语义不变。所有依赖AutoClient的App须同版本更新，不能用v4安装包代验。
4. 新增`:auto-lyrics`：迁出已有解析／HTTP／取消实现。AutoCluster的`VisualMusicSession`按实际可视需求运行（完整主题声明歌词组件且投屏实际请求中，或原厂音乐增强启用），缓存8条／24小时、有限失败重试、切歌取消旧请求。原始完整时间歌词优先；服务器现有搜索仍只按曲名与歌手，专辑／时长用于客户端核对，多个不同匹配不会把首条冒充确定结果。来源歌曲ID保留，但尚没有核验各音乐平台的ID直查provider，不声称已支持源App直查。
5. AutoCluster：独立“仪表／主题／设置”，原厂增强中的音乐／背景各页分开；音乐仅配置页预览；草稿和已应用配置分开。原有主题管理／编辑器／组件库保留到`ThemeActivity`，主题应用明确切换到完整自定义出口。未收到原厂替换运行回执时只显示等待，不把Root就绪当运行成功。原厂增强的恢复意图单独保存与恢复，停止显示时同时撤销两种出口；不以旧投屏开关作为原厂增强的启动条件。日夜选择只影响本App与仪表，不改车机系统设置。
6. 封面：CarPlay的`GalaxyL6OemArtwork`只交付有界图像FD；AutoService `OemArtworkWriter`处理130px JPEG和固定自有OTA桥路径。替换卡片的GCA1封面由`KanziMediaPublisher`发布，带会话与曲目匹配，只在封面版本变化时转换。没有开放共享目录或接收客户端任意Shell／目标路径。Android落盘成功不代验QNX读取和原厂DIM实际显示。
7. 仪表卡片：80px紧凑头部、当前32px／四行／短进度；替换与完整主题／App预览均加入长句单次滚动。QNX测量复用本车`TextBlock2D::measureOverride(Vector2)`，固定ELF中地址0x20d558，输入与返回为s0/s1；0x20d644读取真实排版宽度，不按字数估宽。800ms停留后28px/s，暂停冻结、切句／切歌／seek复位。封面会话哈希避免不同来源同名曲复用旧图。

## 原生媒体API依据

Android官方说明：`getActiveSessions`按优先级返回会话，并要求媒体控制权限或已启用的通知监听组件；`METADATA_KEY_MEDIA_ID`是来源服务内的持久内容标识，不天然等于其他歌词平台ID。[MediaSessionManager](https://developer.android.com/reference/android/media/session/MediaSessionManager)、[MediaMetadata](https://developer.android.com/reference/android/media/MediaMetadata)。本轮实现据此保留来源包名与ID，不跨服务猜测歌曲ID。
