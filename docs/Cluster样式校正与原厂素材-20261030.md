# Cluster歌词、巡航及功率样式校正

> 最新用户调整：歌词默认四行，1行已播放＋第2行当前＋2行待播放；以下五行记录是上一次版本。现行组合歌词宽324px、进度条220px，右上新增独立档位和驾驶模式。

2026-10-30。用户指出上一版歌词宽度、样式与revision-3不一致，巡航短弧关系不直观；进一步要求灯光、安全带、车门图标和未系带/车门提示采用原厂样式。当前优先修正歌词和巡航；原始功率正负与单位需测试，不把用户的记忆当成协议定义。

## 本轮修改

- 组件树中信息区仍为可编辑子组件。右侧容器定位1248/72、600×426；歌词与进度实际宽324，中心x1510，对齐参考图。标题25/歌手18，五行普通25/当前32/最外24，行中心间隔43。去掉普通行反复衰减和硬卡片背景，背景使用缓存模糊封面、深色遮罩和四边柔和渐隐；默认地图背景透明度0.45，使底图服从前景信息。
- 目检整屏时发现一个独立布局错误：StaticLayout复制了上一组件居中label的TextPaint.textAlign，导致同一歌词单独正常、放在标题之后却向左裁切。构造布局时固定LEFT，由StaticLayout自己对齐；增加“在居中标题之后绘制与单独绘制逐像素一致”的回归，不能仅凭单组件缩略图验收整屏。
- 巡航默认采用目标速度→屏上实际指针的差值弧；弧端使用同一平滑车速样本，支持当前高/低于目标的双向弧，不跨零点取短路径。目标圆点仍定位设定值；相等时差值弧为零，圆点继续显示。可选原短目标标记或仅圆点；关闭隐藏/待机白/激活绿不变。
- 回收满量程默认120kW、驱动200kW，均可设置；只有弧/条填充按量程封顶，数值不截为50/60。新增驱动/回收双向模式与独立/有符号输入合同。显示约定驱动+、回收−，并不据此推定原车raw符号；有符号输入的正号代表哪一方向可配置，但必须先核实来源。只有有效、未过期且单位明确为kW的字段可用于功率；原始abs/status不冒充kW。
- 预览补齐明确演示的灯光/转向/安全带状态，蓝色远光与绿色近光区分。这里仍是自绘临时状态行，**原厂图标/安全告警还原没有完成**，不能替代QNX原车层或宣称告警优先级已验收。

## 原厂素材已经定位，尚未完成状态映射

本机既有QNX采集目录的`ClusterHMI/warning.kzb.txt`含`WarningC/seat_belt_red/white/grey`、四门open/close、车身/前后盖等资源名；`ClusterDataSource.xml`分别声明前后排安全带和四门状态。原始warning.kzb中只读提取291张完整PNG，逐chunk CRC通过；原样保存在忽略目录`.local/oem-warning-inspection-20261030/`，没有进入APK、主题包或测试ZIP。

PNG物理排列与文本资源目录排序不同，已经用候选图查看确认，不能按序号错贴“安全带/车门”名称。下一步解析资源目录到纹理的实际引用，核对目标固件，再在停车条件下对照主副驾未系/已系、四门开闭、近远光/转向等真实状态，记录位置、大小、昼夜、闪烁、提示覆盖和优先级。只读取与复用原车素材/显示关系，不修改原车HMI、原车启动项或关闭原车告警。

来源摘要与准确行号见[原厂素材发现证据](../tools/evidence/cluster-oem-warning-discovery-20261030.json)。这证明本机有原厂资源，不等于已经复原其显示/状态机。

## 功率现场对照已准备

`capture_cluster_fields.py`新增accelerating/coasting/recovering标签，并保存白名单单位；它只读已有快照，不改变车辆状态。分别记录原车功率读数、原始abs/status、当前车速与回收档位，在安全条件下由用户执行实际场景，观察+50/+60与回收时符号及倍率，再确定单位换算/状态方向；静态±60kW绘制测试不能代替这一步。新增有单位/无单位、正负60、反转方向、280不截读数和过期回归。
