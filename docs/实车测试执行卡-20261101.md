# 实车测试执行卡（2026-11-01，契约 v4）

首验：银河 L6 / 2023 Max / FlymeAuto 2.3.1 / Android 11。三个 App 必须同轮更新，签名及数据保留。旧 `field-ready.sh` 和 10 月 30 日测试包不代表当前版本。

## 准备与入口

在工程根目录执行：

```sh
source scripts/field_ready.sh
field init
export FIELD_HOST='当前Android地址'
```

地址从当前邻居和已有本地入口核对；IPv6 链路本地地址带 `%接口`，不套用旧全局地址。`source`、`init` 均离线。之后的现场命令使用显式 Android root Telnet 入口，不使用电脑远程 ADB、不执行 `adb connect/root`。Telnet UID0 仅证明该入口身份，不能代验 AutoService 自身 ADB、helper 或 QNX UID。

## 到车后显式执行

```sh
field install                 # 同包 pm install -r，同轮三APK及独立GPU测试APK
field check                   # 回读车机已装三APK摘要与包内摘要比对
field authorize               # --app-only：由AutoService完成自身授权，核验其真实UID/TLS
field gpu                     # 显式运行自有GPU测试，不代表QNX/实际仪表已验收
field snapshot before
```

安装/授权/GPU 都是显式动作；本轮准备阶段没有执行。授权结果必须是 AutoService 私有 ADB 与 RootService 的真实身份回读，不拿电脑/Telnet身份代替。正常 QNX 取得/接收端准备仍由 AutoService 按需求处理。

## 主流程（场景在 App 中设置，采样脚本不改变场景）

1. 停车先测无线 MANUAL 默认路径、USB；Wi-Fi Direct 显式选项另测。记录连接耗时、自动恢复、重复进出和退出是否恢复原车显示。
2. CarPlay 连通后播放音乐，核对原车媒体中心封面、曲目、歌词、播放状态与进度；测试方控播放/暂停、前后曲、Siri和接挂电话；微信通话由用户确认双向声音。
3. 打开完整导航和仪表主题，核对地图完整内容、音乐可视区、菜单循环分页，以及退出释放。原车“图传异常”单独记录，不认定已修复。
4. 车辆字段只读缓存：静止保持速度/档位超过 2 秒，核对仍有有效值；安全条件下由用户操作挡位、巡航与回收，脚本只观察，不能自动控制车辆。没有订阅的字段不会为标定自动补采；需要相应主题订阅或显式诊断扫描，扫描结束后停/启车辆功能以释放已知残留注册。

```sh
field fields parked --duration 15
field perf static --duration 60 --warmup 10
field perf map30 --duration 120 --warmup 15
field snapshot during
# 有异常立即保留限定状态；不保存原始协议、认证或媒体正文
field snapshot fault
# 用户在UI停止仪表/车辆功能后
field perf stopped --duration 30 --warmup 5
field snapshot after
```

`map30` 只是场景标签，执行前需在 UI 实际设好帧率。性能报告包含自有进程 CPU（单核100%）、PSS/RSS、线程、FD、图形帧计数、车辆 ticks/reads/bundles/feeds 及增量速率；SurfaceFlinger单列。`fields` 仅记录白名单字段，不自动发起车辆订阅或读取。单位、功率方向及车速偏差需原车对照，不能由采样成功推定。

本轮结果存入包外 `$FIELD_RESULTS`；默认每次加载生成唯一目录。先用 `field init` 绑定测试包，勿混用旧目录。需要整改前后比较时，两版分别同条件采样；缺历史基准则明确“无整改前实测”，不能补写成实测对比。
