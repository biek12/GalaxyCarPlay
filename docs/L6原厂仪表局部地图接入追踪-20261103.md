截图只证明视觉上有局部地图与原厂样式共存；其软件/固件版本、真实渲染来源和实现方案未知。本项目已采集固件与截图中的固件不能自动视为相同。

## 2. FullMapStatus：真实代码存在，但尚不是视频入口

`cluster-hmi`：

- `FunctionMultiMediaInfoManager::init`位于`0x136b78`，连接`hmi.clusterfunction.client`，登记多个通知。
- 通知`0x13`（19）登记至对象偏移`+0x190`。构造函数`0x13a3d0`在`0x13a440`写入该对象vtable；GOT地址`0xa4a210`的`R_AARCH64_RELATIVE` addend为`0xa26398`，对应`LogicAdapter::FullMapStatusNotify`的vtable。此项为人工交叉核对的重定位证据。
- `FullMapStatusNotify::Notify`（`0x136600`）从payload首地址读取32位整数，比较并更新`HMIState.FullMapStatus`属性；未在该函数中见到帧buffer导入或纹理更新。

`libMiddleware`：

- `FullMapStatusNotify::Notify`（`0x10fc38`）读取整数并调用`HMIStateServer::SetFullMapStatus`（`0x10fbb8`）。
- setter先比较旧值，并要求对象`+0x26f0`字段等于`0xa2`，才保存状态并发`EVENT_MSG`类型`0x24`。结合`HMIStateServer::OnRegNotify`（`0x10ada8`）同字段日志，字段为VehicleType；该数值尚未与本车运行时值及截图固件匹配。不能拿此条件概括为L6不支持局部地图。
- 这两个回调分别在原厂HMI与中间件端消费状态；尚未找到该状态实际发布者、原厂地图帧生产者，以及此状态到地图可视节点的绑定。

本批`ClusterDataSource.xml`和`rightmenu/background/clusterfunction/adas.kzb.txt`索引中未命中`FullMap`；不能把HMI代码含有此分支说成资源已经绑定它。KZB文本索引不是完整场景反编译，未命中也不证明运行时绝对没有相关节点。

## 4. Android视频入口仍缺哪段

共用地图代码`AutoMap-dim/sources/com/flyme/auto/map/multi/DimCallbackImpl.java:51-68`只枚举已有Presentation显示，命中Android display11后启动`DimActivity`；它不创建该显示，也不证明显示后端连接QNX。

本车真实`AMapDimAdapter`仍委托`EmptyDimAdapter`。两份SDK的`setPresentationToDimSwitch`仍为空。故“Hook支持标志→调用openDimView”最多绕过Java门控，还缺：

1. 本车真正的Android视频生产Surface/显示设备及帧格式。
2. 对应原厂跨域接收进程与传输合同。
3. 地图帧在QNX变成纹理或Screen窗口的地方。
4. 原厂右侧区域如何显示、切换、让位和退出恢复。

935个ELF的动态导入定向扫描未在`cluster-hmi/libMiddleware`发现直接的HAB导入入口；命中范围见本地report。此扫描不覆盖静态链接、动态查符号、内核后端或未采集固件，不能据此证明原厂没有视频传输。

## 5. 哪种局部方案已有实施基础

**独立局部窗口与原厂共存：源码基础明确，产品实现尚未完成。** 可保留原厂HMI，沿既有111→AutoService→HAB链仅送地图，在自有QNX窗口显示指定区域；这能实现截图类别的效果，但不能称为已复用原厂视频通道或免自有接收程序。

| 保留/修改点 | 当前源码事实 | 需要补齐 |
|---|---|---|
| CarPlay111与110隔离 | 已有独立地图尺寸与Surface链 | 局部地图按目标区域协商，不能把整幅图压成小缩略图，不能串到中控110 |
| 自有HAB协议 | `galaxy_hab_protocol.h:13`目标只有display/width/height/z | 增加独立窗口x/y与呈现尺寸合同并版本化；原像素buffer尺寸与显示区域分开 |
| QNX窗口 | `galaxy_hab_qnx.c:154-194`按目标ID建窗，设置buffer/窗口尺寸和z | 接入位置/区域更新，确认原厂状态与可用区域；当前没有position属性设置 |
| 显示与退出 | `galaxy_hab_qnx.c:327-332`显示/post；`:86-109`隐藏、flush、销毁自有资源 | 保持会话所有权、幂等恢复，并让位于原厂提示/菜单；不得以抬高层级遮原车提示 |
| 原厂场景内融合 | 已有数据回调与右菜单状态机 | 尚缺真实地图纹理/帧输入接点、线程合同和节点绑定，不能直接交付Hook补丁 |

当前输出RGBX且无端到端alpha；“Android画布透明”不会自动露出原厂画面。规则矩形局部窗口可以先避免依赖alpha；不规则融合另需像素格式、混合和硬件合成验证，不能靠改背景色冒充。

## 后续研究的准确落点

原厂视频复用路线继续追`FullMapStatus`的通知发布者与真实帧生产/接收端；运行时目录核对是用于确认这段缺口，不能由猜屏号代替。原厂场景内融合则需要解出具体节点、属性和输入纹理，不应先重写整个Kanzi主题。局部自有窗口路线已有明确改动边界，但本轮没有擅自选择它替代用户要求核验的原厂路线，也未改变现有完整主题能力。
